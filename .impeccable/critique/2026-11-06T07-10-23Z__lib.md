## 5 ประเด็นที่ควรแก้ก่อน

### 1. P1 · CSV ถูกปฏิเสธทั้งที่ผู้ใช้เลือกไฟล์ได้

เลือก `critique-words.csv` จาก Downloads ของ Android ได้ แต่แอปแสดง “รองรับเฉพาะไฟล์ CSV และ JSON” ข้อมูลเดียวกันใน JSON เปิด preview ได้ครบ 2 แถว จึงไม่ใช่ความผิดของข้อมูลคำศัพท์

MediaStore ของเครื่องทดสอบระบุ CSV นี้เป็น `text/comma-separated-values` ขณะที่ parser ยอม CSV เฉพาะ `text/csv` และ `application/csv` รวมกับ generic MIME บางชนิด Picker ของ Android เปิดให้เลือก alias ที่ parser ไม่รับ

ผลกระทบคือช่องทางนำเข้า CSV ที่หน้าจอประกาศรองรับใช้ไม่ได้ในกรณีปกติของ Android นี้ แนวแก้คือตกลงชนิดไฟล์ที่ picker และ parser รองรับให้ตรงกัน และคงการตรวจเนื้อหา ขนาด และจำนวนแถวไว้ ทวนด้วย Android DocumentsUI จริง แนวงาน `$impeccable harden`

### 2. P1 · คำหลายความหมายได้คะแนนผิดโดยไม่มีบริบท

นำเข้า `bank` สองแถว ได้แก่ `financial institution` และ `side of a river` ทั้งสองเป็น noun จากนั้นฝึกตามหมวดแบบคำศัพท์ไปหาความหมาย ทั้งสองข้อแสดงเพียง “bank” และตัวเลือกสองความหมายเดิม เลือก `financial institution` ทั้งสองข้อได้ถูกหนึ่ง ผิดหนึ่ง และคะแนน 50%

ผู้เรียนไม่มีข้อมูลบนโจทย์ที่ใช้แยกว่าระบบต้องการความหมายใด สาเหตุคือสร้างตัวลวงจากทุก meaning โดยไม่กรองความหมายที่ถูกของ spelling เดียวกัน แล้วตรวจคำตอบกับแถวเป้าหมายเพียงแถวเดียว

แนวแก้คือไม่ใช้ความหมายที่ถูกอีกความหมายของคำเดียวกันเป็นตัวลวง หรือเพิ่มบริบทที่แยกความหมายก่อนให้คะแนน พร้อมตรวจคำหลายความหมายทั้งสองทิศทาง แนวงาน `$impeccable harden` และ `$impeccable clarify`

### 3. P2 · นำเข้าไฟล์เดิมซ้ำแล้วแจ้งว่าเพิ่มคำใหม่

นำเข้า JSON สองแถวสำเร็จ จากนั้นเลือกไฟล์เดิมอีกครั้ง หน้า preview ระบุ “ผ่าน 0 · ต้องแก้ 0 · ซ้ำ 2” แต่กดยืนยันแล้วแสดง “เพิ่ม 2 · ซ้ำ 0 · ไม่ผ่าน 0” ทั้งที่รายการมีเพียงสองแถวเดิม

Repository คืนผล acceptedCount ของงานเดิมตาม sourceHash แล้ว UI แปลผลเป็นจำนวนคำที่เพิ่งเพิ่ม ผู้ใช้จึงเชื่อจำนวนที่แจ้งไม่ได้ แนวแก้คือแยกผลการนำเข้าที่เคยสำเร็จออกจากคำใหม่ในครั้งนี้ และให้ preview/ผลยืนยันตรงกัน แนวงาน `$impeccable harden` และ `$impeccable clarify`

กรณีลบคำก่อนนำเข้าไฟล์เดิม และ tombstone ยังขวางการคืนคำ พบจาก source/tests แต่ไม่ได้ทดลองลบเพื่อทวนบน APK รอบนี้
