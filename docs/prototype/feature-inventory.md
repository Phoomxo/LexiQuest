# Prototype feature inventory

This is the active, source-backed contract for the Real Local-First Prototype
at the Phase 0 baseline. A visible label or a constructed screen is evidence of
reachability only; it is not evidence that the feature works on a device.

Readiness is recorded at the start of **Known blocker**:

- **ready**: the bounded source review found a truthful local behavior and no
  known production-path debt for the stated scope;
- **degraded**: a real behavior exists, but persistence, connectivity,
  integration, or device evidence is incomplete;
- **blocked**: the current behavior can fabricate a result/history or cannot
  meet the approved prototype contract;
- **not exposed**: production code exists but no current menu/route reaches it,
  or a closed policy deliberately hides it.

The inventory covers 63 entry points: 8 typed account routes, 5 primary
destinations, 3 drawer entries, 20 learning/practice entries, 9 settings and
account actions, 4 category-management entries, 8 nested practice entries, and
6 hidden legacy/research/device entries. It names all 43 production screen
files reachable from the current route/menu surfaces, including policy-gated
surfaces. The baseline allowlist contains 18 exact debt pairs, including 6
direct Firebase screen pairs, 1 direct HTTP screen pair, and 2 direct plugin
screen pairs (one screen has both Firebase and plugin debt).

Curated vocabulary, questions, sentences, stories, equipment, and export
examples are **product content**, not user history. They may remain as labelled
starter/demo packs. Default scores, past attempts, weakness records, speech
measurements, or achievements that appear to describe the current user are
different: they require real records or an explicit unavailable/empty state.
Quiz option shuffling, secure ID entropy, statistical `sample` terminology,
and test-injected fake providers are not production debt.

Navigation terminology:

- **Typed route** means an `AppRoute` path resolved by `AppRouter`.
- **Direct route** means a screen constructs `MaterialPageRoute` itself.
- **Indexed destination** means the main `IndexedStack`; it is not a typed
  route even though `/home` reaches the containing shell.

## Direct production boundaries

Direct screen imports found by the bounded scan are:

- Firebase: `categories_page.dart`, `choose_mode_screen.dart`,
  `main_vocabulary.dart`, `quiz_screen.dart`,
  `select_category_for_quiz.dart`, and `select_wallpaper_screen.dart`.
- HTTP: `add_vocab_screen.dart`.
- Plugins: `categories_page.dart` (`shared_preferences`) and
  `speak_to_text_screen.dart` (`speech_to_text`).
- UI-only packages such as `fl_chart` and `flutter_speed_dial` are recorded as
  presentation dependencies, not device/provider production debt.

All current navigation outside the eight `AppRoute` values uses direct
`MaterialPageRoute` construction. Completing the typed route registry and
removing screen-owned provider/plugin boundaries remains Phase 7 work after
feature interfaces stabilize.
