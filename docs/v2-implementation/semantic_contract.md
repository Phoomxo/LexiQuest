## Frozen Definitions

### 1. Points — RETIRED TERM 🚫

| Field | Value |
|-------|-------|
| **Status** | DEPRECATED — do not use in new code |
| **Legacy meaning** | Ambiguous: sometimes XP, sometimes Coins, sometimes both |
| **Code locations** | `lib/progress/local_progress_repository.dart`, `lib/services/local_user_progress_store.dart` |
| **V2 replacement** | Use `XP` or `Coins` explicitly. Never write "Points" in new identifiers, comments, or UI labels |
| **Exception** | `PointsLedgerEntries` table name is preserved for migration continuity — see Conflict C1 in `authority_matrix.md`. The *table* name is legacy; the *concept* it stores is XP |

**Lint rule (in architecture fitness test):**
```dart
// New lib/features/ code must not contain identifier 'points' (case-insensitive)
// Allowed exceptions: PointsLedgerEntries (table reference only), // legacy comment
```

### 2. XP (Experience Points) ✅

| Field | Value |
|-------|-------|
| **Nature** | Non-spendable engagement signal |
| **Purpose** | Show learning effort and activity — NOT mastery |
| **Source** | Learning events processed by `XpProjection` (to be created Week 5-6) |
| **Storage** | `PointsLedgerEntries` table (existing) → rename candidate `XpLedgerEntries` in schema v7 |
| **Permitted uses** | Profile display, streak streak calculation, leaderboard, CEFR progress indicator |
| **FORBIDDEN uses** | Purchasing items, unlocking curriculum content, gating features, substituting for mastery |
| **Authority** | `features/learning` domain → `LexiMotivation` domain (Week 5-6) |
| **Idempotency** | All XP grants MUST use `idempotencyKey` on `PointsLedgerEntries.unique(ownerId, idempotencyKey)` |

**Example — correct:**
```dart
await xpProjection.grant(XpGrantRequest(
  ownerId: identity.ownerId,
  amount: 20,
  sourceEventId: event.eventId,
  idempotencyKey: 'session:${event.eventId}:xp',
));
```

**Example — forbidden:**
```dart
// ❌ DO NOT: use XP to gate content
if (user.xp >= 500) unlockLevel();  // XP is not a mastery gate

// ❌ DO NOT: call it "points"  
final points = await rewardRepo.getXp(ownerId);
```

### 3. Coins (Reward Credits) ✅

| Field | Value |
|-------|-------|
| **Nature** | Spendable virtual currency |
| **Purpose** | Buy cosmetic items, avatar accessories, convenience boosts — NOT mastery signals |
| **Source** | `RewardTransactions` ledger via `RewardUseCases.grantCoins()` with `idempotencyKey` |
| **Storage** | `RewardTransactions` table (existing) — this is the **sole** coins authority |
| **Permitted uses** | Shop purchases, streak freeze purchase, cosmetic unlocks |
| **FORBIDDEN uses** | Unlocking curriculum content, expressing mastery, substituting for XP |
| **Authority** | `features/rewards` — `DriftRewardRepository` is sole writer |
| **Balance** | Computed as `SUM(amount) FROM RewardTransactions WHERE ownerId = ?` |
| **Idempotency** | All coin grants MUST use `idempotencyKey` on `RewardTransactions.unique(ownerId, idempotencyKey)` |

**Example — correct:**
```dart
await rewardUseCases.grantCoins(RewardGrantRequest(
  ownerId: identity.ownerId,
  amount: 50,
  sourceEventId: questEvent.eventId,
  idempotencyKey: 'quest:${questEvent.eventId}:coins',
  catalogVersion: currentCatalogVersion,
));
```

### 4. Mastery ✅

| Field | Value |
|-------|-------|
| **Nature** | Projection from sustained learning evidence |
| **Purpose** | Curriculum gates, skill confidence score, adaptive content selection |
| **Source** | `AnswerAttempts` + `SrsStates` + `LearningSessions` processed by `MasteryProjection` (Phase 0) |
| **Storage** | New `MasteryStates` Drift table (schema v8, Phase 0) |
| **Permitted uses** | Unlocking CEFR levels, adaptive difficulty, progress dashboard |
| **NOT affected by** | XP amount, Coins balance, streak length, time spent, purchases |
| **Authority** | `features/learning` (extended in Phase 0) |
| **Current status** | NOT IMPLEMENTED — no new code should reference mastery until Phase 0 |

### 5. Quest ✅

| Field | Value |
|-------|-------|
| **Nature** | Bounded, time-limited learning mission with explicit reward |
| **Purpose** | Short-term motivation, directing attention to weak areas |
| **Source** | Generated by `QuestDomainService` (Week 5-6, D3.5) from LearnerPersona |
| **Storage** | New `QuestInstances` + `QuestCompletionEvents` Drift tables (schema v8) |
| **Completion** | Immutable completion event with `idempotencyKey` — no double-completion |
| **Reward** | Via `RewardGrantRequest → RewardTransaction` (atomic, within same DB transaction) |
| **Authority** | NEW domain — `features/quest/` (to be created Week 5-6) |
| **QUARANTINED** | `lib/services/streak_and_daily_quest_service.dart` — in-memory, no persistence |
| **QUARANTINED** | `lib/services/adaptive_daily_quest_service.dart` — incompatible model, no persistence |
| **Migration** | Old DailyQuest data cannot be migrated (was never persisted) |

**Model conflict documented:**
```
streak_and_daily_quest_service.DailyQuest:
  {id, title, targetCount, currentProgress, coinReward, xpReward}

adaptive_daily_quest_service.DailyQuest:
  {title, description, targetMode}   ← DIFFERENT SHAPE, SAME NAME

Resolution: Both quarantined. New QuestInstance model defined in D3.5.
```

### 6. Streak ✅

| Field | Value |
|-------|-------|
| **Nature** | Count of consecutive learning days satisfying daily activity threshold |
| **Purpose** | Habit formation motivation signal |
| **Source** | `LearningSessions.occurredAtUtcMs` processed by `StreakProjection` (Week 5-6) |
| **Storage** | New `StreakStates` Drift table (schema v8) — NOT SharedPreferences, NOT in-memory |
| **Timezone** | Calculated via `TimezonePolicy` (D2.3, Week 3-4) — learning day boundary is user-local midnight |
| **Freeze** | Streak freeze is a purchased item from `OwnedRewardItems`; consumed via `RewardGrantRequest` with negative amount |
| **Grace period** | 1-day grace (missed day does not immediately break streak) — policy defined in `TimezonePolicy` |
| **Authority** | `LexiMotivation` domain (Week 5-6) |
| **QUARANTINED** | `lib/services/streak_and_daily_quest_service.dart` — `_currentStreakDays = 1` hardcoded, resets on restart |

---

### 7. Learning Day ✅

| Field | Value |
|-------|-------|
| **Definition** | A calendar day in the user's local timezone during which ≥1 `LearningSession` with `durationMs ≥ 60000` was recorded |
| **Boundary** | Midnight to midnight in device timezone (captured at session start) |
| **Authority** | `TimezonePolicy` (D2.3) |
| **NOT** | A UTC day. NOT a 24-hour window from last session. |

---

### 8. Identity ✅

| Field | Value |
|-------|-------|
| **guestOwnerId** | Local Drift `LocalOwners.id` — UUID generated on first launch; never changes |
| **cloudUid** | Firebase Auth UID — present only after sign-in; null for guests |
| **canonicalOwnerId** | The stable identifier for all ledger entries. Equals `guestOwnerId` for guests; after upgrade, equals `guestOwnerId` (guest identity is preserved, cloud is linked) |
| **actorIdentity** | Who performed the action — in single-user app = `canonicalOwnerId`. Used in `EventEnvelopeV2.actorIdentity` |
| **ownerIdentity** | Who owns the data — `canonicalOwnerId`. Used in `EventEnvelopeV2.ownerIdentity` |

## Prohibited Patterns (Linted by Fitness Tests)

```
❌ new code using ambiguous term "points" in identifiers
❌ XP used as currency (buying items with XP)  
❌ Coins used as mastery signal
❌ Streak/Quest stored in SharedPreferences or in-memory field
❌ import of quarantined services in lib/features/ code
❌ Direct Firestore writes outside of sync gateway
❌ DailyQuest model from streak_and_daily_quest_service imported anywhere
```
