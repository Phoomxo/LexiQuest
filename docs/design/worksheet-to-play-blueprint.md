## 1. ข้อวินิจฉัยและการตัดสินใจ

**ต้นแบบปัจจุบันจัดเมนูได้ชัดขึ้น แต่ยังเป็นชุดหน้ากิจกรรมมากกว่าระบบที่พาคนเริ่มจากศูนย์ไปใช้ภาษาได้จริง** การมีครบ 14 กลุ่มงานและ 14 โหมดไม่ได้พิสูจน์ว่าผู้ใหญ่ที่ไม่เคยเรียน เด็กที่ยังอ่านไทยไม่คล่อง และคนที่รู้กฎแต่ใช้ภาษาไม่ได้ จะเรียนจากระบบเดียวกันได้สำเร็จ

คำบอกเล่าหกกลุ่มมีประโยชน์ต่อการตั้งสมมติฐาน แต่ไม่ควรแปลงเป็นระดับ 1–6 ที่ทุกคนต้องเดินผ่านตามลำดับ อายุ ความรู้ตัวอักษร การอ่านคำ ความรู้ไวยากรณ์ คำศัพท์ การฟัง การพูด และการเขียนเป็นคนละมิติ คนอาจเข้าหลายกลุ่มพร้อมกัน และมีความสามารถเปลี่ยนไปตามหัวข้อหรือสถานการณ์

| การตัดสินใจ | สิ่งที่จะทำ | เหตุผล |
| --- | --- | --- |
| คงไว้ | เมนู วันนี้ / ฝึก / คำศัพท์ / ฉัน และคำสั่งภาษาไทย | มีทางเริ่มและทางกลับที่คุ้นเคย ไม่ต้องเรียนศัพท์ของระบบก่อนเรียนภาษา |
| เปลี่ยนก่อน | เปิดด้วยสาธิต → ทำพร้อมตัวช่วย → ลองเอง → ทบทวน | คนที่ไม่เคยเรียนต้องมีสิ่งให้เรียนก่อนถูกถาม |
| เพิ่มแกนกลาง | ภาพทักษะแยกด้าน ความต้องการตัวช่วย และตัวเลือกปรับความยากด้วยตนเอง | ไม่ส่งทุกคนอายุเดียวกันหรือรู้ tense เท่ากันไปเส้นทางเดียว |
| เพิ่มเนื้อหาจำเป็น | เสียง–ตัวอักษร–อ่านคำ, คำศัพท์ในบริบท, การฟังเข้าใจ, เขียนแบบมีขั้นช่วย | เติมช่องว่างที่โหมดเกมเดิมไม่ทดแทน |
| ทำให้เป็นหลักสูตรชัดเจน | Phonics: เสียงกับรูปเขียน → ผสม/แยกเสียง → อ่าน/สะกดคำ → ข้อความที่ใช้รูปเสียงที่เรียนแล้ว | มีทางช่วยคนรู้ A–Z แต่ยังอ่านคำไม่ได้ โดยไม่บังคับทุกคนเริ่มใหม่ |
| ปรับหลักออกแบบบท | Comprehensible Input: เรื่องฟัง/อ่านที่เข้าใจความหมายได้ มีบริบทและตัวช่วยตามความจำเป็น | เพิ่มการรับภาษาที่สื่อความ ไม่ให้กิจกรรมทั้งหมดกลายเป็นข้อสอบแยกคำ |
| ใช้ซ้ำ | กลไกคำตอบ บทเรียน SRS คะแนน ข้อมูลเจ้าของ และ content policy ที่มีอยู่ | ไม่สร้างระบบคะแนนหรือฐานหลักฐานอีกชุด |
| ทำภายหลัง | ซ้อมสอบเต็มชุด การประเมินงานเขียน/เสียงขั้นสูง และ AI สนทนาเสรี | ต้องมีเนื้อหาและการตรวจคุณภาพเฉพาะ ไม่ช่วยแก้ทางเข้าของคนเริ่มจากศูนย์โดยตรง |
| เลิกใช้เป็นตัวชี้วัดหลัก | จำนวนหน้าจอ จำนวนโหมด จำนวน tense และจำนวนเกณฑ์ที่ติ๊กครบ | วัดผู้ใช้เริ่มได้ ทำต่อได้ และแสดงทักษะที่เรียนได้จริง |

ขอบเขตอายุ 6–50 ปีเป็น **เป้าหมายการเข้าถึง** ไม่ใช่คำรับรองว่าทุกวัย ทุกความพิการ และทุกสภาพแวดล้อมได้รับการพิสูจน์แล้ว แอปต้องบอกขอบเขตที่ยังช่วยไม่ได้ และมีทางเรียนต่อที่เหมาะสมโดยไม่ตีตราผู้ใช้

เหตุผลการจัดลำดับใหม่: (1) แยกทักษะการอ่านตัวเขียนจากความเข้าใจภาษาจึงไม่ต้องบังคับสองทางเดินเท่ากัน (2) ตรวจเนื้อหา/เสียงก่อนทดลองช่วยลดความสับสนระหว่างปัญหาบทกับ UI (3) วัดเป้าหมายแคบและงานใหม่ช่วยจำกัดคำกล่าวอ้าง (4) ชุดเล็กทำให้เปลี่ยนทีละปัจจัยและเรียนรู้จากข้อผิดพลาดได้ก่อนลงทุนคลังใหญ่ ทั้งหมดเป็นการออกแบบของโครงการ ไม่ใช่ข้อพิสูจน์ว่าชุดนี้มีประสิทธิผลแล้ว. ฐานอ้างอิงและขอบเขตประชากรอยู่ในข้อ 2

## 2. หลักฐานและขอบเขตการอนุมาน

แยกสี่ประเภท: **รายงานจากผู้ใช้**, **สิ่งที่พบใน source**, **หลักฐานจากแหล่งทางการ**, และ **ข้อเสนอที่ต้องทดสอบ**. ไฟล์ข้อมูลผู้ใช้ที่ล็อกสิทธิ์ยังไม่ได้รับหรือเปิดอ่าน จึงไม่ทราบจำนวนตัวอย่าง วิธีเก็บ สัดส่วนวัย หรือการกระจายทักษะ ห้ามสร้างสถิติหรืออ้างว่าเป็นตัวแทนผู้เรียนไทยทั้งหมด

## 5. ภาพทักษะและการเลือกเส้นทาง

### 5.1 แยกข้อมูลสามชุด

1. **เป้าหมาย:** ชีวิตประจำวัน โรงเรียน งาน เดินทาง ความสนใจ หรือสอบ เลือกหลายอย่างและเปลี่ยนได้
2. **หลักฐานทักษะ:** ตัวอักษร/เสียง, อ่านคำ/สะกด, คำศัพท์ที่เข้าใจ, คำศัพท์ที่นึกใช้, ฟังเข้าใจ, พูด/โต้ตอบ, อ่านเข้าใจ, เขียนสื่อสาร, grammar ด้านรูป–ความหมาย–การใช้ ไม่รวมเป็นคะแนนเดียว
3. **เงื่อนไข:** ตัวช่วยไทย ข้อความ/เสียง ขนาดอักษร เวลา เน็ต ไมค์ คีย์บอร์ด และผู้ดูแล ข้อมูลนี้ไม่ลดระดับภาษา

อายุใช้จัดความเหมาะสมเนื้อหาและการคุ้มครอง ไม่ทำนายทักษะ ไม่ต้องถามวันเกิดละเอียดเพื่อเริ่มบทเรียน local ทั่วไป แต่ก่อนใช้ความสามารถที่ขึ้นกับวัย/ความยินยอมต้องมีสถานะที่ตรวจได้ตามนโยบายที่จะกำหนด ผู้ไม่ระบุใช้เนื้อหาปลอดภัยและเรียนพื้นฐานต่อได้ ไม่ถือว่าเป็นผู้ใหญ่โดยอัตโนมัติ

### 5.2 สถานะที่อ่านเข้าใจและมีหลักฐาน

ใช้ “ยังไม่ได้ลอง”, “กำลังหัดพร้อมตัวช่วย”, “ทำเองได้ในบทนี้”, “กลับมาทำได้อีก” พร้อมตัวอย่างงานและวันที่ แทน “คุณอ่อน 0%” หรือ “รู้ tense 100%”. ทำข้อเดิมถูกหลังดูเฉลยยังเป็นการฝึก ข้อมูลไม่พอให้บอกว่าไม่พอ

ข้อความเหล่านี้ต้องมีชื่อกิจกรรม/ทักษะกำกับ เช่น “จับคู่เสียงได้เองในสองข้อนี้” ไม่ใช้ “ทำเองได้” ลอย ๆ จนเข้าใจว่าอ่าน/พูดผ่านแล้ว สถานะผลไม่เป็นเงื่อนไขล็อกบทต่อ และสถานะของบทที่เพียงเปิด/ฟังจบไม่เป็น mastery

ข้อมูลภายในเชื่อม owner, skill/เป้าหมาย, item revision, attempt/session, วิธีตอบ, ตัวช่วย, replay/ความเร็ว, ผล validator, วันที่ และ policy version. ถ้าต้องแสดงความเชื่อมั่น เริ่มจากจำนวน/ความหลากหลาย/ความใหม่ของหลักฐาน ไม่สร้างเปอร์เซ็นต์ที่ยังไม่สอบเทียบ

### 5.3 เริ่มโดยไม่ทำให้เสียกำลังใจ

มี “เริ่มแบบมีคนพา” และ “ลองหาบทที่เหมาะกับฉัน”. ทางแรกเข้าสาธิตได้ทันที ทางหลังถามทีละเรื่อง ลองเฉพาะทักษะที่สนใจ มี “ยังไม่เคยเรียน”, “ไม่แน่ใจ”, “ตอนนี้ฟังไม่ได้” และข้ามโดยไม่ถูกนับผิด

ไม่สอบยาวก่อนเห็นประโยชน์ เริ่มกิจกรรมสั้นแล้วค่อยเพิ่มข้อมูลจากการใช้จริง หากผิดซ้ำหรือขอช่วยให้สอนก่อน ไม่วัดต่อจนเกิดคะแนนต่ำ ทั้งสองทางปรับง่าย/ยาก/เปลี่ยนเรื่องได้โดยไม่ลบประวัติ

### 5.4 แยกสิทธิ์เรียนต่อ คำแนะนำ และหลักฐานทักษะ

ฉบับ 4 ใช้สามการตัดสินใจแยกกัน: **เปิดบทเรียนได้ไหม** ตรวจความพร้อมเนื้อหา/สื่อ/เจ้าของ; **แนะนำอะไรต่อ** เป็นคำแนะนำที่เปลี่ยนเองได้; **รายงานว่าทำอะไรได้** ยึดหลักฐานของเป้าหมายนั้น. ไม่มีการปลดล็อกบทจากคะแนน Phonics, การเปิดไมค์ หรือการยินยอมเก็บเสียง

ผู้เรียนเลือก “ลองบทต่อไป”, “ฝึกอีกครั้ง”, “ดูตัวอย่าง”, “เปลี่ยนไปฟังเรื่อง” และกลับได้ ถ้าบทต้องใช้สื่อที่ยังไม่มี ให้บอกเหตุพร้อมทางอื่น ไม่ลดระดับภาษา ผู้ไม่เปิดไมค์ยังเรียน/ทบทวนต่อได้ ส่วนการอ่านออกเสียงที่ไม่ได้สังเกตแสดงว่า “ยังไม่ได้ตรวจการอ่านออกเสียง”

ตารางต่อไปนี้เป็น **กฎแนะนำรุ่นทดลอง `pilot-routing-v1`** ซึ่งต้อง pin ใน WP1 และทดสอบก่อนใช้ เป็นทางเลือก UX ไม่ใช่เกณฑ์ mastery หรือคะแนนมาตรฐาน:

| เหตุการณ์ | คำแนะนำที่เสนอ | สิ่งที่บันทึก/รายงาน |
| --- | --- | --- |
| ยังไม่เคยลอง | สาธิตสั้นและให้เลือกทางเริ่ม | ยังไม่มีหลักฐาน ไม่ตีเป็นศูนย์ |
| ถูกในสองข้อที่ต่างกันของเป้าหมายแคบเดียว ภายใต้เงื่อนไขที่กำหนด | “ลองตัวอย่างถัดไป” พร้อมปุ่มทบทวน | รายงานผลสองข้อและชนิดงาน เช่น จับคู่เสียง; ไม่แปลงเป็นอ่านคล่อง/ผ่านระดับ |
| ผิด/ไม่แน่ใจหนึ่งข้อ หรือใช้ตัวช่วยที่เฉลยเป้าหมาย | เสนอตัวอย่างอธิบายหนึ่งจุดและข้อใหม่ | คงคำตอบแรกและ assisted attempt แยกกัน; ข้อหลังเฉลยไม่กลายเป็น independent |
| ผิดสองข้อในเป้าหมายเดียว | ชวนกลับสาธิต เปลี่ยนวิธี หรือพัก เลือกต่อเองได้ | ใช้ชวนช่วย ไม่วินิจฉัยว่าทักษะต่ำ และไม่บังคับวนข้อเดิม |
| ไม่ตอบเพราะไม่พร้อม/ข้าม | ไปต่อหรือเปลี่ยนกิจกรรมได้ | skipped/unobserved ไม่เป็นคำตอบผิด |
| เสียงไม่เล่น/คีย์บอร์ดหรือ UI ขัดข้อง | แก้เครื่องมือหรือเลือกงานที่ไม่พึ่งสิ่งนั้น | invalid attempt แยกเหตุ ไม่ใช้คำนวณความสามารถ |
| ไม่มีไมค์/ไม่มีผู้ตรวจเสียง | ใช้กิจกรรมที่ตรวจได้และเลือกบทต่อ | ห้ามสร้างผลอ่านออกเสียง; self-report แยกจากผลที่ยืนยัน |
| กลับมาทำข้อใหม่ภายหลัง | ชวนทบทวนหรือบทถัดไปตามผลจริง | เพิ่มหลักฐานเฉพาะขอบเขตและวันที่ ไม่อ้างจำถาวร |

“สองข้อ” ใช้คุมคำแนะนำแบบเบา ๆ เท่านั้น โดยเฉพาะงานเลือกตอบยังมีโอกาสเดาถูก จำนวนนี้ไม่ใช่หลักฐานพอรับรองทักษะทั่วไป. การนับต้องอาศัย item family ที่ต่างกัน ไม่ใช่กดข้อเดิมซ้ำ และต้องรู้ว่าตัวช่วยใดเปลี่ยนความหมายของผล ถ้าเงื่อนไขไม่ครบ ให้ไม่คำนวณคำแนะนำจากคะแนน แต่ยังเลือกเรียนต่อได้

ก่อนเขียน rule ให้ WP1 ระบุ objective, สิ่งที่สอน, ตัวช่วยที่ยอมรับ, รูปแบบคำตอบ, correct/incorrect/invalid/unobserved, รูปแบบข้อใหม่ และข้อความผลของแต่ละบทให้ครบ ผู้ตรวจเนื้อหาตรวจความหมาย; domain เดิมตรวจการ commit ไม่เปิด LLM ตัดระดับหรือเลือกความยากแทนกฎนี้

| ไม่รู้ตัวอักษรและไม่เข้าใจอังกฤษ | ฟัง/ดูสถานการณ์เข้าใจง่าย พร้อมตัวเลือกเริ่มรูป–เสียง | เริ่มฟังได้ก่อนเรียน A–Z ครบ |
| รู้ชื่ออักษรแต่ผสมเสียงไม่ได้ | Phonics ตรงรูป–เสียง/ผสมคำ | เรื่องฟังที่เหมาะกับความเข้าใจ ไม่ท่องชื่อทั้งหมดใหม่ |
| ฟังเข้าใจมากกว่าอ่าน | ฝึกอ่านคำตามรูปเสียงที่สอน | ฟังเรื่องยากกว่าได้ ไม่มี prerequisite จากคะแนนอ่าน |
| อ่านรูปคำได้แต่ไม่เข้าใจ | คำศัพท์ วลี เรื่องพร้อมความหมาย | ทบทวน Phonics เฉพาะจุดตามสมัครใจ |
| รับสารได้แต่พูดเขียนยังไม่คล่อง | งานสื่อสารและฝึกสิ่งที่รู้ให้คล่อง | ไม่บังคับรับสารอย่างเดียว และไม่บังคับตอบด้วยเสียง |

แยกความยาก **การถอดรหัสตัวเขียน** กับ **ความเข้าใจคำ/เรื่อง**. เนื้อหาเรื่องไม่ต้องจำกัดด้วยรูปเสียงที่อ่านได้ทั้งหมด; ข้อฝึกอ่านเองต่างหากที่ต้องใช้ prerequisites ที่สอนแล้ว อายุและความเร็วพิมพ์ไม่เป็นตัวแทนสองมิตินี้ และไม่สร้างคะแนนรวมระดับเดียวจากผลที่สังเกตไม่ครบ

## 6. หลักสูตรและวงจรการสอนที่ต้องเติม

วงจรหลัก: **เห็นประโยชน์ → ดู/ฟังตัวอย่าง → ทำไปด้วยกัน → ลองเอง → รู้เหตุผล → กลับมาทบทวน → ใช้กับเรื่องใหม่**. ความผิดพลาดเป็นข้อมูลเพื่อช่วยสอน ไม่ใช่เหตุให้ตัดสิทธิ์หรือบังคับซื้อหัวใจ

ตารางต่อไปนี้เป็นภาพรวมหลักสูตรระยะขยาย ขอบเขตที่ทำก่อนคือชุดใน 6.6 เท่านั้น ไม่ต้องทำครบทุกแถวหรือทั้ง 12 tense ก่อนทดลองรอบแรก

| เส้นทาง | เนื้อหา/การสอน | ตัวอย่างกิจกรรม | เงื่อนไขก้าวต่อ |
| --- | --- | --- | --- |
| พร้อมเริ่ม | สาธิตปุ่มเสียง การตอบ การย้อนกลับ และความหมายโจทย์ | ฟังคำสั่งไทยและแตะภาพเพื่อเรียนรู้วิธีใช้ | แยกกดเป็นออกจากรู้ภาษา |
| เสียงและความหมาย | วัตถุ การกระทำ บุคคล ความต้องการง่าย ๆ | เห็นแก้ว ฟัง water รู้ความหมายไทย แล้วเลือกภาพใหม่ | รู้ความหมายที่สอนโดยไม่บังคับอ่านอังกฤษ |
| ตัวอักษรและอ่านคำ | ใหญ่/เล็ก ชื่อแยกจากเสียง รวม/แยกเสียง คำที่ไม่ตรงแบบ | อ่านคำที่ใช้รูปเสียงที่สอนแล้ว เทียบส่วนที่ต่าง | อ่านคำใหม่ในขอบเขตที่สอน ไม่วัดแค่ท่อง ABC |
| คำสู่วลี | ศัพท์ตามเป้าหมาย กลุ่มคำที่ใช้คู่กัน ฟังคำในประโยค | water → a glass of water → ขอเครื่องดื่ม | เข้าใจและเลือกใช้วลีในบริบท |
| ประโยคสื่อสาร | ใครทำอะไร ถาม ปฏิเสธ เวลา จำนวน สถานที่ ความสุภาพ | นัดหมาย บอกกิจวัตร ขอให้พูดซ้ำ | เข้าใจ/ใช้รูปได้ ไม่ต้องจำชื่อกฎก่อน |
| ใช้หลายทักษะ | ฟัง/อ่านเรื่องแล้วตอบ โต้ตอบ เขียน แก้ร่าง | อ่านเวลาร้าน ฟังนัดหมาย เขียนบอกเพื่อน | สื่อข้อมูลที่ต้องการและตรวจความเข้าใจ |
| ขยายตามเป้าหมาย | ภาษาเรียน/งาน/ความสนใจ สรุป หลักฐาน ความคิดเห็น | อ่านหลายย่อหน้า เขียนโน้ต/อีเมล เปรียบเทียบข้อมูล | งานซับซ้อนตามหลักฐานรายทักษะ |
| เตรียมสอบ | เรียนรูปแบบ → ฝึกเป็นส่วน → ชุดจำลอง | ฟังเติมตาราง อ่านใจความ เขียนตามโจทย์ | คลังข้อสอบ/สื่อ/rubric/เวลา/บันทึกผ่านการตรวจ |

ตารางเป็นทางเนื้อหา ไม่ใช่ประตูล็อกตายตัว คนพูดได้แต่ยังอ่านไม่ได้เรียนพูดต่อควบคู่การอ่านคำได้ ผู้มีข้อจำกัดการได้ยินต้องมีทางเรียนที่เหมาะสม โดยไม่อ้างว่าเส้นทางภาพทดแทนการวัดการฟัง

### 6.1 ตัวอย่างบทแรกที่สอนได้จริง

บท “ขอน้ำ”: บอกเป็นไทยว่าจบแล้วจะเข้าใจและเลือกคำขอน้ำ → ภาพชัดพร้อมเสียง/ความหมาย → สาธิตความต่างระหว่างแตะฟังกับส่งคำตอบ → เลือกภาพจากสิ่งที่สอน → ตัวอย่างคำขอน้ำ → ลองในสถานการณ์ใหม่ → สรุปสิ่งที่ฝึกและนัดทบทวน

เด็กอาจใช้ที่บ้าน ผู้ใหญ่ใช้ร้านอาหาร เป้าหมายภาษาเทียบเคียงกันแต่ไม่ทำให้ผู้ใหญ่รู้สึกกลับไปเป็นเด็ก ถ้ายังไม่พร้อมใช้ประโยค จบที่คำก่อนได้โดยไม่แสดงว่าล้มเหลว นี่คือเรื่องเล่าสำหรับออกแบบ ไม่ใช่คำยืนยันว่าหนึ่งบททำให้พูดได้แล้ว

### 6.2 ไวยากรณ์และ “12 tense”

เก็บตาราง 12 รูปที่คนไทยคุ้นเป็นแหล่งเปิดดูใน “ประโยคและไวยากรณ์” ไม่ใช้วัดความสามารถทั้งหมด เรียนด้วย **ความหมายที่จะสื่อ → ตัวอย่าง → รูปคำ → ลองใช้** และมีศัพท์ที่จำเป็นก่อน. คำว่า tense ในหลักสูตรทั่วไปมักรวมรูปเกี่ยวกับเวลาและ aspect; ไม่ให้ผู้เริ่มต้นต้องผ่านศัพท์วิชาการก่อนสื่อสาร

| กลุ่มอ้างอิง | หัวข้อเมื่อขยายครบ | วิธีจัดลำดับ |
| --- | --- | --- |
| Present | simple, continuous, perfect, perfect continuous | กิจวัตร/กำลังทำ แล้วค่อยความเชื่อมโยงอดีตและความต่อเนื่อง |
| Past | simple, continuous, perfect, perfect continuous | เหตุการณ์ที่ผ่านมา แล้วค่อยความสัมพันธ์ระหว่างเหตุการณ์ |
| Future forms | simple, continuous, perfect, perfect continuous ตามชื่อแบบเรียนทั่วไป | แผน/ความตั้งใจ/คาดการณ์ แล้วค่อยการมองไปยังจุดเวลาในอนาคต |
| นอกตาราง 12 รูป | be/do/have, คำถาม/ปฏิเสธ, คำนาม/พหูพจน์, articles, pronouns, prepositions, modal verbs, comparison, conjunctions และหัวข้อตามเป้าหมาย | ตามประโยชน์และ prerequisite ของงานสื่อสาร ไม่ใส่ทั้งหมดในบทแรก |

แต่ละหัวข้อแยก “เข้าใจความหมาย”, “สร้างรูป”, “เลือกใช้ในสถานการณ์” และ “ใช้ขณะพูด/เขียน”. เติมช่องว่างครั้งเดียวไม่ยืนยันรู้ทั้งหัวข้อ ไม่แสดงรู้ครบ 100% จากการดูครบทุกบท

### 6.3 คำศัพท์และทิศทางภาษา

คำหนึ่งมีเสียง รูปเขียน ความหมายเฉพาะบริบท คำที่ใช้คู่กัน รูปผัน และการนำไปใช้ การเลือกคำแปลถูกไม่เท่ากับนึกคำมาพูดหรือเขียนได้ เพิ่มทั้งเข้าใจเมื่อเห็น/ได้ยินและนึกใช้จากสถานการณ์ รวมคำหลายความหมายและคำตอบไทยที่ใช้แทนกันได้

อังกฤษ→ไทยและไทย/สถานการณ์→อังกฤษรองรับตามความหมายจริงของกิจกรรม การพิมพ์แปลกลับอาจมีหลายคำตอบ ต้องมี accepted variants/rubric. Listening/reading ไม่จำเป็นต้องมีปุ่มสลับทิศเหมือนบัตรคำ และการฟังไทยไม่เป็นหลักฐานการฟังอังกฤษ

คำอ่านไทยเป็นตัวช่วยเลือกเปิดในเนื้อหาที่ตรวจแล้ว พร้อมเสียงต้นแบบและข้อจำกัด ไม่ใช้คำอ่านไทยตัดสินการออกเสียง ไม่ถือสำเนียงไทยเป็นความผิดโดยตัวมันเอง มุ่งสื่อสารเข้าใจและเสียงในขอบเขตที่สอน

### 6.4 Phonics: เส้นทาง “เริ่มอ่านภาษาอังกฤษ”

Phonics ในแผนนี้สอนความสัมพันธ์ของรูปเขียนกับเสียงอย่างมีลำดับ มีการสาธิตและสะสมความรู้เดิม ใช้การผสมเสียงแบบ synthetic phonics เป็นกิจกรรมหนึ่ง ไม่อ้างว่าเป็นสูตรที่ดีที่สุดสำหรับทุกวัย. **ชื่อตัวอักษร**, **ความตระหนักเสียงในคำพูด**, **เชื่อมรูปกับเสียง**, **อ่านคำ**, **สะกด**, และ **เข้าใจคำ** เป็นเป้าหมายคนละอย่าง. ฐานหลักฐานการสอนพื้นฐานอ่านที่ใช้อ้างมีขอบเขต K–3 จึงต้องตรวจความเหมาะสมผู้ใหญ่ไทยแยก ตาม [IES](https://ies.ed.gov/ncee/wwc/PracticeGuide/21/Published).

| ขั้นสอนที่เสนอ | กิจกรรมและตัวช่วย | หลักฐานที่ใช้ได้ |
| --- | --- | --- |
| รู้รูปและใช้งาน | ใหญ่/เล็ก ชื่อตัวอักษรเมื่อจำเป็น แยกปุ่มฟังชื่อกับฟังเสียง | ระบุว่าจำรูป/ชื่อได้ ไม่เรียกอ่านคำได้ |
| สังเกตเสียงและเชื่อมรูป | ฟังเสียงต้นแบบ เทียบคำ/รูปที่ต่างกัน พร้อมความหมาย | การแยกเสียง/จับคู่รูป–เสียงภายใต้รูปแบบโจทย์นั้น |
| ผสมเสียง | แสดงส่วนของคำ เช่น m–a–t สาธิต /m/ /æ/ /t/ → mat แล้วค่อยลดตัวช่วย | เลือกเสียงคำที่ตรงเป็น recognition; อ่านออกเสียงเองต้องมีหลักฐานเสียงที่ประเมินได้ |
| แยกเสียงเพื่อสะกด | ฟังคำที่รู้ความหมาย แยกเสียงแล้วแตะตัวอักษรหรือพิมพ์ | แยก tile selection, copy และ spelling recall; แต่ละแบบมีตัวช่วยต่างกัน |
| รูปเสียงเพิ่มเติม | เช่น sh/ch, กลุ่มพยัญชนะและแบบสระที่ผู้ตรวจจัดลำดับ | ฝึกในคำที่มีรูปเสียงก่อนหน้าครบ ไม่ถืออักษรหนึ่งมีเสียงเดียวตลอด |
| อ่านข้อความต่อเนื่อง | คำ/ประโยคที่ประกอบด้วยรูปเสียงที่สอนแล้ว พร้อมคำข้อยกเว้นที่สอนชัด | ตรวจอ่านแยกจากเข้าใจความหมายและการมีเสียงอ่านให้ฟัง |

ลำดับชุดตัวอักษรต้องเลือกโดยผู้ตรวจหลักสูตรจากคำที่สร้างได้และเป้าหมาย ไม่เรียง A–Z เพื่อให้ครบตัวก่อนผสมคำ. คำไม่ตรงแบบและเสียงที่ต่างตามสำเนียงต้องระบุอย่างถูกต้อง ไม่เดากฎจากตัวอักษรเดี่ยว ต้องมีรายการ prerequisites, รูปเสียงที่สอนแล้ว, ข้อยกเว้น และคำใหม่สำหรับตรวจการนำไปใช้

เสียง Phonics ต้องผ่านการตรวจว่าเป็นเสียงเป้าหมาย ไม่ใช่ TTS อ่านชื่อตัวอักษรหรือเติมเสียงท้ายที่ทำให้ผสมคำผิด. IPA เป็น metadata/เครื่องมือผู้ตรวจ ไม่เป็นสิ่งบังคับให้ผู้เริ่มต้นอ่าน ไม่ใช้คำถอดเสียงไทยสร้างแบบเสียงหลัก บทสอนใช้รูปและเสียงที่ตรวจแล้ว; ผู้เรียนเลือกเล่น หยุด ซ้ำได้

**ภาพช่วยความหมายในช่วงสอน แต่ไม่ควรเฉลยคำในช่วงตรวจการอ่านเอง**. ถ้ามีภาพแมวแล้วตอบ cat ได้ อาจรู้จากภาพ ต้องใช้คำ/ลำดับใหม่ที่ไม่เฉลยด้วยภาพหรือเสียงก่อนตอบเมื่อวัดการอ่าน พร้อมวิธีเข้าถึงที่ระบุข้อจำกัด ไม่บังคับไมค์เป็นเงื่อนไขเข้าเรียน และไม่เรียกการเลือกคำตอบว่าออกเสียงเองผ่านแล้ว

### 6.5 Comprehensible Input: ข้อกำหนดของบทฟังและอ่าน

เป็นหลักเลือกและนำเสนอเนื้อหาที่ผู้เรียนเข้าใจสารได้ ไม่ใช่แท็บชื่อวิชาการหรือเพียงเพิ่มไฟล์เสียง. ใช้ภาพ/การกระทำ/บริบท/คำช่วยไทยอย่างมีจุดประสงค์ แล้วให้พบภาษาเดิมในเรื่องที่เปลี่ยนไป คงการฝึกพูด เขียน grammar และทบทวนไว้ การผสมนี้เป็นแนวทางของ LexiQuest ไม่ใช่การอ้างว่าใช้ทฤษฎีของ Krashen ทุกข้อหรือรับรองว่าการรับสารอย่างเดียวเพียงพอ

| องค์ประกอบบท | ข้อกำหนดการออกแบบ |
| --- | --- |
| เป้าหมายและเรื่อง | มีสารให้เข้าใจ เช่น ใครอยู่ที่ไหน/ต้องการอะไร ไม่ใช่รายการคำไร้สถานการณ์ เลือกหัวข้อเหมาะวัยและความสนใจ |
| ความยาก | ดูศัพท์ รูปประโยค ความยาว ความเร็วเสียง ความคุ้นเรื่อง และตัวช่วยแยกกัน “i+1” ใช้เป็นแนวคิด ไม่สร้างตัวเลขระดับบวกหนึ่งหรือสัดส่วนคำรู้จักตายตัว |
| ทางช่วย | ฟังซ้ำ ชะลอเสียงที่ตรวจคุณภาพแล้ว ภาพ คำแปลเฉพาะจุด/บทพูดเมื่อเลือก ไม่บังคับตัดภาษาไทยทันที |
| การดูว่าเข้าใจไหม | แตะเหตุการณ์/เรียงภาพ/เลือกความหมาย/ตอบสั้นตามความพร้อม ไม่บังคับเขียนอังกฤษเพื่อพิสูจน์การฟังของคนที่ยังเขียนไม่ได้ |
| ไม่แทรกสอบตลอด | ให้ฟัง/อ่านเพลินได้ ชวนตรวจความเข้าใจในจังหวะเหมาะ การเปิดเรื่องและเวลาอยู่หน้าไม่เป็นความชำนาญ |
| ปรับเมื่องง | ลดภาระศัพท์/ความยาว/เสียงทีละปัจจัยหรือเพิ่มตัวอย่าง รักษาเป้าหมายและให้ผู้เรียนเลือกเปลี่ยน ไม่เพิ่มภาษาใหม่หลายอย่างพร้อมกัน |
| เรียนต่อ | ชวนเล่าหรือเขียนตามความพร้อมและกลับทบทวน ไม่บังคับพูดทันทีเพื่อปลดล็อกการเรียน |

เนื้อหาที่ **อ่านตามรูปเสียงที่สอนแล้วได้** กับเนื้อหาที่ **เข้าใจความหมายได้** ต้องตรวจคนละอย่าง บทขอน้ำจาก 6.1 ใช้เป็น input พร้อมเสียง/ภาพได้ แต่คำ water หรือประโยคขอน้ำไม่ถือเป็นแบบอ่านเองสำหรับผู้ที่ยังไม่เรียนรูปเสียงนั้น

เมื่อดูความสมดุลหลักสูตร ใช้กรอบรับสาร–ผลิตภาษา–เรียนรูปภาษา–ความคล่องจาก [Nation](https://www.wgtn.ac.nz/lals/resources/paul-nations-resources/paul-nations-publications/publications/documents/2007-Four-strands.pdf). ไม่บังคับเวลาเท่ากันทุกบทหรือใช้เวลาหน้าจอเป็นผลเรียน เรื่องยาวขึ้นต้องเป็นไปตามหลักฐานความเข้าใจและการเลือกของผู้เรียน

### 6.6 ขอบเขตชุดทดลองแรกที่กำหนดให้ทำจริง

ฉบับ 4 เริ่มสองกลุ่มผู้ใหญ่ 18–50 ปี: **A — ไม่เคยเรียน/เริ่มอังกฤษจากศูนย์** และ **B — รู้ชื่อตัวอักษรแต่ยังผสมอ่านคำไม่ได้**. ใช้คำบอกเล่าประกอบกิจกรรมสั้นเพื่อดูจุดเริ่ม ไม่ให้ผู้พัฒนาติดป้ายจากอายุหรือแบบสอบยาว ผู้ใหญ่ที่อ่านไทยไม่สะดวกให้มีเสียงคำสั่งและบันทึกความต้องการช่วยแยก

ช่วงวัยนี้ใช้จัดกลุ่ม UX ไม่แทนสถานะความยินยอมตามกฎหมาย ก่อนเข้าร่วมต้องตรวจเงื่อนไขที่เกี่ยวข้องกับบุคคลและข้อมูลที่จะเก็บทุกคน การปฏิเสธเก็บเสียงยังไม่ตัดสิทธิ์เรียน

การจำกัดวัยในรอบแรกเป็นการจัดลำดับงาน ไม่ใช่ข้อสรุปว่าเด็กใช้ไม่ได้หรือใช้ได้เหมือนผู้ใหญ่ กลุ่มเด็ก/วัยรุ่นและทักษะอื่นยังอยู่ในแผนขยาย ต้องมีเนื้อหา/เงื่อนไขผู้ดูแลและหลักฐานของกลุ่มนั้นก่อนอ้างรองรับอายุ 6–50 ครบ

| สิ่งส่งมอบชุดแรก | ขอบเขตที่ต้องมี | สิ่งที่ไม่อ้างจากชุดนี้ |
| --- | --- | --- |
| บท Phonics หนึ่งลำดับสั้น | ชุดรูป–เสียงที่ผู้ตรวจเลือกให้ผสมคำได้ สาธิต ผสม/แยกเสียง ความหมาย และลองเอง มีคำใหม่จากรูปเสียงเดิม | ไม่ใช่หลักสูตร A–Z ทั้งหมดหรือใบรับรองอ่านคล่อง |
| เรื่องรับสารหนึ่งเรื่องหลัก | เรื่องสั้นมีเหตุการณ์ต่อเนื่องและประโยชน์ในชีวิตผู้ใหญ่ ภาพ/เสียง/คำไทยเปิดช่วยได้ ฟังหรืออ่านต่อโดยไม่ต้องตอบทุกช่วง | ไม่ใช่ศัพท์โดด ๆ แล้ว quiz ทุกหน้า และไม่ให้คะแนนเพียงฟังจบ |
| ข้อ/เรื่องสำหรับตรวจใหม่ | ชุดก่อนเรียน หลังเรียน และติดตามภายหลังที่เทียบเป้าหมายแต่ไม่ซ้ำคำตอบเดิม แยกจากตัวอย่างที่สอน | ไม่ใช้การจำเรื่อง/ข้อเดิมแทน transfer |
| จุดเชื่อมที่เลือกได้ | หลังเรื่องอาจชวนฝึกคำที่อ่านตามรูปเสียงที่เรียนได้; หลัง Phonics อาจชวนฟังเรื่อง | ไม่บังคับเรียนสองส่วนคู่กันทุกบทหรือผ่านส่วนหนึ่งเพื่อเปิดอีกส่วน |
| สถานะใช้งานจริงของสองทาง | เริ่ม ขอช่วย ข้าม พัก กลับต่อ ไม่มีเสียง กดซ้ำ เปลี่ยนเจ้าของ และผลที่บอกขอบเขตตรง | ไม่รับรองทุก route ของทั้งแอป |

ตัวอย่างสองทาง: “ฝึกผสมคำสั้น” อาจใช้ mat/map ตามชุดที่ผู้ตรวจเลือก; “ขอน้ำในร้าน” ใช้บทพูดและบริบทที่เข้าใจ แม้ผู้เรียนยังอ่าน water เองไม่ได้. “แมวกับเสื่อ” จากฉบับก่อนเป็นตัวเลือกสาธิตจุดเชื่อม ไม่ใช่แม่แบบบังคับทุกบท

ก่อน WP2 ต้องมี mini-content pack ที่ **ตรวจแล้วสำหรับการทดลอง**: เป้าหมาย/ลำดับรูปเสียง, script ไทย–อังกฤษ, ภาพและเสียงตามหน้าที่, เฉลย/rubric, ข้อใหม่, สิทธิ์สื่อ, content/media revision และบันทึกผู้ตรวจ. เป็นคุณภาพขั้นต่ำเพื่อแยกปัญหาบทเรียนจาก UI ไม่ต้องผลิตคลังเต็มหรือ migration production ก่อนทดลอง

ระบุบทบาทในบันทึก: ผู้สร้างเนื้อหา, ผู้ตรวจการสอนอ่านอังกฤษและความเหมาะกับผู้ใหญ่ไทย, ผู้ตรวจเสียง/ภาษา (คนเดียวกับผู้ตรวจเนื้อหาได้เมื่อมีความสามารถ), ผู้ดำเนินกิจกรรมผู้ใช้ และผู้รับผิดชอบข้อมูล. ต้องระบุผู้ทำจริงเมื่อถึง WP1; ห้ามใส่ชื่อหรือผลอนุมัติสมมติ. AI ช่วยร่างไม่แทนการตรวจเหล่านี้ และไม่มีการว่าจ้าง/ส่งข้อมูลออกอัตโนมัติ

หากยังไม่มีผู้ตรวจหรือเสียงที่ผ่านตรวจ ทำ wireframe/interaction ด้วยป้ายสื่อร่างได้ แต่ยังไม่เปิดรอบตรวจการเรียน. ตรวจ navigation ด้วยสื่อร่างได้เฉพาะเพื่อดูการใช้ปุ่ม และต้องแยกผลนั้นจากผลของบทเรียนจริง

## 7. โมดูลที่จะคง ปรับ เพิ่ม และพัก

เพิ่มความสามารถตามตาราง ไม่เพิ่มเมนูหรือจำนวนโหมดเพื่อให้ดูหลากหลาย การเปลี่ยน mode ID/API ต้องมีเหตุผลและ mapping ย้อนกลับ

ลำดับในตารางเป็นความสำคัญของผลิตภัณฑ์โดยรวม คำว่า “ชุดแรก” ใช้เฉพาะส่วนย่อยที่จำเป็นต่อ 6.6 ไม่สั่งพัฒนาทั้งโมดูลพร้อมกัน; บทตัวอย่างใช้ interaction เดิมที่เหมาะได้โดยไม่ต้องเปิดความสามารถทุก mode

| กลุ่มงาน | ฐานเดิม/ข้อเสนอเดิม | งานปรับ | ลำดับ |
| --- | --- | --- | --- |
| ทางเข้ามีคนพา | ยังไม่มี lesson onboarding จริง | สาธิตการใช้ สอนก่อนถาม เลือกตัวช่วย | ก่อนขยายกิจกรรม |
| Phonics: เริ่มอ่านภาษาอังกฤษ | picture lab, word-scramble, handwriting-scratchpad บางส่วน | ลำดับรูป–เสียง/ผสม/แยกเสียง/คำใหม่/ข้อความอ่านได้; แยก trace/copy/recall; แตะแทนลาก | ชุดแรกตาม 6.4 |
| ฟังและอ่านเรื่องที่เข้าใจ | listening lab, cefr-reading, ภาพ–เสียง–คำ และบทตามสถานการณ์ | คัด input ตามความเข้าใจพร้อมตัวช่วยและหลายบริบท แยกความเข้าใจจากการอ่านออกเสียง | หลักร่วมตั้งแต่ชุดแรกตาม 6.5 |
| คำศัพท์เข้าใจและนึกใช้ | meaning-quiz, definition-quiz, typed-recall, matching, flashcard | บริบท ตัวช่วยเป็นขั้น หลายคำตอบ แยกทบทวนจากดูเฉลย | ชุดแรก |
| ฟังและสื่อสาร | dictation, speaking, shadowing, listening lab | ฟังเข้าใจก่อนพิมพ์ตาม ผลัดกันพูดตามสถานการณ์; recognition ไม่ตัดสินคนเดียว | ชุดแรก/ขยายตามสื่อ |
| ประโยคและไวยากรณ์ | cloze, sentence-scramble, sentence lab | อธิบายความหมาย เลือกใช้/แก้/สร้างประโยค ไม่จำกัดเติมกริยา | หลังทางเริ่มพร้อม |
| อ่านเข้าใจ | associative-reading, cefr-reading, evidence lab | คำ→ประโยค→เรื่อง หาใจความ/หลักฐาน/ไม่มีข้อมูล ระดับต่างจริง | หลังคลังพร้อม |
| เขียนสื่อสาร | writing lab; typed-recall ไม่ครอบคลุม | คิด→วางโครง→เขียน→ตรวจ→แก้; ร่าง/ประวัติ/rubric เข้าใจง่าย | หลัง draft lifecycle พร้อม |
| ภารกิจใช้จริง | mission lab และหลายรูปแบบฝึก | เป้าหมายย่อย ผลจากการเลือก ทางขอช่วย หลายคำตอบที่เหมาะสม | หลังส่วนย่อยมั่นคง |
| ซ้อมสอบ | exam draft | เรียนรูปแบบ/ฝึกส่วน/จำลองชุดแยกกัน; Reasoning ไม่ใช่พาร์ตทางการ | หลัง core และ content gate |

หกกลุ่มเดิมยังอยู่: **ภาพ–เสียง–คำ, ฟังแล้วหา, ประโยคใช้จริง, นักสืบข้อความ, ห้องเขียน, ภารกิจใช้จริง** โดยเป็นเนื้อหาและ interaction ภายในระบบสอนเดียวกัน ไม่ใช่หกฐานคะแนนใหม่

เส้นทางสอบจริงระบุ IELTS Academic หรือ General Training เพราะงานอ่าน/เขียนต่างกัน ส่วน TOEIC Listening/Reading และ Speaking/Writing เป็นคนละชุดการประเมิน โหมดเรียนเปิดซ้ำ/ดูคำอธิบายได้ ชุดจำลองต้องระบุกติกาเสียง เวลา หยุด และตัวช่วย. ใช้คะแนนฝึก LexiQuest ไม่แปลงเป็น band/scaled score ทางการจนกว่าจะมีหลักฐานรองรับ. อ้างอิง [IELTS test types](https://ielts.org/take-a-test/test-types), [ETS LR](https://www.ets.org/toeic/about/listening-reading.html), [ETS SW](https://www.ets.org/toeic/about/speaking-writing.html).

## 8. ปรับตามวัยโดยไม่ผูกวัยกับความสามารถ

ช่วงต่อไปนี้เป็นกลุ่มออกแบบ/ทดสอบ ไม่ใช่เส้นแบ่งความพร้อมทางสมองหรือภาษา

รอบแรกในฉบับ 4 ตรวจผู้ใหญ่ 18–50 สองโปรไฟล์ก่อน ตารางทุกวัยยังคงเป็นเป้าหมายขยาย แต่ต้องมีการตรวจบทและ UX กับเด็ก/วัยรุ่นจริงใน WP6 ก่อนอ้างครอบคลุมอายุเหล่านั้น

| กลุ่ม | ความต้องการที่ต้องตรวจ | สิ่งที่เสนอ | สิ่งที่เลี่ยง |
| --- | --- | --- | --- |
| 6–8 ปี | อ่านไทยได้แค่ไหน จำขั้นตอนได้ไหม ใช้กับผู้ดูแลหรือไม่ | หนึ่งคำสั่งต่อขั้น เสียงไทยเมื่อแตะ ภาพชัด เป้าหมายสั้น ทางช่วยจากผู้ดูแล | สอบยาว อ่านอธิบายกฎเอง แชตเสรีที่ยังไม่มีการคุ้มครอง |
| 9–12 ปี | ความสนใจ ความอายเมื่อผิด เครื่องร่วม | เรื่องโรงเรียน/ชีวิต/ความสนใจ เลือกความท้าทายและพักได้ | บังคับแข่ง เปิดเผยคะแนน สมมติว่าอ่านอังกฤษแล้ว |
| 13–17 ปี | ความเป็นส่วนตัว เป้าหมายเรียน/สอบ ไม่อยากถูกทำให้เป็นเด็ก | ภาพลักษณ์กลาง งานสื่อสารจริง กติกาข้อมูลที่อ่านรู้เรื่อง | ตีตราระดับต่อหน้าคนอื่น หรือกดดันให้กลับมาทุกวัน |
| 18–50 ปี | งาน ครอบครัว เวลา ประสบการณ์เรียน/ดิจิทัลแตกต่าง | ชีวิต/งาน/เดินทาง เริ่มง่ายอย่างมีศักดิ์ศรี พักและต่อสะดวก | บังคับธีมเด็กสำหรับพื้นฐาน หรือคิดว่าทุกคนใช้แอปคล่อง |

เลือกความสนใจ/รูปแบบนำเสนอได้ ไม่สร้างทางชาย/หญิงหรือผูกอาชีพกับเพศ มีตัวละคร/สถานการณ์หลากหลายโดยไม่ถามข้อมูลเกินจำเป็น ผู้ดูแลไม่ต้องรู้ภาษาอังกฤษ หน้าช่วยบอกให้ช่วยเรื่องการใช้งานและให้ผู้เรียนตอบเอง

## 9. อุปสรรคภาษาและสภาพแวดล้อม

หัวข้อภาษาไทยด้านล่างเป็นสมมติฐานที่ต้องสังเกต ไม่เหมารวมคนไทยทุกคน และไม่ใช้วินิจฉัยความผิดปกติการเรียนรู้

| ปัจจัย | วิธีรองรับ | วิธีไม่ตีความผลผิด |
| --- | --- | --- |
| อ่านไทยไม่คล่อง/ภาษาแรกอื่น | คำไทยง่าย ภาพ เสียงคำสั่ง ทางใช้ร่วมผู้ดูแล | แยกไม่เข้าใจคำสั่งจากไม่รู้ภาษา; ยังไม่อ้างรองรับทุกภาษาแรก |
| จำชื่อตัวอักษรแต่ถอดเสียงไม่ได้ | สอนรูป–เสียงและอ่านคำเป็นขั้น | ABC ไม่ใช่เกณฑ์ผ่านอ่าน |
| เสียงท้าย/คำติดกันฟังไม่ชัด | เสียงตรวจแล้ว เทียบความต่าง ค่อยกลับความเร็วธรรมชาติ | ผลจากเสียงช้าคือหลักฐานในเงื่อนไขนั้น |
| แปลตรงคำ/คำหลายความหมาย | บริบท กลุ่มคำ คำอธิบายไทยเฉพาะความหมาย | เก็บ sense/context และรับคำแปลที่ถูกหลายแบบ |
| รู้เรื่องเวลาแต่ใช้ประโยคผิด | เทียบเจตนา/รูปคำ เส้นเวลาเมื่อช่วยจริง | ตรวจสื่อความแยกจากรูป ไม่เหมาจากชื่อ tense |
| กลัวผิด/อายพูด | ทดลองส่วนตัว อัด/ฟังตนเองเมื่อเลือก แก้ทีละจุด | ไม่ใช้ไมค์/พูดเบาไม่เท่ากับทักษะต่ำ |
| เสียงดัง/ไม่มีหูฟัง/พูดไม่ได้ตอนนี้ | เรียนอ่าน/เขียนหรือเลื่อนเสียง | ดูบทพูดไม่เป็นผล listening |
| เน็ตแพง/ขาดช่วง | ชุดเริ่มอยู่ในเครื่อง ขนาดดาวน์โหลดชัด local ก่อน sync | ไม่ถือ offline เป็นผิด/abandon; ไม่สัญญาทุก pack/AI ใช้ offline |
| เครื่องช้า/พื้นที่น้อย | ลด animation โหลดสื่อเท่าที่ใช้ ล้าง cache แยก | ไม่ลบ draft/ประวัติเพื่อคืนพื้นที่; กล้องไม่เป็น prerequisite |
| เครื่องร่วม | เจ้าของ session ชัด แยกโปรไฟล์ ปิด context เมื่อเปลี่ยนคน | ซ่อนหน้าหรือ PIN อย่างเดียวไม่แทน owner isolation/encryption policy |
| พิมพ์ไม่คล่อง/auto-correct | วิธีตอบตามเป้าหมาย ฝึกคีย์บอร์ดแยก ระบุการช่วยพิมพ์ | auto-complete ไม่ใช่ spelling recall; ถ้าตรวจไม่ได้ต้องจำกัดคำกล่าวอ้าง |
| สายตา/การได้ยิน/มือ/สมาธิต่าง | ขยาย screen reader ลดเคลื่อนไหว แตะแทนลาก ไม่จับเวลาในโหมดเรียน | ทางเลือกอาจเปลี่ยนทักษะที่วัด ต้องเก็บเงื่อนไข |
| สายเข้า/ปิดแอป/ถูกขัดจังหวะ | save/resume ที่มองเห็นและถามก่อนทิ้ง | timeout ไม่กลายเป็นคำตอบผิด/คะแนนซ้ำ |

### 10.1 ต้นแบบรอบแรกและภาพรวมที่จะขยาย

รอบแรกทำสองการเดินทางตาม 6.6: ผู้ใหญ่เริ่มศูนย์ และผู้ใหญ่รู้ A–Z แต่อ่านคำไม่ได้. ทั้งสองเลือก Phonics หรือเรื่องรับสารได้โดยอิสระ ผ่านเริ่ม → ตัวอย่าง → ลอง → ขอช่วย/ข้าม → พัก → กลับ → ผล. ไม่เปิดตัวเลือกทั้งหมดพร้อมกัน หน้า “วันนี้” แนะนำหนึ่งอย่างและเปลี่ยนได้โดยไม่ทำ placement ยาว

ทำเฉพาะหน้าร่วมที่ต้องใช้: เลือกจุดเริ่ม/ตัวช่วย, สาธิต, กิจกรรม, เรื่อง, ผล, ทบทวนและงานค้าง รวมสถานะสื่อ/เจ้าของที่กระทบเส้นทาง. W01–W14 และห้าเส้นทางเดิมเป็นแผนภาพรวมเพื่อเช็กผลกระทบและขยายภายหลัง ไม่เป็นเงื่อนไขให้ทำต้นแบบครบทุกระบบก่อนพบผู้ใช้

เมื่อสองทางแรกมีหลักฐานแล้ว จึงเพิ่มเด็กกับผู้ดูแล คนรู้กฎแต่ติดคำ/การฟัง และผู้เตรียมสอบทีละกลุ่ม แต่ละกลุ่มมีเนื้อหาและการทดลองของตน ไม่ยกผลผู้ใหญ่ไปปิดเกณฑ์เด็ก

### 10.2 ถ้อยคำและ accessibility

ตัวอย่าง: “ประเมินระดับ” → “ลองหาบทที่เหมาะกับฉัน”; “Submit” → “ตรวจคำตอบ”; “Incorrect” → “ลองดูคำนี้อีกครั้ง”; “Sync pending” → “บันทึกในเครื่องแล้ว รอส่งเมื่อมีเน็ต”; “model unavailable” → “ยังใช้การหาคำจากภาพไม่ได้ พิมพ์คำเองได้”. “บันทึกแล้ว” ต้องแสดงหลังบันทึกสำเร็จจริง

เป้าผลิตภัณฑ์: พื้นที่แตะหลักอย่างน้อย 48 logical pixels ใน Flutter และตรวจเครื่องจริง; HTML ตรวจ CSS pixels แยก. ตรวจข้อความขยาย 200%, contrast ข้อความปกติอย่างน้อย 4.5:1 ตามเกณฑ์ที่เกี่ยวข้อง, label/focus/screen reader, วรรณยุกต์ไม่ตัด, ไม่ใช้สี/เสียงอย่างเดียว และทางเลือกแทนลาก. WCAG 2.2 AA ขนาดเป้าหมายขั้นต่ำคือ 24×24 CSS pixels พร้อมข้อยกเว้น ไม่ใช่คำยืนยันว่าขนาดนั้นเหมาะกับผู้ใช้เรา. อ้างอิง [WCAG 2.2](https://www.w3.org/TR/WCAG22/).

ไม่เปิดเสียงซ้อน มีเล่น/หยุด/ซ้ำที่หาเจอ ไม่ autoplay ทุกหน้าโดยไม่เลือกก่อน ผู้ใช้ต้องควบคุมเสียงได้และไม่เผยเสียงส่วนตัวในที่สาธารณะ

### 10.3 หน้าจอและสถานะที่เพิ่มสำหรับสองแนวทาง

| จุดเข้า/หน้า | สิ่งที่ต้องกดดูได้ในร่างรอบใหม่ |
| --- | --- |
| วันนี้ → บทที่แนะนำ | อธิบายว่า “ลองเชื่อมเสียงกับตัวอักษร” หรือ “ลองฟังเรื่องสั้น” ตามข้อมูล เปลี่ยนเองได้ |
| ฝึก → เริ่มอ่านภาษาอังกฤษ | ขั้นที่เรียนแล้ว/ยังไม่ลอง โดยไม่แสดงว่าอายุเป็นระดับ; เลือกเริ่มมีคนพาหรือข้ามสิ่งที่รู้ |
| หน้าเสียงกับตัวอักษร | ปุ่ม “ฟังชื่อ” กับ “ฟังเสียง” แยกชัด สาธิตแล้วลองเอง ใช้ทีละเสียงไม่ซ้อน |
| หน้าผสม/แยกเสียง | แตะส่วนของคำ ฟังสาธิต/ลองเอง ปุ่มแทนลาก และบอกว่ากำลังอ่านหรือสะกด |
| ฝึก → ฟังและอ่านเรื่อง | เลือกเรื่อง/ความยาก/ฟังหรืออ่าน มีภาพและตัวช่วยไทยที่ควบคุมได้ ไม่เพิ่มแท็บหลัก |
| หน้าเรื่องและตัวช่วย | ฟัง/หยุด/ซ้ำ บทพูด/คำแปลเลือกเปิด แสดงงานค้างและตำแหน่งที่กลับต่อ |
| ผลบท/ทบทวน | แยก “จับคู่เสียงได้”, “ฝึกอ่านคำ”, “เข้าใจเรื่องโดยใช้ภาพช่วย” ไม่รวมเป็นอ่านคล่องหรือ CEFR |

ต้นแบบต้องมีไม่มีเสียง/โหลดสื่อไม่ได้/เปลี่ยนเจ้าของ/ออกขณะฟัง/กลับมาข้อเดิม. การปิดหน้าและเปลี่ยนคนต้องหยุดเสียงเก่าและไม่คืน draft/context ของคนเดิม เมื่อกด feedback ให้รักษาตำแหน่ง/จุดโฟกัสที่อ่านต่อได้. ข้อความ UI ใช้ไทย ส่วน Phonics/Comprehensible Input เป็นคำอธิบายของทีมและหน้าเรียนรู้เพิ่มเติมเท่านั้น

## 11. เนื้อหา แบบฝึก และคุณภาพคำตอบ

ต้นทุนสำคัญอยู่ที่เนื้อหา/สื่อ ไม่ใช่จำนวนหน้าจอ ไม่ใช้ book หรือข้อเดิมซ้ำเป็นตัวแทนคุณภาพทั้งโมดูล ก่อนประมาณวันเสร็จต้องรู้เป้าหมาย ขอบเขต จำนวนตัวอย่างที่พอทดสอบ และเวลาตรวจโดยผู้รู้ภาษา

โครงข้อมูลที่เสนอสำหรับออกแบบ ยังไม่ใช่ schema ที่นำเข้า production:

- ตัวตน: `id`, `revision`, `schemaVersion`, source/license, ผู้ตรวจ, publication, checksum และสื่ออ้างอิง
- การสอน: objective, prerequisites, ทักษะย่อย, เป้าหมายชีวิต, ศัพท์ที่ต้องรู้, เหตุผลความยาก, ความเหมาะสมเนื้อหา; CEFR mapping เป็น optional พร้อมที่มา
- บทสอน: คำสั่งไทย ตัวอย่างเฉลย เหตุผล ขั้นตัวช่วย และข้อให้ลองเองที่ต่างจากตัวอย่าง
- โจทย์: prompt/context, direction, response format, answer variants/rubric, เหตุผลตัวลวง, evidence span ของการอ่าน, replay/transcript/translation policy และสิ่งที่วัด
- สื่อ/การเข้าถึง: ภาพ/alt, เสียง/ผู้พูด/ความเร็ว/สำเนียงตามขอบเขต, transcript/caption, สิทธิ์, ขนาด, offline availability, วิธีตอบอื่นที่ไม่เปิดคำตอบโดยไม่บันทึก
- หลักฐาน: item family กันนับข้อซ้ำเสมือนข้อใหม่, assisted/independent policy, ข้อจำกัดเครื่องมือ, กฎรับคำตอบ/feedback

ขั้นผลิต: เป้าหมาย → แต่งโจทย์/สื่อมีสิทธิ์ → ตรวจภาษาและคำไทย → ตรวจการสอน/ตัวลวง/หลายคำตอบ → ตรวจวัย/เข้าถึง → ตรวจ manifest → ทดลองกลุ่มเป้าหมาย → publish revision. ต้องมีผู้ทบทวนภาษาที่เหมาะสม งาน AI ช่วยร่างยังเป็น draft จนผ่านตรวจ

เริ่มบทจำกัดจำนวนแต่ครบวงจรสอนและมีข้อใหม่สำหรับตรวจความเข้าใจ ไม่กำหนดจำนวนคำต่อบททุกวัยเท่ากันโดยไม่มีเหตุผล ไม่คิดว่า phonics อย่างเดียวครอบคลุมการอ่าน หรือใช้ศัพท์ยากจนบังทักษะที่วัด. เป้าหมายช่วงแรกคือเนื้อหาที่ใช้เรียนได้ครบหนึ่งเส้นทาง ไม่ใช่ฐานโจทย์จำนวนมากที่ยังไม่ตรวจ

ถ้าเฉลยกำกวม เปิดรายงานปัญหา ตรวจ/ระงับ revision จากการแจกใหม่ เก็บ attempt เดิมและวิธีแก้ผลกระทบที่ย้อนตรวจได้ ไม่เปลี่ยน answer key ย้อนหลังจนความหมายคะแนนเก่าถูกแก้เงียบ ๆ

### 11.1 ข้อมูลเนื้อหา/เสียงและหลักฐานที่ต้องขยาย

เป็นสัญญาระดับออกแบบให้ WP1 จับคู่กับ canonical models ก่อนเลือก migration ไม่เพิ่ม JSON ที่ไม่มีผู้รับผิดชอบตรวจความหมาย และไม่ส่งคำสอนทั่วไปเข้า scoring โดยฝืน mode เดิม

| ข้อมูล | อยู่กับอะไร | การใช้งาน/การตรวจ |
| --- | --- | --- |
| `instructionalTrack`, `objectiveId`, `sequenceRevision` | เนื้อหาบทที่มี revision | แยกเส้นทางสอนจาก interaction mode; Phonics/CI ไม่ใช่ชื่อ scoring engine ใหม่ |
| grapheme–phoneme mapping, สำเนียง, prerequisites, exception words | เนื้อหา Phonics ที่ตรวจแล้ว | ชุดรูปเสียงต้องครบสำหรับข้ออ่านเอง; ตัวเขียนหลายตัวแทนเสียงเดียวได้; ไม่ใช้ character count แทนจำนวนเสียง |
| `phonemeAudio`, `wordAudio`, `storyAudio` และข้อความกำกับ | media manifest | แยกเสียงย่อย/คำ/เรื่อง มี checksum, license, ผู้ตรวจคุณภาพ; ไม่มีเสียง Phonics ที่ผ่านตรวจให้ยังไม่พร้อม ไม่ fallback เป็นชื่ออักษร |
| ศัพท์/โครงสร้าง/ความยาว/ความเร็ว/บริบท | เรื่องฟัง/อ่าน | เก็บองค์ประกอบความยากแยก ไม่ใช้ป้าย A1 อย่างเดียวตัดสิน input เหมาะ |
| `supportPolicy`, `allowedClaim` | เป้าหมายและข้อแต่ละชนิด | กำหนดตัวช่วยที่เป็นส่วนของโจทย์ ตัวช่วยเพิ่มเติม และตัวช่วยที่เฉลยสิ่งที่วัด |
| `supportUsed`, `responseModality`, `evidenceKind` | attempt ภายใต้เจ้าของ | แยกแตะ/พิมพ์/เสียง, machine-validated/human-reviewed/self-reported และภาพ/เสียง/คำแปลที่ใช้ ไม่ยก self-report เป็นผลยืนยัน |
| `contentRevision`, `mediaRevision`, `ruleVersion`, operation identity | หลักฐาน/การ resume | กลับมาข้อเดิมบนชุดข้อมูลเดิม ไม่ตีความผลเก่าด้วยเสียง/เฉลยใหม่ ไม่เพิ่มซ้ำเมื่อ replay |

**ตัวช่วยไม่ทำให้ผลใช้ไม่ได้ทุกชนิดโดยอัตโนมัติ:** ภาพประกอบอาจเป็นเงื่อนไขที่ตั้งใจของการเข้าใจเรื่อง; ภาพเฉลยคำกลับทำให้ยังยืนยันการถอดรหัสคำไม่ได้. ฟังเสียงอ่านให้ฟังไม่เป็นหลักฐานอ่านตัวเขียนเอง และดูบทพูดไม่เป็นผล listening ล้วน ต้องสรุปตาม `allowedClaim` ของงานนั้น

ชุดแรกเป็นสื่อ local ที่ตรวจแล้ว ใช้เสียงบันทึกหรือเสียงสังเคราะห์ที่ตรวจคุณภาพ/สิทธิ์รายบท ไม่สมมติว่า TTS ทุกอุปกรณ์ออกเสียงย่อยได้ถูก และไม่ต้องซื้อ/เรียก provider เพื่อเปิดบทเรียน. สื่อขาด/เสียให้หยุดเฉพาะกิจกรรมที่พึ่งสื่อนั้น พร้อมเลือกบทอื่น ห้าม commit ว่าผู้เรียนตอบผิดเพราะไม่มีเสียง

## 12. AI ในแอป กล้อง และการวัดเสียง

ผู้ช่วยอยู่ใน LexiQuest ไม่มีขั้นเชื่อม ChatGPT/MCP สำหรับผู้เรียน หน้าที่คืออธิบายคำ/บท ยกตัวอย่าง ช่วยวางขั้นคิด และชี้จุดแก้หลังผู้เรียนลองเอง คำตอบหรืองานที่ AI แก้ต้องไม่กลายเป็นหลักฐานว่าผู้เรียนทำได้

เริ่มช่วยเฉพาะบทเรียน/คลังตรวจแล้ว มีคำช่วยพื้นฐานไม่เรียก AI เมื่อปิด/ไม่มีเน็ต/หมดโควต้า แชตเปิดกว้างเป็นระยะหลังเมื่อมีนโยบายและผลตรวจ ไม่จำเป็นต่อบทแรก

| เรื่อง | ข้อกำหนดก่อนเปิดจริง |
| --- | --- |
| ความถูกต้อง | ระบุบท/revision ที่อธิบาย ยอมรับความไม่แน่ใจ แจ้งผิดได้ ไม่มีคะแนนทางการจากคำตอบโมเดล |
| บริบท | ส่งเฉพาะเจ้าของและงานปัจจุบันเท่าที่จำเป็น ไม่ส่งข้อมูลไม่มี owner; คำตอบช้าหลังออก/เปลี่ยนคนไม่ไปตอบอีกคน |
| เด็ก/วัยไม่ทราบ | ใช้คำช่วยตรวจแล้ว ตรวจนโยบายอายุ provider ความยินยอม การเก็บข้อมูลและกำกับก่อน live; ไม่เดากฎหมายจากช่วงวัย UX |
| ข้อมูลส่วนบุคคล | ไม่เก็บ/ส่งเสียง ภาพ ใบหน้า ตำแหน่ง แชตเกินจำเป็นเป็นค่าเริ่มต้น ระบุ retention/delete/export และขอบเขตผู้ดูแล |
| ค่าใช้จ่าย | provider/billing ยังไม่เลือก; งบและขีดจำกัดก่อน network ไม่มี paid fallback อัตโนมัติ ไม่มีซื้อ/เปิดบริการในงานนี้ |
| กล้อง | คำจากโมเดลเป็นข้อเสนอ ผู้เรียนยืนยันก่อนเพิ่ม พิมพ์เองได้ ภาพไม่เป็นคะแนนเรียน |
| เสียงพูด | ASR ผิดอาจมาจากเครื่อง/สภาพแวดล้อม/โมเดล retry/ฟังตนเอง/เรียนทางอื่นได้ ไม่ตัดสินจาก transcript อย่างเดียว |

อิง [UNICEF AI and children 3.0](https://www.unicef.org/innocenti/reports/policy-guidance-ai-children). ก่อนใช้จริงตรวจเงื่อนไข provider และกฎหมายที่เกี่ยวข้องในขณะนั้น เป็น prerequisite ของความสามารถนั้น งานพื้นฐานทำต่อได้

Jev/router ช่วยทีมพัฒนาเป็นคนละส่วนกับการตัดระดับหรือให้คะแนนผู้เรียน แผนนี้ไม่เปิด/เพิ่ม provider เพื่อผลิตหลักฐานการเรียน

ทิศข้อมูล: ผู้เรียนตอบ → domain validate → commit ภายใต้ owner/session/content revision → หลักฐานอ่านกลับได้ → projection ความก้าวหน้า/คำแนะนำ/รางวัล. UI และ AI อ่านตามสิทธิ์ ไม่เขียนคะแนนเอง คะแนนกิจกรรม/รางวัลยังใช้ policy เดิมที่เกี่ยวข้อง การฝึกมีตัวช่วยกับหลักฐานทำเองต้องแยก แม้บางกิจกรรมยังมีรางวัลความพยายามตามกติกาเดิม

Migration: เพิ่มเท่าที่จำเป็น; ข้อมูลเก่าขาด flags/revision ให้ถือว่าไม่ทราบเงื่อนไข ไม่เติม independent เอง. แสดงประวัติเก่าได้โดยไม่อ้างเทียบระดับใหม่ ใช้ feature flag กับ UX ที่ยังไม่พร้อมโดยไม่ล้างฐาน

ข้อจำกัดที่ตรวจพบสำหรับฉบับ 3: `RecordAnswerCandidate` ยังอ้าง `wordId`/`promptMode`/`isCorrect` ขณะที่ `SkillEvidence` มี key/label/sampleSize/accuracy. ต้องตรวจสัญญา evidence ที่เชื่อมอยู่ก่อนรองรับเป้าหมายระดับรูปเสียงหรือเรื่องหลายคำ ห้ามใช้ wordId สมมติแทนเรื่อง หรือเปลี่ยนแค่ label แล้วถือว่าได้หลักฐานทักษะใหม่. ถ้าจำเป็นต้องขยายชนิดเป้าหมาย/คำตอบ ให้ทำผ่าน domain/repository เดิมแบบ versioned พร้อม mapping legacy และ targeted migration tests; ไม่ฝืนทุกงานให้เป็นผลถูก/ผิดของคำศัพท์หนึ่งคำ

ข้อกำหนดเพิ่มฉบับ 4: การเปิดบท/คำแนะนำ/หลักฐานต้องแยก responsibility แม้อ่านข้อมูลร่วมกันได้ การกด “บทต่อไป” ไม่เรียก score commit และไม่มีเงื่อนไขว่า microphone permission หรือ verified oral evidence ต้องพร้อมก่อนเปิดบทเรียนทั่วไป. Schema ที่จำเป็นค่อยทำใน WP4 หลังทดลอง ไม่ให้การออกแบบ adaptive profile เต็มระบบขวาง WP1–WP3

ก่อนแตะข้อมูลจริงมี backup/restore ที่ตรวจได้ รวม SQLite/WAL/SHM ตามสถานะแอป/นโยบายเดิม ใช้สำเนาทดสอบก่อน ถ้าเวอร์ชันเก่าอ่านรูปแบบใหม่ไม่ได้ ต้องระบุ forward-only migration และวิธีกู้ที่ไม่ทิ้งงานหลัง backup; rollback UI ไม่เท่ากับ downgrade schema ปลอดภัย ปิดฟีเจอร์แล้วต้องยังส่งออก/กู้ร่างผู้เรียนได้

## 14. การทดลองและกติกาตัดสินใจก่อนขยาย

แยก **การใช้งาน**, **สัญญาณการเรียนตามเป้าหมายแคบ**, และ **ความถูกต้องของข้อมูล/ระบบ**. ไม่ใช้ค่าเฉลี่ยรวมปิดปัญหาของกลุ่มใด และไม่เรียกการตรวจเอกสารหรือปุ่มกดว่าเป็นผลเรียน

### 14.1 ลำดับทดลองและผู้เข้าร่วม

1. WP1 มีสื่อ/เนื้อหา/rubric ขนาดเล็กที่ตรวจแล้วก่อนรอบเรียนจริง; wireframe ที่ยังใช้ placeholder ตรวจได้เฉพาะ navigation
2. WP2 ทำต้นแบบสองเส้นทาง ไม่รอครบ W01–W14. ผู้ตรวจลองเสียง/คำสั่ง/ข้อใหม่บนเครื่องที่ใช้ทดลองก่อน
3. WP3 รอบ A รับผู้ใหญ่กลุ่ม A และ B กลุ่มละ 3–5 คนเพื่อค้นปัญหาเชิงคุณภาพ แยกผลแต่ละกลุ่มและความต้องการช่วย ไม่ถือจำนวนนี้แทนประชากร
4. ตรวจเริ่มเอง/รู้ว่าจะทำอะไร/ขอช่วย/ข้าม/พัก–กลับ/อ่านผล โดยผู้ดำเนินการไม่ชี้ปุ่ม ถ้าจำเป็นต้องช่วยให้บันทึก ไม่ซ่อนความช่วยเหลือจากรายงาน
5. ให้ทดลองบทด้วยเงื่อนไขที่ freeze เก็บก่อน–หลังด้วยงานเทียบเคียง และติดตามข้อใหม่ภายหลังตาม 14.2 เฉพาะเมื่อเงื่อนไขผู้เข้าร่วมพร้อม
6. แก้สาเหตุที่พบแล้วตรวจรอบ B กับผู้ใช้ใหม่อย่างน้อยกลุ่มที่ได้รับผล; เก็บ source/content/rule version ใหม่ ผลคนเคยใช้มี learning effect จึงไม่รวมเหมือนผู้ใช้ใหม่

รายงาน `สำเร็จเอง n/N`, ช่วย n/N, skipped/invalid, ปัญหาเริ่ม/กลับ/เข้าใจคำสั่ง, เหตุเลิก และเวลาที่ใช้จริง. เวลาเป็นข้อมูลประกอบ ไม่ตัดสินว่าผู้ช้าไม่มีความสามารถ ไม่เก็บเสียง/ข้อมูลส่วนตัวเกินจำเป็นเพื่อให้ได้ตัวเลข

เด็ก 6–8 พร้อมผู้ดูแล, 9–12, วัยรุ่น และโปรไฟล์อื่นเข้ารอบขยายทีละกลุ่มหลังฐานสองทางนิ่ง ต้องตรวจเงื่อนไขที่เกี่ยวข้องก่อนรอบเด็ก ไม่ยกผลผู้ใหญ่แทนหลักฐานเด็ก. ผู้ใช้ที่มีข้อจำกัดเฉพาะยังต้องมีหลักฐานของตนก่อนอ้างรองรับ ไม่บังคับรอบแรกครอบคลุมผลคูณทุกวัย×ทุกทักษะ×ทุกอุปกรณ์

| เชื่อมรูป–เสียง | จับคู่รูปกับเสียงบนข้อที่ลำดับ/คำต่างจากช่วงสอน | ถูกตาม mapping / ผิด / มีตัวช่วย / สื่อเสียหรือไม่ได้ลอง; ไม่ใช้ชื่อตัวอักษรแทนเสียง |
| เริ่มอ่านคำ | คำใหม่ประกอบด้วยรูปเสียงที่สอนแล้ว ไม่มีภาพหรือเสียงก่อนตอบเฉลยคำ | ผู้ตรวจฟังตรงหน้าได้โดยไม่ต้องเก็บไฟล์เสียง; อ่านได้ / ต้องให้คำใบ้หรือแก้เสียง / ยังทำไม่ได้ / ไม่ได้ตรวจ. รับการออกเสียงที่สื่อคำได้ตาม rubric ไม่บังคับสำเนียงเหมือนต้นแบบ |
| เข้าใจเรื่อง | เรื่อง/รายละเอียดใหม่เทียบเป้าหมายเดิม ตัวเลือกต่างเหตุการณ์ ไม่ใช้ภาพคำตอบชัดเจนจนไม่ต้องรับภาษา | ระบุสารสำคัญได้ / ได้เมื่อช่วย / ยังไม่ได้ / ไม่ได้ตรวจ. ตอบไทยหรือเลือกภาพได้; ไม่ปนความสามารถเขียนอังกฤษ |
| จำภายหลัง | งานใหม่จากรูปเสียง/ความหมายที่ฝึกและไม่ใช่ข้อที่เพิ่งเฉลย | เก็บวันที่ ตัวช่วย การฝึกอื่นระหว่างรอบ และผลตาม rubric เดิม |

WP1 ระบุรายการข้อสำหรับก่อนเรียน หลังเรียน และติดตามแยก พร้อมเหตุผลว่าเทียบเป้าหมายกันได้. ไม่ให้ผู้ตรวจเปลี่ยนความหมาย “ผ่าน” หลังเห็นคำตอบ และไม่เพิ่มรอบฝึกเฉพาะคนจนผ่านแล้วรายงานเสมือนใช้เงื่อนไขเดียวกัน

ช่วงติดตาม 3–7 วันเป็นข้อเสนอทดลองดูการจำเบื้องต้น ไม่ใช่ค่ามาตรฐานหรือหลักฐานจำระยะยาว ผู้ขาดนัดยังอยู่ในจำนวนผู้เข้าร่วมและแสดง missing ไม่ลบทิ้ง. ผู้ทำได้ก่อนเรียนอยู่แล้วให้รายงาน ceiling/พื้นฐานเดิม ไม่อ้างว่าเกิดการเรียนจากแอป

เสียงอ่านที่ไม่ได้สังเกตหรือไม่ให้บันทึก **ไม่ทำให้หยุดเรียน**. ถ้ายินยอมให้ผู้ตรวจฟังตรงหน้า ใช้ rubric โดยไม่เก็บเสียงได้; ถ้าไม่ต้องการหรือไม่มีผู้ตรวจ ให้คงผล unobserved และประเมินเฉพาะกิจกรรมที่ตรวจได้. คะแนน recognition ไม่ถูกยกระดับเป็น oral decoding

ผล pilot อธิบายได้เฉพาะทักษะ/กลุ่ม/เงื่อนไขที่ทดลอง ไม่พิสูจน์เหตุ–ผลหรือความเหนือกว่าวิธีอื่น. งานวิจัยเพื่อกล่าวอ้างประสิทธิผลต้องมีแผนศึกษา/ขนาดตัวอย่าง/กลุ่มเปรียบเทียบและการอนุมัติที่เกี่ยวข้องเป็นงานแยก ไม่มี research activation หรือการส่งข้อมูลวิจัยในงานนี้

### 14.3 การตัดสินใจหลังทดลองและเงื่อนไขที่ต้องแก้

กติกาด้านล่างเป็น **เกณฑ์จัดงานรอบทดลอง** ไม่ใช่ค่าความสามารถมาตรฐานหรือเกณฑ์รับรองประชากร ต้องประกาศก่อนรอบและรายงานผู้ไม่สำเร็จด้วย ไม่เลือกเฉพาะตัวอย่างที่ดี

| สถานะ | เงื่อนไข | การกระทำ |
| --- | --- | --- |
| แก้ก่อนขยาย | มีข้อผิดเนื้อหา/เสียงหนึ่งจุดที่สอนผิด, ข้อมูลหาย/ข้ามเจ้าของ, เข้า/กลับบทไม่ได้ หรือมีความหมายผลลวง | แก้และตรวจใหม่ตรงสาเหตุ ไม่เปิด increment นั้นต่อด้วยป้าย PASS |
| แก้บท/คำสั่งก่อนขยาย | ตั้งแต่สองคนในกลุ่มเดียวสะดุดที่คำสั่ง/แนวคิดเดียวกัน หรือทำข้อเดิมได้แต่ข้อใหม่ไม่ได้เป็นรูปแบบซ้ำ | แยก UI/เนื้อหา/วิธีวัด เปลี่ยนทีละปัจจัย แล้วตรวจกลุ่มนั้นใหม่ |
| รอหลักฐาน | ผู้ตรวจ/สื่อ/ผู้ร่วม/การติดตามยังไม่พร้อม หรือมีแต่การตอบที่ไม่ได้วัดเป้าหมาย | บันทึก pending ของผลนั้น ทำงานออกแบบ/เทคนิคที่ไม่พึ่งผลต่อได้ ไม่ลดเกณฑ์ |
| ทดลอง increment ถัดไปได้ | สื่อ/rubric ผ่าน; มีผู้ร่วมอย่างน้อยสามคนต่อกลุ่ม; ไม่มีปัญหาสำคัญค้าง; ในแต่ละกลุ่มมีหลักฐานงานใหม่ตามเป้าหมายและการติดตามจากอย่างน้อยสองคน พร้อมรายงานทุกคนที่ไม่สำเร็จ/ขาดนัดและขอบเขตที่ยังไม่รองรับ | ขยายทีละเนื้อหาหรือทีละกลุ่ม ไม่ประกาศผลดีสำหรับทุกคนหรือเปิดทั้งระบบ |
| จำกัดเฉพาะส่วนที่มีหลักฐาน | Phonics หรือเรื่องรับสารให้ผลต่างกัน หรือบางกลุ่มยังไม่มีหลักฐาน | ขยายได้เฉพาะส่วนที่เข้าเงื่อนไขข้างบน อีกส่วนคงแก้/รอ ห้ามใช้ผลอีกทักษะปิดช่องว่าง |

ขั้นต่ำสามคน/หลักฐานสองคนเป็นขอบเขตปฏิบัติของ pilot นี้เพื่อหลีกเลี่ยงการตัดสินจากตัวอย่างเดียว **ไม่ใช่ threshold ทางวิทยาศาสตร์**. ต้องแสดงผล n/N ทุกคนและเหตุที่ยังไม่สำเร็จ ถ้ามีรูปแบบปัญหาซ้ำเข้าเงื่อนไข “แก้ก่อนขยาย” ให้ใช้เงื่อนไขนั้นก่อน แม้มีตัวอย่างสำเร็จครบขั้นต่ำ

แต่ละ track×กลุ่มตัดสินใจแยกกัน โดยมีเป้าหมายที่ระบุไว้ก่อนเริ่ม ถ้าคำถามหลักของ track ยังไม่มีข้อมูล เช่น มีแต่จับคู่เสียงเมื่อจะดูอ่านคำ ให้คง pending. หลังสองรอบแก้ที่ยังติดปัญหาเดิม หยุดเพิ่ม scope ของส่วนนั้นและทบทวนสมมติฐาน/วิธีสอนหรือเป้าหมาย ห้ามทำกิจกรรมเดิมซ้ำไม่สิ้นสุดหรือผ่อน rubric เพื่อปิดงาน

### 14.4 เกณฑ์เพิ่มเฉพาะ Phonics และ Comprehensible Input

รายการนี้เป็นหัวข้อเพิ่มของทะเบียนใหม่ ไม่ใช่การเปิด 215 ข้อเดิม และยังไม่มีแถวใดถูกนับว่า implementation ผ่านจากการเขียนแผน

| รหัส | สถานการณ์และผลที่ต้องยืนยัน | ชั้นหลักฐาน |
| --- | --- | --- |
| PH01 | ปุ่มฟังชื่อ/เสียงให้เสียงคนละหน้าที่ถูกต้อง ไม่มีอักษร/เสียงที่ยังไม่ได้สอนหลุดเข้าโจทย์อ่านเองโดยไม่ระบุ | ตรวจเนื้อหา/สื่อ + native audio |
| PH02 | ทำตัวอย่างได้แล้วลองคำใหม่จากรูปเสียงที่เรียน โดยไม่ให้ภาพ/เสียงก่อนตอบเฉลยสิ่งที่วัด | domain + งานอ่านที่ผู้ตรวจประเมินได้ |
| PH03 | เลือก tile, พิมพ์เอง, copy และอ่านออกเสียงมี evidence scope ต่างกัน; ปิดไมค์ยังเรียนได้แต่ไม่เกิดผลอ่านออกเสียงปลอม | domain/storage + native |
| PH04 | คำข้อยกเว้น/หลายเสียง/สำเนียงมีเฉลยและสื่อที่ถูกต้อง; ผู้ใหญ่ไม่ถูกส่งกลับท่อง A–Z ด้วยอายุ | content review + UX |
| CI01 | ผู้เรียนอธิบาย/เลือกสารของเรื่องใหม่ที่เทียบเคียงได้ ไม่ตอบจากภาพเฉลยหรือคำเดิมที่จำอย่างเดียว | UX + งานความเข้าใจใหม่ตามเป้าหมาย |
| CI02 | เปิดภาพ/ซ้ำ/ช้า/คำไทย/บทพูดแล้วเก็บเงื่อนไขตรง; สรุปไม่ยก assisted หรือ reading เป็น listening ล้วน | domain/storage + native |
| CI03 | ปรับความยากเปลี่ยนเนื้อหา/เงื่อนไขจริง; ฟังเก่งอ่านอ่อนมีคำแนะนำแยก ไม่บังคับทางเดียว | rule tests + prototype/native UX |
| PC01 | เปิดเรื่องได้ก่อนอ่าน A–Z ครบ; ข้าม Phonics/ปฏิเสธไมค์/ไม่มีผู้ตรวจเสียงแล้วยังเลือกบทต่อได้ บริบทเหมาะกับกลุ่มที่กำลังตรวจ | routing + UX ของกลุ่มใน scope; เด็กตรวจในรอบขยาย |
| PC02 | ดูบท/ฟังเสียง/ดูเฉลยอย่างเดียวไม่เพิ่ม mastery; double tap/resume ไม่สร้างผลซ้ำ | domain + persistence หลัง restart |
| PC03 | เสียงขาด/เสีย/no permission/offline ไม่เป็นคำตอบผิด; พักกลับตรงขั้นและ revision; เปลี่ยน owner ไม่เล่นเสียงหรือคืนงานเก่า | integration/storage + native |
| PC04 | ขยายตัวหนังสือ/ใช้ screen reader/แตะแทนลากได้; ถ้าตัวช่วยอ่านโจทย์เฉลยทักษะนั้น ต้องจำกัดคำกล่าวอ้างและให้ทางเรียนต่อ | accessibility จริง + evidence policy |

การทดลองต้องมีงานแยกอ่านคำกับเข้าใจเรื่อง และรายงานตามวัย/ความพร้อมเดิม. ไม่มีไมค์หรือไม่มีผู้ตรวจเสียงให้คงผลเฉพาะ recognition/งานที่ตรวจได้ ไม่แทนด้วย ASR PASS. ถ้างานเลือกตอบมีโอกาสเดาถูก ให้ใช้หลายโจทย์ใหม่/งานที่ต่างกันก่อนสรุป ไม่ตั้ง “ผ่าน Phonics” จากข้อเดียว. กติกาบทและ rubric ต้อง pin ใน WP1 ตาม 5.4/14.2 ก่อนทดสอบ ไม่เปลี่ยนเกณฑ์ย้อนหลังเพื่อให้ผ่าน

### 14.5 หลักฐานเทคนิคตามชั้นที่เปลี่ยน

- Domain: access/recommendation/evidence แยกกัน; rule ทดลอง, ตัวช่วย, skip/invalid/noEvidence, คำตอบหลายรูป และกรณีไม่มีไมค์ยังเรียนต่อได้
- Storage: restart/draft/duplicate/owner switch/queue และ migration เมื่อมีจริง; ไม่ให้เลือกบทต่อสร้าง mastery หรือ XP เอง
- Native: เสียงย่อย/คำ/เรื่องจริง, back/background, offline/permission, ตัวหนังสือ/keyboard/screen reader และการหยุดเสียงเมื่อเปลี่ยนคน
- สื่อ/ผลส่งออก: content/media revision ตรงกับผล; เปิด artifact เทียบข้อมูล; ไม่ใช้สื่อร่างรับรอง production audio
- AI/camera/sync ที่อยู่นอกหน่วยแรกยังไม่ถูกนับว่าผ่าน; ตรวจเมื่อ increment นั้นเข้าขอบเขต

Host/Node ผ่านไม่แทน native; native ผ่านไม่แทนผู้เรียนเข้าใจ; UI สำเร็จไม่แทน persistence; ผลตัวอย่างเดียวไม่แทนหลักฐานของกลุ่ม

## 15. แผนดำเนินงานฉบับ 5: เสาหลัก โมดูล สปรินต์ และการส่งต่อ

writer เดียว ทำทีละ package ไม่มี subagent/ผู้พัฒนาพร้อมกัน. ผู้ใช้อนุมัติให้สร้างแชตใหม่ต่อสปรินต์และแชตย่อยแบบเรียงลำดับเพื่อควบคุม context; ข้อนี้แทนข้อห้ามเปิด task ใหม่ของฉบับ 4 และกติกา dispatch เก่าสำหรับงาน UX นี้. ตาราง WP คงไว้เป็น dependency ของผลิตภัณฑ์ ไม่ใช่จำนวนสปรินต์หรือคำสั่งสร้างแชต. WP1 ต้องผ่านก่อนทดลองการเรียนด้วย WP2; wireframe/navigation ที่ไม่อ้างผลเรียนทำล่วงหน้าได้. ผล WP3 กำหนดส่วนที่จะลง Flutter. เก็บ 14 workflow/14 modes เป็นความครอบคลุมอนาคต

| งาน | ผลส่งมอบ | ขึ้นกับ | เกณฑ์จบงาน |
| --- | --- | --- | --- |
| WP0 แผนฉบับนี้ | ขอบเขตสองกลุ่ม กฎเลือกบท/รายงานผล เกณฑ์ทดลอง ลำดับและข้อจำกัด | การวิเคราะห์ห้าประเด็น | เอกสารสอดคล้องกัน ยังไม่อ้างว่าการเรียนผ่าน |
| WP1 ชุดบทเรียนทดลองที่ตรวจแล้ว | pilot brief, หนึ่งลำดับ Phonics, หนึ่งเรื่องรับสาร, ชุดตรวจใหม่, เสียง/ภาพ/สิทธิ์, rubric/support policy และชื่อผู้ตรวจจริง | WP0 | สื่อและคำสอนถูกต้องสำหรับการทดลอง; freeze revision/rule/ข้อวัด; ไม่มี placeholder ถูกนับเป็นสื่อผ่าน |
| WP2 ต้นแบบสองทาง | เริ่ม→สาธิต→ลอง/ข้าม→ช่วย→พัก/กลับ→ผล ทั้งแบบไม่มีไมค์และเลือกคนละทาง | WP1 สำหรับการทดลองเรียนจริง | เดินจบและใช้สื่อที่ตรวจแล้ว; ไม่มีการล็อกบทด้วยผลเสียง; ปัญหา draft/scroll/เนื้อหาระดับที่กระทบสองทางแก้แล้ว |
| WP3 ทดลองและตัดสินใจ | ผลแยกกลุ่ม A/B, ก่อน–หลัง/ติดตามตามเป้าหมาย, ปัญหา/การแก้/รอบตรวจใหม่ และสถานะ 14.3 | WP2 และผู้ร่วมตามเงื่อนไข | ได้สถานะที่มีหลักฐาน ไม่ใช่บังคับต้อง PASS; ขยายเฉพาะ track×กลุ่มที่เข้าเกณฑ์ |

### 15.5 สปรินต์แรกและเกณฑ์เลือกรอบต่อไป

คำสั่งต่อเนื่องล่าสุด 2026-09-24: ทำงานพร้อมใน backlog ทั้งแผนต่ออัตโนมัติ ทีละ package/สปรินต์/แชตใหม่ตามบริบท ไม่หยุดเพียงร่าง S01-C เสร็จ. UX ภาษาไทย/accessibility/สัญญาข้อมูล/ต้นแบบที่ไม่พึ่งผลเรียนทำต่อได้; S01-D และ instructional Flutter ยังต้องผ่าน prerequisite เดิม. ใช้ Jev ช่วยเสนอ model/effort สำหรับแชตถัดไปจาก pool ที่อนุญาตและ executor schema/quota สด (Astra/Sol รองรับ ultra ตามเครื่องมือปัจจุบัน; Luna ไม่รองรับ; ตรวจใหม่ตอน dispatch). ถ้า live Jev ไม่พร้อมใช้โมเดลปัจจุบันเป็น deterministic fallback โดยบอกตรง ๆ. Standard/default, single writer, วงเงิน USD5 เดิมและ guarded reservation ยังบังคับ ไม่เปิด Fast/paid fallback หรือรีเซ็ต ledger.

ลำดับเลือกรอบใหม่: (1) owner/data/เริ่มหรือเรียนต่อไม่ได้แก้ก่อน (2) สื่อ/ผู้ร่วมพร้อมแต่ยังไม่มี trial evidence ให้ทดลอง/แก้สองทาง (3) ส่วนที่ผ่านเกณฑ์ข้อ 14.3 ลง Flutter เฉพาะส่วนนั้นแล้ว native/persistence (4) รอ prerequisite ให้เลือก independent navigation/ไทย/a11y/interface ที่พร้อม (5) ฐานมั่นคงแล้วขยายศัพท์/SRS → ประโยค/เขียน → อ่าน/ฟัง/พูด/ภารกิจตามหลักฐาน (6) กล้อง/AI/สอบเข้าเมื่อ prerequisite และเหตุผลผู้ใช้พร้อม (7) ขยายวัยทีละกลุ่มจากหน่วยมั่นคง ไม่กำหนดวัยละหนึ่ง sprint

งานรอ dependency ไม่เปิดเป็นแชตว่างเพื่อรอ; เลือกงานพร้อมใน scope ที่ได้รับอนุญาต หากไม่มีงานอิสระที่มีประโยชน์เหลือให้รายงาน prerequisite จริง ไม่สร้างงานเพิ่มเพื่อให้ดูว่ากำลังทำ. หลังสองรอบแก้ที่ยังติดรูปแบบเดิม ใช้ข้อ 14.3 ทบทวนสมมติฐานก่อนขยาย

จุดส่งมอบ: prototype พร้อมตรวจใช้งาน → native หน่วยแรกที่รักษาข้อมูล → ชุดทักษะตามเนื้อหา/หลักฐาน → วัย/ฟีเจอร์เสริมที่ผ่าน → frozen release candidate. ไม่มีจุดใดใช้ชื่อ release เพื่อข้ามผลที่ยังไม่ตรวจ

### 15.6 Agile + SDLC ภายในทุกสปรินต์

วงจรต่อ work item: ปัญหาผู้ใช้ → เกณฑ์รับ → ตรวจของเดิม → ออกแบบ → พัฒนาส่วนที่ใช้งานจบได้ → ตรวจตามชั้น → เดโม → แก้/ทบทวน. ไม่รอปลายสปรินต์จึงเริ่มตรวจ

- ก่อนรอบ: ระบุ goal หลักหนึ่งข้อ งานรับเข้า งานสำรองที่ไม่ติด dependency ผู้รับผิดชอบและเกณฑ์รับ เลือกปริมาณจากงานจริงที่เทียบเคียงได้ ไม่เหมาทุกโมดูลเท่ากัน
- ระหว่างรอบ: WIP หนึ่งงานหลัก บันทึกผลล่าสุด/อุปสรรค/ขั้นถัดไปสั้น ๆ; เดโมส่วนที่ตรวจได้ระหว่างสัปดาห์เมื่อมีงานใหม่. ผู้ใช้อนุมัติ heartbeat เดิม `lexiquest-r3` ที่ controller ทุก 30 นาทีแล้ว ไม่สร้างซ้ำและไม่ต้องรอรอบเพื่อทำต่อ; ไม่เปิดบริการเพิ่มเติมโดยปริยาย
- จบรอบ: แยก done/partial/failed/external pending ตามหลักฐาน ทบทวนทั้งผลิตภัณฑ์และวิธีทำงาน บันทึกเวลาทำงาน/เวลารอแยกกันแล้วปรับ forecast
- Ready: เป้าหมายและวิธีตรวจชัด dependency พร้อมตามชนิดงาน มีสื่อ/ผู้ตรวจเมื่อจำเป็น งาน schema มี migration/recovery
- Done: behavior ตรงเกณฑ์ ตรวจชั้นที่ต้องใช้ ไม่มี confirmed defect ค้างในส่วนที่ประกาศเสร็จ มี source/content fingerprint และ artifact; learning outcome ที่ยังรอไม่เปลี่ยนเป็น PASS จาก code completion
- ติดตามความคืบหน้าด้วยเส้นทางที่ใช้ได้/โมดูลใน scope ที่ผ่าน/defect/เวลา ไม่ใช้จำนวนหน้า จำนวนแชต 215 ข้อ หรือเป้าหมายจำนวนสปรินต์เป็นเปอร์เซ็นต์สำเร็จ

### 15.7 หนึ่งสปรินต์ต่อแชตและการส่ง source

ใช้ `docs/development/ux-delivery/` เป็นที่เก็บสถานะการทำงานของแผนนี้ และใช้เอกสารแผนนี้เป็น requirement authority. State เก่าของ Ari/Jev/G/B bundles และทะเบียน 215 เป็นประวัติ ไม่เริ่ม dispatch จากไฟล์เหล่านั้น. เลือก saved project LexiQuest `e0d28f74-0d26-40bc-b126-4cfebe4ff7a0` หลังตรวจ list_projects

ชื่อเริ่ม: `LexiQuest · S01 · ทางเริ่มเรียน`. แยกเป็น S01-B/C เมื่อถึงขอบเขตงานที่มี checkpoint หรือ context หนาแน่นจนต้องอ่านซ้ำมาก; หนึ่งแชตมีเป้าหมายหลักหนึ่งเรื่อง ไม่แยกตามทุกไฟล์/คำสั่ง ไม่ใช้เปอร์เซ็นต์ context ที่เครื่องมือไม่รายงาน. สร้าง fresh chat พร้อมข้อความสั้นและพาธ ไม่ fork ประวัติทั้งหมด ไม่เปิดหลายแชตลงมือพร้อมกัน

Handoff ต้องมี goal/current item/next action, project/worktree/branch/HEAD, source fingerprint และ dirty manifest, acceptance และ artifact ตามชั้น, RED/defect/pending, decision notes, writer/revision และ successor ID ถ้ามี. แยก checkpoint source จาก accepted source; end of chat ไม่ใช่ end of sprint หรือ PASS

การส่งต่อ: หยุดแก้และรอคำสั่งเขียนจบ → snapshot/hash dirty และ untracked ที่ต้องใช้โดยไม่ reset/clean → บันทึก immutable handoff → ปล่อย application writer → สร้าง successor หนึ่งรายการ → successor ตรวจ source จริงก่อน claim writer. ถ้า tool เริ่มจาก default checkout ต้องรับ source ตาม manifest อย่างปลอดภัยก่อนเขียน; ไม่ถือชื่อ branch อย่างเดียวเป็นหลักฐาน. หาก SHA/manifest ไม่ตรงให้วินิจฉัยการรับ source ไม่ overlay งานอื่นแบบเดา

ตรวจ successor ID ก่อนสร้างทุกครั้ง; setup pending ให้ติดตามรายการเดิม ไม่สร้างซ้ำ. ผู้ส่งหยุดเปลี่ยน application source หลัง release; receipt การสร้างแชตเก็บแยกจาก snapshot. ผู้รับส่งต่อ unresolved scope ทั้งหมดโดยไม่ซ่อน RED และอาจเป็นผู้ dispatch successor ลำดับถัดไปภายใต้อำนาจอนุมัตินี้. คำสั่งหยุดใหม่ของผู้ใช้มีผลสูงสุด

การเก็บข้อกำหนด/แผน/ผลตรวจ/สถานะใน repository เป็น durable project memory ตาม [OpenAI Docs](https://developers.openai.com/blog/run-long-horizon-tasks-with-codex); การแยกแชตเป็นวิธีควบคุมบริบทของงาน ไม่รับรองการประหยัด token เป็นเปอร์เซ็นต์

### 15.8 สัญญาระบบและการตรวจรับที่ต้องคง

ใช้ข้อ 11.1/13 ขยายสัญญาแบบ versioned ผ่าน domain/repository เดิม เป้าหมายทักษะแยก interaction ห้าม fake wordId เก็บ owner/session/content/media/support/modality/operation identity แยก wrong/skipped/unobserved/invalid เก่า unknown ไม่เติมหลักฐานเอง. Access/recommendation/evidence และ canonical content/scoring/SRS/reward authorities แยกความรับผิดชอบตามเดิม

ผลรับงานแยกสามแกน: ระบบ (บันทึกจริง/ไม่ซ้ำ/ไม่ข้ามเจ้าของ/กู้ได้), การใช้งาน (เริ่มเอง/เข้าใจ/ช่วย/พักกลับ/อ่านผล พร้อมบันทึกผู้ช่วย), การเรียน (งานใหม่ตาม construct และเงื่อนไขจริง). Host ไม่แทน native/provider/user และผลคน/ทักษะอื่นไม่ปิดช่องว่าง

ตรวจ correct/wrong/empty/variants/support/exit-resume/double tap/restart/owner/offline/media failure/permission/late AI ตาม scope. Defect ทำซ้ำ→RED ที่เกี่ยวข้อง→ต้นเหตุ→แก้→targeted→native/user retest ที่จำเป็น. ใช้ `tool/cli/verify-scope.ps1` ตามข้อ 15.2 และ reuse passed evidence เมื่อ fingerprint เดิม

ก่อนแตะข้อมูลอุปกรณ์จริงสำรอง/ตรวจ restore SQLite/main/WAL/SHM ตามสถานะแอป แยกแอปทดสอบจากข้อมูลผู้ใช้. Migration ตรวจ upgrade และการกู้ที่ไม่ทิ้งงานใหม่. ไม่รัน heavy Flutter/backend/Android/GPU พร้อมกัน ไม่แก้ source ระหว่าง gate. Freeze release scope แล้ว regression/native/endurance 180 นาทีจริงและกระทบยอด; full verifier เฉพาะ frozen SHA

ไม่ซื้อบริการ ไม่เปิด paid fallback/deploy/research activation; Jev/router เป็นเครื่องมือทีมพัฒนา ไม่ตัดสินคะแนนผู้เรียน. ก่อนเริ่มจริงบันทึกแผน/ตรวจความสอดคล้อง/เตรียม state+handoff แล้วเปิด S01 ตามอำนาจอนุมัติของผู้ใช้ ไม่ถามอนุมัติการดำเนินการเดิมซ้ำ

## 16. เกณฑ์ตรวจรับใหม่และนิยามความสำเร็จ

สร้างทะเบียนเมื่อ scope ของ increment ชัด แถวหนึ่งมี requirement/ผู้ใช้/สถานการณ์/expected/ชั้นหลักฐาน/source fingerprint/content revision/result/artifact/defect. สถานะ ผ่าน / ล้มเหลว / ยังไม่ทดสอบ / รอเงื่อนไขภายนอก พร้อมเหตุผล นอก release scope บันทึกแยกและตรวจ dependency ไม่ใช้ป้ายนี้ปิด defect ที่จำเป็นต่อผู้ใช้ใน release

| กลุ่มเกณฑ์ | สิ่งที่ยืนยันก่อนอ้างรองรับ |
| --- | --- |
| เริ่มศูนย์ | สอนจริงก่อนถาม ไทย/ตัวช่วยเข้าถึง ไม่ติด signup/AI/ไมค์ |
| ไปต่อและผลเรียน | no-mic/no-reviewer ยังเลือกบทต่อได้; ไม่มีการเพิ่ม mastery/XP จากการปลดล็อกหรือเปิดบท; ผลเสียงที่ไม่ตรวจยัง unknown |
| ทักษะต่างกัน | ไม่แนะนำจากอายุ/tense อย่างเดียว unknown ไม่เป็น zero เปลี่ยนทางได้ |
| การสอน | เนื้อหา/เฉลย/สื่อตรวจแล้ว assisted/independent แยก ทางเลือกตอบมีความหมาย |
| Phonics/CI | ตรวจคนละ construct: รูป–เสียง/อ่านคำ/สะกด/เข้าใจสาร; มีคำและเรื่องใหม่, prerequisites/ตัวช่วย/เสียงถูกต้อง และไม่บังคับ ABC ก่อน input |
| ใช้ง่าย | รายงานรายกลุ่ม/งาน ข้อขัดขวางแก้และ retest กลุ่มไร้ข้อมูลไม่เป็น PASS |
| เข้าถึง | ขนาด/contrast/ขยาย/focus/screen reader/แตะ รวมไทยและเครื่องที่ประกาศ |
| ข้อมูล/คะแนน | ไม่ข้าม owner ไม่หาย/ซ้ำ ตรวจ persistence หลัง restart/sync |
| สื่อ/AI | หลักฐานจริงตามชั้น นโยบาย/ข้อจำกัดพร้อม baseline เรียนได้เมื่อบริการไม่พร้อม |
| ผลเรียน | ระบุเป้าหมาย/เงื่อนไขที่ตรวจ ไม่อ้างระดับทางการหรือทุกวัยจาก pilot |

215 เกณฑ์เก่า: เก็บหลักฐาน; reuse หลัก owner/data/scoring หลังตรวจ applicability; เขียน UI/route/AI ใหม่; retire learner ChatGPT/MCP-pairing. ไม่ลบประวัติหรือนับแถวเก่าเป็นเปอร์เซ็นต์งานใหม่

ใช้ `tool/cli/verify-scope.ps1` สำหรับ checks ตาม implementation gate ผ่านแล้ว fingerprint เดิมไม่รันซ้ำ. หลัง defect ใน release scope ปิด ให้ freeze source/content ตรวจ regression และ native ที่ได้รับผล Full release verifier เฉพาะ frozen PR/release SHA. Endurance 180 นาทีจริงตามข้อกำหนดโครงการเป็นงานช่วง release บน source คงที่ มี checkpoint/crash/ANR/resources/ข้อมูลก่อน–หลัง ไม่เริ่มในงานออกแบบนี้

Definition of Done ของ **แผน** คือขอบเขต/ช่องว่าง/เส้นทาง/หลักฐาน/ข้อจำกัด/ลำดับชัด. ของ **ผลิตภัณฑ์** ต้องผ่านเกณฑ์ increment และกลุ่มที่อ้างด้วยหลักฐานจริง ไม่มี RED ที่จำเป็นค้าง ข้อมูลเดิมคงความหมาย เงื่อนไขภายนอกไม่เป็น PASS ห้ามใช้สองสถานะนี้แทนกัน
