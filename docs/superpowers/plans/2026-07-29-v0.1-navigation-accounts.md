# LexiQuest v0.1 Typed Navigation and Accounts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the fragmented account/navigation flow with one typed route system and production Firebase account lifecycle covering registration, verification, sign-in, guest upgrade, forgot/reset password, change password, and sign-out.

**Architecture:** UI consumes an injected provider-independent `AccountGateway`; only `FirebaseAccountGateway` imports Firebase Auth. A typed `AppRoute` registry owns every account route and consumes validated Firebase Hosting action links through `app_links`. Registration/profile provisioning is one idempotent workflow, and password recovery always returns a neutral user-facing acknowledgement to prevent account enumeration.

**Tech Stack:** Flutter 3.44.7, Dart 3.12.2, Firebase Auth 6.5.6, Cloud Firestore, App Links 7.2.1, Material 3, Android App Links, Firebase Hosting domain `vocab-learning-app-219ef.web.app`, Android package `com.lexiquest.app`.

## Global Constraints

- The primary architecture is on-device first.
- The supported baseline is Android 10 or newer, 4 GB RAM, and 2 GB available storage; 6 GB RAM is recommended.
- The Android package version is `0.1.0+1`.
- Firebase is the only account and synchronization platform in v0.1.
- Gemini is the only AI provider and uses a user-supplied key; no provider key is bundled.
- Supabase is absent from the v0.1 runtime and Android build inputs.
- Production code must not return mock, sample, simulated, or fabricated results.
- Core learning must open, run, and save without cloud availability.
- Account UI uses natural UTF-8 Thai and the centralized Material 3 theme.
- Passwords, action codes, ID tokens, email addresses, and provider diagnostics must not be logged.
- Password-reset acknowledgement must not reveal whether an account exists.
- Every production behavior change follows red-green-refactor TDD.
- Branch names for this program must not contain `codex`.

```dart
enum AccountActionMode { resetPassword, verifyEmail }

final class AccountActionLink {
  const AccountActionLink({required this.mode, required this.code});

  static const host = 'vocab-learning-app-219ef.web.app';
  static const path = '/auth/action';

  final AccountActionMode mode;
  final String code;

  static AccountActionLink? tryParse(Uri uri) {
    if (uri.scheme != 'https' ||
        uri.host != host ||
        uri.path != path ||
        uri.userInfo.isNotEmpty ||
        uri.hasFragment) {
      return null;
    }
    final code = uri.queryParameters['oobCode']?.trim() ?? '';
    final rawMode = uri.queryParameters['mode'];
    if (code.isEmpty) return null;
    final mode = switch (rawMode) {
      'resetPassword' => AccountActionMode.resetPassword,
      'verifyEmail' => AccountActionMode.verifyEmail,
      _ => null,
    };
    return mode == null ? null : AccountActionLink(mode: mode, code: code);
  }

  @override
  bool operator ==(Object other) =>
      other is AccountActionLink &&
      other.mode == mode &&
      other.code == code;

  @override
  int get hashCode => Object.hash(mode, code);
}

final class AccountSession {
  const AccountSession({
    required this.uid,
    required this.email,
    required this.isAnonymous,
    required this.isEmailVerified,
  });

  final String uid;
  final String? email;
  final bool isAnonymous;
  final bool isEmailVerified;
}

final class GuestUpgradeResult {
  const GuestUpgradeResult({
    required this.previousUid,
    required this.session,
  });

  final String previousUid;
  final AccountSession session;
}
```

```dart
abstract interface class AccountGateway {
  AccountSession? get currentSession;
  Stream<AccountSession?> authStateChanges();
  Future<AccountSession> signIn({
    required String email,
    required String password,
  });
  Future<AccountSession> createAccount({
    required String email,
    required String password,
  });
  Future<void> signOut();
  Future<AccountSession?> reloadSession();
  Future<void> sendVerificationEmail();
  Future<void> applyVerificationCode(String code);
  Future<void> requestPasswordReset(String email);
  Future<String> verifyPasswordResetCode(String code);
  Future<void> confirmPasswordReset({
    required String code,
    required String newPassword,
  });
  Future<void> changePassword({
    required String currentPassword,
    required String newPassword,
  });
  Future<GuestUpgradeResult> upgradeAnonymous({
    required String email,
    required String password,
  });
}
```

## Plan 2 completion gate

Plan 2 is complete only when:

- all account screens use `AccountGateway` and typed routes;
- production account UI has no direct Firebase Auth call;
- registration creates one account/profile and blocks home until verified;
- verification resend is throttled;
- forgot-password responses do not enumerate accounts;
- valid reset action codes can be verified and consumed exactly once in-app;
- invalid/expired codes have a safe recovery path;
- changing a password reauthenticates with the current password;
- guest upgrade links credentials and emits an explicit UID migration handoff;
- sign-out clears navigation history;
- account copy is natural UTF-8 Thai;
- no password, email, action code, token, or provider message is logged;
- Android App Links use Firebase Hosting, not retired Dynamic Links;
- focused, full Flutter, CLI, and Android debug APK gates pass;
- remote Firebase email-template/Hosting parity is recorded as an owner gate
  and must pass before the signed v0.1 APK is distributed.
