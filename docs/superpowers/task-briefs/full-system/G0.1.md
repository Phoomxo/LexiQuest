## ตรวจและบันทึกปัญหา

ตรวจตาม source-inspection protocol; ไม่ใช้การรัน Flutter แทนหลักฐานชนิดนี้

Verification kind: `source-inspection`; bounded subsystem: `Runtime`. ยืนยัน targets กับ actual reconciled source ก่อนรัน. ใช้ existing passed evidence เมื่อ source/dependency/config fingerprint ยังตรง; ไม่รัน full release verifier ก่อน frozen PR/release SHA และไม่รัน heavy suites พร้อมกัน. Docs/source-inspection ใช้ hash/path/link/Git/diff checks ไม่สร้าง Flutter PASS แทน. Planned targets ไม่ใช่ผลทดสอบที่รันแล้ว

บันทึก unexpected failure ตั้งแต่ครั้งแรก: DefectID, source/config, steps, expected/actual, evidence, root cause, fix และ retest. คำสั่ง/filesystemล้มซ้ำหรือไม่มี progress10นาทีให้หยุดวิธีที่ผิดแล้ว diagnose ไม่ retry วน. ใช้ judgment แก้ recoverable blockers; external-required ที่ยังไม่ผ่านเป็น NOT RUN/external-pending. ก่อนปิด package ตรวจ diff/callers/data integrity และ acceptance ใหม่โดยแยกจาก implementation pass
