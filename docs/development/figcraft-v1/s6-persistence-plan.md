## Exact physical contract

- AnswerAttempts adds nullable `calendar_evidence` and `quest_intent` text. Historical rows stay NULL. The future bounded versioned decoder validates original owner, rule/tzdb, civil labels, normalized exact segment arrays and immutable per-cadence pins. Capture from the already authoritative stored occurrence milliseconds; epoch endpoints may retain microseconds. No JSON1-specific SQL dependency or duplicate answer log.
- New `owner_calendar_epochs`: `rule_id` PK; owner FK; immutable origin owner; signed effective/expires UTC microseconds; IANA ID; tzdb revision; `is_selected` boolean. Unique origin/effective time and partial selected owner/effective uniqueness. Expiry must be after effective time. Settings validates nonoverlap transactionally. Guest historical rules survive; target selected schedule controls future learning.
- New shared `quest_definition_revisions`: Quest ID + catalog version PK, digest, canonical definition. Unique Quest/version/digest supports exact composite FK. No v10 content is promoted to a trusted revision by migration. Original shared quest_definitions stays byte-for-byte historical identity/content.
- Rebuild QuestInstances retaining its eight old fields/IDs/FKs and removing lifetime owner/Quest uniqueness. Add nullable origin owner, `period_key`, calendar rule ID, civil label, exact `segments_json`, definition digest, canonical instance ID (self FK); `record_kind` defaults to `legacy`. Canonical/alias/conflict rows require complete pins; legacy remains unverifiable. Composite Quest/version/digest FK references exact revision; NULL legacy digest preserves older missing bodies. Partial unique owner/period key for canonical records; never key by segment or updated catalog version.
- New `quest_claim_receipts`: ID PK; owner FK; original issuer owner; unique instance FK; issued/completed UTC milliseconds; positive XP; immutable qualifying evidence JSON. No circular projected-points FK or second points writer. Receipt drives the existing XP issuer in the same claim transaction. Migration creates no receipts/XP/coins/outbox.
- New `streak_baselines`: original owner PK; current owner FK; migration cutoff; exact original current/longest/freeze/last-time/updated-time values; boolean continuity selector, at most one selected baseline per owner. Seed existing streak states once without changing raw states/day logs or inventing protection dates. Preserve surprising legacy values for export; a reader must not infer trustworthy historical zones or mint tokens from invalid state.
- New `streak_token_adjustments`: ID PK; current owner FK; original owner; stable command ID; occurrence UTC milliseconds; kind/delta/optional protected day. Unique origin/command. Grant is positive without protected day; manual debit is minus1 without day; auto-protection is minus1 with day, unique original owner/protected day. Raw independent assets/debits survive merge.

Five added tables, four owner scopes and one shared archive. Product denominators remain48/44/64. Shared original definitions and referenced revisions are included in full local export without becoming cloud-delete collections. Required local scopes, schema-aware backend receipt validation, reverse deletion topology, owner merge and discarding untrusted sync metadata are part of this same card's completion. Ordinary incoming answers remain accepted; local Quest authority fields are omitted from outgoing payloads and ignored on incoming replay.
