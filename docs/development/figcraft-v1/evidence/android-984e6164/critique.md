## สิ่งที่ทำงานดีจากภาพที่เห็น

1. หน้าฝึกใช้ platform และจำนวนถึงคิวจากข้อมูลสังเคราะห์ที่ตรวจได้. ไม่แสดงคำแปลก่อนผู้เรียนเปิดเฉลย. ปุ่ม “ทบทวนคำนี้” เด่นเพียงปุ่มเดียวในส่วนแนะนำ.
2. ทั้งสองหน้าใช้ชื่อสี่แท็บไทยตรงกัน. XML ระบุ selected state ให้แท็บปัจจุบัน. ป้ายชื่อยาวทั้ง “คลังคำศัพท์” และ “ความก้าวหน้า” ยังเห็นครบที่ 100%.
3. ข้อความไทยที่เปิดดูไม่พบสระบน วรรณยุกต์ หรือสระล่างตัด/ชนกันที่ขนาดนี้. แถวคำอธิบายยาวตัดบรรทัดได้ และมีแนวซ้ายเนื้อหาใกล้ 24 dp เหมือนแบบ.

## Priority issues ของ milestone

### P1 · คลังยังไม่มีทางเริ่ม “เพิ่มคำ” ตามแบบ

**พบจริง** ปุ่มหลักด้านล่างชื่อ “เพิ่มชุดคำศัพท์”. หน้า FigCraft มี “เพิ่มคำ” ด้านขวาหัวเรื่อง และรวมพิมพ์ ถ่ายภาพ และนำเข้า. Source ยืนยันปุ่มปัจจุบันเรียก `_showAddCategory` ไม่ใช่เมนูเพิ่มคำ (`lib/screens/categories_page.dart:162`).

**ผลต่อผู้เรียน** คนที่ต้องการเก็บคำจากสิ่งของต้องรู้ก่อนว่าจะเปิดหรือสร้างชุด. ภาพ `home-new.png` ชวนไปเลือกชุด แต่เมื่อไปคลังยังต้องแยกความหมายระหว่างชุดกับคำเอง.

**แก้ที่ต้องตรวจรับ** ให้คลังมีทาง “เพิ่มคำ” ที่มองเห็นชัดและเลือกพิมพ์/กล้อง/ไฟล์ได้. เลือกหรือสร้างชุดปลายทางอย่างชัดเจนก่อนเขียน โดยใช้ use case เดิม. คงทางสร้างชุดไว้ในตำแหน่งรองที่หาได้. ตรวจเริ่มจากคนใหม่และผู้มีสองชุดแล้วเก็บลงชุดที่ตั้งใจได้.

Suggested command: `$impeccable clarify`, `$impeccable layout`.

### P1 · ค้นหาเปลี่ยนจากคำในคลังเป็นชื่อชุด

**พบจริง** ช่องแอปเขียน “ค้นหาชุดคำศัพท์”. Source กรอง `category.normalizedName` เท่านั้น (`lib/screens/categories_page.dart:113`). แบบเขียน “ค้นหาคำในคลัง”.

**ผลต่อผู้เรียน** ผู้เรียนจำคำว่า platform หรือ cup ได้ แต่ไม่จำชุด จะค้นจากคลังรวมไม่พบ แม้คำนั้นอยู่ในเครื่อง. งานกลับมาหาคำจากกล้องจึงยังไม่ตรงเส้นทางที่รับไว้.

**แก้ที่ต้องตรวจรับ** ค้นคำของ owner ปัจจุบันข้ามชุดได้ พร้อมชื่อชุดกำกับและทางกลับที่รักษาคำค้น. ไม่ต้องนำข้อมูลจาก owner อื่นหรือสร้างดัชนี/อำนาจเขียนใหม่เพื่อปรับ UI. ตรวจคำจากสองชุด คำไม่พบ และกลับจากรายละเอียดแล้วคำค้นยังอยู่.

Suggested command: `$impeccable shape`, `$impeccable clarify`.

### P1 · หน้าเริ่มฝึกขาดทางฝึกจากชุดและเสนองานที่ยังไม่มีข้อมูล

**พบจริง** ฝึกเพิ่มเติมแสดงอ่านเรื่องสั้นกับฝึกจุดอ่อน แต่ไม่มี “ฝึกจากชุดคำ” เหมือนแบบ. ทางเลือกชุดอยู่ในดูแบบฝึกทั้งหมดและเปลี่ยนชื่อเป็น “ฝึกตามหมวดหมู่” (`lib/screens/choose_mode_screen.dart:262`). แถวฝึกจุดอ่อนตรวจ feature visibility อย่างเดียว ไม่ตรวจว่ามีคำที่ผิด (`lib/screens/choose_mode_screen.dart:306`). Fixture รอบนี้มีเพียงชุด/คำ/SRS ไม่มีประวัติคำตอบผิด.

**ผลต่อผู้เรียน** งานฝึกจากคำที่เก็บไว้ต้องค้นเมนูเพิ่ม และผู้เรียนใหม่ถูกชวนไปงานที่ยังไม่มีข้อมูล. ไม่ใช่จำนวนปลอม แต่เป็นคำแนะนำที่ยังไม่สัมพันธ์กับสถานะจริง.

**แก้ที่ต้องตรวจรับ** วาง “ฝึกจากชุดคำ” ในฝึกเพิ่มเติมด้วยชื่อเดียวตั้งแต่ต้นทางถึงตัวเลือกชุด. แสดง “ฝึกคำที่ตอบผิด” เมื่อมีหลักฐานจริง หรืออธิบายเงื่อนไขอย่างชัดเจนหากแสดงแบบยังไม่พร้อม. ไม่ลด feature registry gates. ตรวจ due/ไม่มี due/ผู้ใช้ใหม่/โหลดล้มเหลว และกลับหน้าเดิมหลังจบรอบ.

Suggested command: `$impeccable distill`, `$impeccable clarify`.

### P2 · หัวเรื่องและลำดับภาพสองแท็บยังไม่ร่วมระบบ

**พบจริง** หน้าฝึกใช้หัวใหญ่ชิดซ้าย แต่คลังใช้หัวเล็กกึ่งกลาง. แบบใช้หัวเรื่อง 32 และแนวซ้าย 24 ทั้งคู่. ช่องค้นในแอปมีทรงแคปซูลและเงาเด่น ขณะที่แบบใช้กรอบบาง. ชื่อชุดกับคำอธิบายยังมีน้ำหนักใกล้กัน และไอคอนลบเด่นเท่าทางเปิดชุด.

**ผลต่อผู้เรียน** การเปลี่ยนแท็บให้ความรู้สึกคนละลำดับชั้น คลังให้พื้นที่สายตากับเครื่องมือมากกว่าเนื้อหาที่ต้องหา. บนหน้าฝึก “ฝึกเพิ่มเติม” เริ่มประมาณ y336 แต่แบบอยู่ประมาณ y457 ซึ่งสัมพันธ์กับเนื้อหาการ์ดที่ขาด ไม่ควรแก้ด้วยช่องว่างตายตัวอย่างเดียว.

**แก้ที่ต้องตรวจรับ** ใช้ heading/spacing/color roles ร่วมตามแบบผ่านส่วนประกอบเดิม จัดชื่อชุดเด่นกว่าข้อมูลรอง และลดน้ำหนักเครื่องมือลบโดยยังเข้าถึงได้. เทียบที่สัดส่วนเดียวกันอีกครั้งทั้ง 100%/200% และธีมมืดก่อนรับ. ห้ามทำตัวอักษรคงที่เพื่อไล่ภาพ 100%.

Suggested command: `$impeccable typeset`, `$impeccable layout`, `$impeccable polish`.

### P2 · การ์ดคำถึงคิวขาดบริบทที่ช่วยนึก

**พบจริง** แอปแสดงคำกับคำแนะนำทั่วไป. แบบมีชื่อชุด ประโยคใช้งาน และภาพสถานีที่ไม่บอกคำแปล. คลังในแบบมีตัวอย่าง station/platform/ticket เพื่อบอกเนื้อหาก่อนเปิดชุด.

**ผลต่อผู้เรียน** ผู้เรียนเห็นว่าจะทบทวนคำอะไร แต่ไม่เห็นว่าคำนี้อยู่ในชุดไหน และแยกสองชุดได้จากชื่อเพียงอย่างเดียว.

**แก้ที่ต้องตรวจรับ** เพิ่มชื่อชุดจริงและข้อมูลตัวอย่างที่ authority เดิมมี. ถ้ายังไม่มีประโยคที่ตรวจที่มาได้ ให้ระบุเป็นส่วนที่ยังขาดและจัด layout รองรับโดยไม่ hardcode ประโยคสาธิตเป็นข้อมูลจริง. ภาพช่วยจำต้องไม่เปิดคำตอบก่อนเฉลย รวมชื่อที่โปรแกรมอ่านหน้าจออ่านด้วย.

Suggested command: `$impeccable shape`, `$impeccable clarify`.

## Cognitive load และ emotional journey

Home มีงานในเนื้อหาสี่ทางที่เห็น ได้แก่ทบทวน อ่าน ฝึกจุดอ่อน และดูทั้งหมด จึงยังไม่เกินสี่ทางในกลุ่มงานเดียว. แถบสี่แท็บเป็นอีกกลุ่มหนึ่ง. ปัญหาคือทางฝึกจากชุดที่ต้องการกลับซ่อนอยู่ ขณะที่งานไม่มีประวัติยังเสนอขึ้นมา. ข้อความแถวละหลายบรรทัดเพิ่มการอ่านก่อนตัดสินใจ.

คลังมีช่องค้น สองแถวชุด ปุ่มลบสองจุด และปุ่มเพิ่มชุด รวมเป็นหกพื้นที่กระทำในเนื้อหาที่เห็น. สองตัวเลือกลบใช้ตำแหน่งเดียวกับที่ผู้เรียนมองหาทางเปิดชุด. ความหนาแน่นโดยรวมยังต่ำ จึงควรปรับลำดับงาน ไม่ต้องเพิ่มการ์ดหรือย่อทุกอย่างให้เล็ก.

จุดเริ่มของคนมีคำถึงคิวมั่นใจได้เพราะเห็น platform กับปุ่มเด่น. ช่วงเปลี่ยนจาก “อยากเก็บคำ” ไปคลังเป็นจุดที่ความมั่นใจลดลง เพราะคำสั่งเปลี่ยนเป็นเพิ่มชุด. รอบนี้ไม่เห็นหน้าเฉลยหรือจบรอบ จึงยังไม่ประเมิน peak/end ของเส้นทางเต็ม.

## Persona red flags

- **Jordan ผู้ใช้ครั้งแรก** เมื่อได้รับงาน “เก็บคำอังกฤษจากสิ่งของ” จะเห็นเพิ่มชุดคำศัพท์ แต่ไม่เห็นกล้องหรือเพิ่มคำจากคลังทันที. นี่เป็นการคาดการณ์จาก UI โดยผู้วิจารณ์ ไม่ใช่ผลสังเกตผู้เรียนจริง.
- **Casey ผู้ใช้มือถือที่ถูกขัดจังหวะบ่อย** ผู้ที่จำได้เฉพาะคำต้องจำชื่อชุดเพิ่ม เพราะช่องค้นยังหาเฉพาะชุด. ยังไม่มีหลักฐานการปิดเปิดแอปในชุดภาพนี้ที่จะยืนยันการกลับมาทำต่อ.
- **Sam ผู้ใช้โปรแกรมอ่านหน้าจอ/ตัวอักษรใหญ่** XML มีชื่อปุ่มหลักและ selected state ของแท็บ แต่ TalkBack, ลำดับโฟกัส, การประกาศสถานะ และ 200% ยังไม่ได้ตรวจ. Search editable node ใน UI dump ไม่มี text/content-desc จึงต้องฟังจาก TalkBack จริงก่อนสรุปว่า label ครบหรือขาด.

## ภาษาไทย เป้าแตะ และข้อสังเกตรอง

- ที่ 100% ไม่พบการตัดหรือชนของวรรณยุกต์ใน “ฝึกภาษา”, “คลังคำศัพท์”, “ถึงเวลาทบทวน 1 คำ”, “เพิ่มคำศัพท์เพื่อเริ่มฝึก” และคำอธิบายที่เห็น. ผลนี้จำกัดเฉพาะภาพที่แนบ.
- XML ให้เป้าเมนู 77×77 physical px หรือ 48.125×48.125 dp, CTA ทบทวนสูง 48.125 dp, ปุ่มลบสูง 48.125 dp และแท็บ 97.5×80 dp จาก density 1.6. พื้นที่หลักที่วัดได้ไม่ต่ำกว่าเกณฑ์ 48 dp. Child editable area ของ SearchBar ต้องประเมินร่วมกับ parent 56.25 dp ไม่ตัดสินจาก bounds ย่อยเพียงอย่างเดียว.
- ไม่ได้วัด contrast ครบทุกคู่ และไม่ได้จับภาพธีมมืด. ไม่อ้างผ่าน WCAG ทั้งระบบจากภาพนี้.
- XML ของแท็บมีข้อความ “Tab 1 of 4” ภาษาอังกฤษปนกับชื่อไทย. ตรวจการออกเสียง/localization บน TalkBack รอบอุปกรณ์จริง.
- เมนูงานที่ได้รับและภาพใน FigCraft ไม่มีคู่ใน Flutter รอบนี้. ห้ามแสดงจำนวนงานตัวอย่างเพื่อทำให้เหมือนภาพ. เชื่อมเมื่อมี authority ข้อมูลงานจริงแล้วเท่านั้น.

## เกณฑ์รับรอบแก้

แก้ P1 ทั้งสามก่อน แล้วสร้างภาพคู่สองภาพใหม่จาก SHA เดียวและ fixture เดิม. ให้ผู้ตรวจเห็น “เพิ่มคำ”, ค้นคำข้ามชุด, ฝึกจากชุดได้จากหน้าแรก และงานคำผิดสัมพันธ์กับข้อมูล. ตรวจ P2 ผ่านภาพและให้ disposition รายข้อ. จากนั้นเพิ่ม 360/390, 200%, มืด/สว่าง และ TalkBack บนมือถือจริง. ผลทดสอบ Flutter ผ่านไม่เปลี่ยนรายการภาพหรือการเข้าถึงที่ยังไม่ได้ตรวจให้เป็นผ่าน.
