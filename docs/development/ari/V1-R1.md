## จุดเชื่อมและ gate

เส้นทางที่เสนอคือ Flutter → backend → App Server แยกต่อผู้ใช้ → ChatGPT ของผู้ใช้; ไม่ต้องมี Codex บนอุปกรณ์ผู้เรียน แต่ backend ต้องมี binary/credential lifecycle และต้นทุน infrastructure. `AiTutorGateway.generateTutorReply` ใน `lib/features/ai_tutor/domain/ai_tutor_contracts.dart:540`, `AiTutorUseCases` และ gateway factory เป็นจุดพิจารณาในอนาคต. สัญญาปัจจุบันต้องการ BYOK key และ provider enum; backend `/v1/content` เป็น content generation ไม่ใช่ managed-account tutor stream จึงต้องออกแบบ authenticated session route, owner binding, cancel/stream mapping และ quota-only behavior หลัง gate ผ่าน. รอบนี้ไม่แก้ lib/backend/API/schema/provider feature gate ของ production.

[App Server](https://learn.chatgpt.com/docs/app-server) อธิบาย embedding/managed login/stream; [Authentication](https://learn.chatgpt.com/docs/auth) ระบุ device-code เป็น beta และต้องเปิดใน ChatGPT security settings หรือ workspace permission. ไม่ใช่ Developer mode แต่ยังมี UX friction จริง. เอกสารนี้ไม่ใช่การรับรอง hosted distribution/Free ไทย/billing/revoke.

ก่อนเปิด V2 ต้องมีหลักฐาน route/สิทธิ์ใช้งานที่รองรับ backend-hosted per-user สำหรับกลุ่ม Free ไทย, ขอบเขต quota-only/การหมดโควตาโดยไม่ charge หรือ paid fallback, และวิธี revoke/ลบ credential ที่รองรับ. ประเมินการเปิด device-code setting กับข้อกำหนด UX ให้ชัด. บัญชี Free ไทยที่อนุญาตและมือถือจริงยังไม่มีสำหรับขั้นทดสอบ authenticated ภายหลัง; ไม่ใช้ผล live เป็น prerequisite วนย้อนก่อนสร้างต้นแบบ. ไม่มี externalAuthTokens/token-copy/scraping/paid fallback. ไม่สร้าง V2 หรือ task ค้นเอกสารซ้ำเพื่อเลี่ยง gate.

V2/T01–T08/pilot = NOT_RUN; E7 = UNCHANGED_NOT_CLOSED. ปล่อย writer แล้ว ไม่มี successor อัตโนมัติ. Requested Astra/medium, Standard/default; เครื่องมือไม่แสดง effective service tier จึงไม่อ้างว่ายืนยัน runtime tier แล้ว. มี writer เดียว ไม่มี subagents.
