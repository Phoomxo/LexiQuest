# V1-R1 — ทดลองตัวเชื่อม App Server

2026-09-20 · เปิดงานตามคำสั่งผู้ใช้ให้หาวิธีและลงมือพัฒนา · input `a07c7d9c415fb4853a529ee1321fb860982bb40f`

## ทางที่ตรวจต่อ

LexiQuest mobile → backend ของโครงการ → App Server แยกต่อผู้ใช้ → บัญชี ChatGPT ของผู้ใช้ เป็น topology ที่เสนอให้พิสูจน์ ไม่ใช่ระบบที่ใช้งานได้แล้ว ไม่ต้องมี Codex binary บนมือถือหรือคอมพิวเตอร์ส่วนตัวของผู้เรียน แต่ backend มีต้นทุนโครงสร้างพื้นฐานและภาระดูแล credential ที่ต้องประเมิน

เอกสาร [App Server](https://learn.chatgpt.com/docs/app-server) รองรับ product integration, managed ChatGPT login, device-code และ streamed events; binary ที่พบคือ `codex-cli 0.146.0`. [Authentication](https://learn.chatgpt.com/docs/auth) ระบุว่า device-code เป็น beta และต้องเปิดใน ChatGPT security settings เป็นข้อจำกัด UX จริง แม้ไม่ใช่ Developer mode

## งาน 3 ส่วน ภายในหนึ่ง project task

1. **Protocol:** เขียนเครื่องมือตรวจและ adapter ทดลองแบบ stdio ใน `tool/experiments/ari_app_server/`; pin schema จาก binary จริง ตรวจ initialize/account/read/logout/cancel และรองรับการจับคู่ request ID, notification, timeout, EOF/error พร้อมปิด child process เสมอ
2. **Isolation:** ทดสอบ fake process/transport ที่คืน response สลับลำดับ, late event, process ตาย, timeout และ session ที่ปิดแล้ว ต้องแยก simulated ออกจาก binary จริง ไม่เก็บ auth/token หรือ raw payload ที่มีข้อมูลส่วนตัวในรายงาน
3. **Real diagnostic:** รัน initialize/account/read กับ binary จริงใน temporary home และ cwd ว่างที่แยกจากบัญชีปัจจุบัน บังคับ file credential store ใหม่และล้าง inherited provider credentials เฉพาะ child environment ไม่เปิด listener/network service ไม่ login/เรียกโมเดล และไม่ใช้ quota บัญชีผู้พัฒนา ยืนยันไม่มี account แล้ว cleanup เฉพาะ directory/process ที่เครื่องมือนี้สร้าง

ใช้ Python standard library หรือ runtime ที่มีอยู่ ไม่เพิ่ม dependency ถ้าไม่จำเป็น ตรวจความสามารถจาก local schema แทนการคาดเดา endpoint หาก docs กับ binary ไม่ตรง ให้บันทึกและแก้วิธีโดยไม่อ้างผลสำเร็จเกินจริง

## เกณฑ์จบและการส่งต่อ

- มี source ที่รันซ้ำได้, focused tests, ผล binary จริงพร้อม version/hash และคำสั่ง reproduction; fake PASS ไม่ใช่ live login PASS
- สรุปข้อจำกัดที่ยังเหลือให้จำเพาะ: Free/ไทย, hosted deployment, quota-only policy, provider revoke, device-code UX และบัญชี/มือถือสำหรับตรวจจริง ห้ามวนค้นทั่วไปซ้ำโดยไม่มีคำถามใหม่
- งานนี้เป็นเครื่องมือพิสูจน์ V1 ไม่ใช่ V2 chat prototype และไม่เปลี่ยน production API/schema/UI/provider gate. V2/T01–T08/pilot/E7 ยังไม่รับ PASS
- อ่าน runtime interface ของ AI Tutor เดิมเพื่อระบุ integration point ใน handoff โดยยังไม่ต่อเข้าหน้าจอจริง ไม่สร้าง MCP เต็มชุดหรือ paid fallback
- ถ้าหลักฐานเพียงพอเปิด V2 ให้บันทึก gate decision พร้อม sources ก่อนสร้าง successor; หากยังไม่พอ ให้ส่งผลโค้ดที่ตรวจแล้วและ prerequisite จริง ไม่ส่งงานค้นซ้ำวนไปมา

รัน focused checks ผ่าน `tool/cli/verify-scope.ps1` เมื่อรองรับ custom diagnostic; หาก runner ไม่มีช่องทาง Python ให้ใช้ `python -m unittest discover` เฉพาะโฟลเดอร์นี้และบันทึกเหตุผล ไม่รัน 77 rename tests เดิมซ้ำ ไม่แก้หลักฐาน immutable ใน `evidence/`

รายงานสั้นในไฟล์นี้; หลักฐานและ handoff ใหม่อยู่ `V1-R1-evidence.json`/`V1-R1-handoff.json`. หนึ่ง writer; project-bound task, `feature/` branch, Astra/medium, Standard/default, ไม่ใช้ Fast, ไม่มี subagents. ปัญหาที่แก้ได้ต้องวินิจฉัย แก้ และทดสอบต่ออัตโนมัติ
