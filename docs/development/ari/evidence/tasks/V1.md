## ## Gate ก่อนเริ่ม V2 (แก้ความชัดเจน 2026-09-20)
V0–V1 ตรวจ supported route, entitlement, billing และแบบ isolation/revoke ที่ทดสอบได้ ไม่ต้องมีเอกสารรับรองชื่อ LexiQuest หรือผล live ทุกกรณีล่วงหน้า. T04/T05/T06 เป็น acceptance ของ V2 หลังมีต้นแบบ ไม่ใช่เงื่อนไขเริ่มต้นแบบ.

| ข้อ | เกณฑ์ | ผล | สิ่งที่ยังต้องทำ |
|---|---|---|---|
| G1 | Native mobile runtime, transport and browser-only login return | UNCONFIRMED | Supported integration topology compatible with native mobile/no companion, with a feasible auth-return design. No provider certification naming LexiQuest or pre-prototype runtime traces required. |

NOT_MET คงอยู่จากช่องว่าง route/entitlement/billing/distribution/provider-revoke mechanism (G1–G5). G6 มีแบบตรวจแล้ว ไม่เป็น blocker เพียงเพราะยังไม่มี live traces. การไม่มีบัญชีจริงเป็น prerequisite ของการรัน V2; experimental production warning เพียงอย่างเดียวไม่ใช่หลักฐานห้าม prototype.

ตรรกะการออกแบบที่จะตรวจภายหลัง
ข้อความต้องอยู่ใน native LexiQuest; browser เฉพาะ login และไม่มี companion. การมี SDK หรือ Remote ไม่ผ่านเกณฑ์นี้. หากมี supported route จึงกำหนด owner/session generation และผูก event กับ thread/turn เพื่อทิ้ง late reply หลังสลับบัญชี รวมถึงแยก credential/history ของแต่ละคน ทั้งหมดเป็นข้อเสนอการตรวจ ไม่ใช่ implementation หรือผล PASS.

แยก included quota, paid credits/API inference และ hosting infrastructure ออกจากกัน ไม่ประเมินค่า hosting เป็นศูนย์ และไม่ใช้ polling quota เป็นคำรับรองหยุดค่าใช้จ่ายข้ามหลาย session. เมื่อ auth/limit ล้มต้องหยุดโดยไม่มี paid fallback; ต้องมีหลักฐานต้นทางก่อนทดลอง.

ก่อน V2 ต้องมีช่องทาง provider revoke และแบบตรวจ; เวลามีผลและการปฏิเสธ credential เก่าตรวจใน V2 แยกจาก local logout; ห้ามเก็บ token ลงหลักฐาน. Distribution ต้องมี topology/version และข้อกำหนดติดตั้งที่ผู้เรียนทำได้ตาม acceptance เดิม.
