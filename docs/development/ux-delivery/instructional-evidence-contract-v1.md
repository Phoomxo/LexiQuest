Status: **PROPOSED / NOT IMPLEMENTED / NOT CONTENT-APPROVED**, 2026-09-24. Authority: plan v5 §§11.1, 13, 15.5(4), 15.8 and controller instruction to inspect interface readiness. Outcome: reviewers and a later implementer can distinguish a word answer, phoneme observation and story response without inventing word IDs or learner success. This document does not authorize a production API/schema change, migration, research activation or instructional Flutter before relevant trial acceptance.

## 2. Version boundary and proposed ownership

Design name: `InstructionalObservationV1`, schemaVersion **1 in a new namespace**, not EvidenceContext V2, database version 1, nor EventEnvelope version 1. Every name in this section is proposed, not a callable current API.

Proposed ingress: `LearningUseCases.recordInstructionalObservation(candidate)` through a new `InstructionalObservationRepository` capability implemented by the canonical Drift learning repository. Read/replay belongs to that capability and the existing learning event store; no widget, prototype, AI, progress query or experiment component writes scores or SRS directly.

Use the existing EventEnvelopeV2 metadata unchanged if its current fields suffice. Proposed event type `InstructionalObservationRecorded`, eventVersion 1, carries this new payload; it needs explicit adapter, resolver, transport allowlist and consumer support. Unknown event types/versions are retained or rejected explicitly by their owning boundary, never coerced into QuizAttempted. Any envelope-field extension requires a separate envelope-version decision. No enum/API/table changes are made by this draft.

Proposed result is `inserted | replayed` with a canonical source/receipt reference, or a typed rejection. It has no compulsory boolean correctness or SRS snapshot. Rejection codes distinguish unsupported version, invalid shape, identity conflict, stale owner, unavailable session/content/media and unresolved authority. A rejected command is not a wrong learner response.

## 3. Proposed record shape and validation

| Group | Required semantics |
| --- | --- |
| Identity | `schemaVersion`, opaque `sourceEvidenceId`, `ownerId`, `sessionId`, `activityInstanceId`, `itemInstanceId`, `operationId`, UTC occurrence time, positive attempt ordinal. Allocate once at logical action capture; freeze across retries. Authority supplies actor lineage, recording time and consent context. |
| Instruction | `instructionalTrack` = phonics or story; stable `objectiveId` + `objectiveRevision`; `sequenceId/revision`; `itemId/revision` + item-family identity; all resolve in the admitted artifact. Trial form/transfer-item identity remains separate from training item identity. |
| Interaction | A versioned interaction ID (select, type, arrange, copy, oral-observation, listen/read exposure, etc.), actual response modality, language direction and response representation. An interaction never implies the instructional objective. IDs require a reviewed registry before production admission; examples here are descriptive, not new native mode registrations. |
| Target | Exactly one tagged union member from §4, with immutable content pins. No fallback target and no dummy vocabulary ID. |
| Response | Explicit presence = captured / none / unknown; tagged response value or bounded reference and encoding version. A selected option is an item-scoped option ID; typed text preserves original text and records normalization/accepted-variant rule identity separately; arrangements retain ordered token identity. Do not store arbitrary JSON supplied by a widget. |
| Outcome | Exactly one §5 outcome, reason code where required, observation/evaluation provenance and rule/rubric revision when evaluated. The UI cannot declare a canonical grade. |
| Conditions | Instructional artifact identity/checksum; support-policy revision and ordered support-use observations; stimulus modality and response modality; actual media identity/revision/checksum or explicit none/unavailable/unknown; material availability and condition validity. Intended media and actually delivered media are distinct. |
| Claim / eligibility | `classificationStatus` = pending / resolved; resolved evidence declaration and permitted claim IDs issued by the canonical classifier against pinned objective/rule/conditions. Pending is non-scoring. A claim is specific to a construct and conditions; it is not a new mastery flag. |
| Privacy | Provider/observer provenance, observation method, consent and retention classification supplied by canonical authorities. Prefer bounded outcome/rubric codes over raw voice. No recording is required for direct qualified human observation; no consent or observer means unobserved, not failed. |

Strict known-key decoding and discriminant validation apply to the new codec. Unknown schema is unsupported, not legacy. Proposed limits reuse the existing 197-character source evidence budget, 256-character identifier budget and positive attempt limit where applicable, but every derived ID must also fit the canonical budget. Duration may be null; never infer zero from unknown. Reuse canonical UTC-second event representation where the existing event layer requires it; preserve separate measured response duration. Proposed design ceilings: canonical UTF-8 record 64 KiB, captured text 8 KiB, 64 support observations, 16 media references and 256 ordered response tokens; the admitted item may impose smaller limits. Binary media is never embedded. These are conservative design limits, not measured content capacity or current server guarantees; implementation must verify them against transport and representative reviewed content. Exceeding a limit is explicit rejection, never silent truncation.

Version axes are independent: observation schema, objective/rubric, instructional sequence/item, content manifest, media, normalization, classifier/eligibility, envelope payload and projection-applied version. No single string silently substitutes for all of them. Canonical content identity uses integer revision; any EvidenceContext contentRevision string must be produced by a documented canonical mapping, not a lossy ad-hoc cast.

## 4. Target union and content admission

| Target kind | Identity and authority | What it does not mean |
| --- | --- | --- |
| word | Existing canonical vocabulary ID plus exact lexical content revision/checksum, owner-access/pinned-content authority | A spelling string, deleted foreign word, or fabricated ID is not an admissible reference. A word target alone does not establish recall, pronunciation or decoding. |
| phoneme | Stable phoneme ID in a pinned inventory ID/revision/checksum and accent/language identity; item pins its grapheme mapping and ordered sequence as applicable | Never use Unicode character count as sound count, a TTS letter name as phoneme media, or a fabricated word row to satisfy a FK. Multi-phoneme objectives pin the ordered inventory members in the item. |
| story | Stable document/story ID and exact revision/checksum inside the admitted artifact; question/evidence span IDs belong to the pinned item | Document completion/reading position is exposure or navigation, not a comprehension answer. Do not attach one arbitrary word as a proxy for the story. |

Reuse ContentQualityPolicy to authenticate the existing manifest container, then a new strict instructional codec verifies inventory/story/item/support references and required media. The current lexical codec is insufficient for these references. A reviewed manifest container does not imply the media, rubric or phoneme mapping has been reviewed.

At session admission freeze a content/sequence snapshot; re-entry revalidates access and exact pins. A new revision cannot reinterpret old responses. Missing/retired/inaccessible assets return an explicit unavailable path with other learning routes available. A missing phoneme clip never silently falls back to device letter-name TTS. Private prototype drafts can be inspected but do not become production learning evidence.

## 5. Outcome algebra and allowed inference

| Outcome | Admission meaning | Projection treatment |
| --- | --- | --- |
| correct | An observed valid response meets the pinned criterion, with permitted evaluator and conditions | Only policy-eligible evidence contributes to its specific construct. Correct is not automatic mastery/SRS/reward. |
| wrong | An observed valid response fails that criterion under valid conditions | Counts only in the corresponding eligible assessed denominator. Never use for unavailable media, refusal or timeout without observation. |
| skipped | Learner explicitly chooses to skip this item | Progress/history may record the action; no correctness denominator or failed answer. |
| unobserved | No admissible observation, e.g. no qualified observer, declined voice observation, no response, or indeterminate delivery | Null assessment, reason retained; no inferred inability. Any exposure/effort claim requires its own actual evidence. |
| invalid | A response/observation exists but conditions or instrument make its evaluation unusable | Reason retained, excluded from assessment denominator; not the same as malformed command rejection. |

Legacy `unknown` is a read-side knowledge state (§8), not a learner-selected outcome and not a manufactured observation. Partial/rubric dimensions may be retained with the pinned rubric; do not flatten an open-ended story response to correct/wrong until that rubric actually supports the decision. Pending grading remains unobserved for the assessed outcome with an explicit pending reason; later assessment is a new linked immutable evaluation operation, not an edit of history. Linkage/supersession must be validated to prevent double counting; exact correction policy remains an implementation prerequisite.

`evidenceKind` separates machine-validated, human-reviewed and self-reported. ASR confidence is not an oral-decoding grade. Copying or selecting a word is not oral reading; transcript-supported listening must preserve that condition. A picture can be intended story context yet reveal a phonics answer. Therefore `supportUsed` records type, identity, phase/order (before/after response) and purpose relative to the pinned support policy; `none` requires known absence, whereas `unknown` records missing history. HintLevel 0 alone is never proof of no support.

For resolved declarations reuse valid frozen EvidenceContext V1 only for its existing semantics. Current declared non-legacy contexts require protocol/experiment/assignment/consent metadata; local baseline learning must not fabricate these fields or activate research. Use the existing canonical context provider and valid local classification path, and keep new fields in the new record. Feature-contract identity remains validated rather than a hand-written placeholder. Pending/new outcome metadata lives in the new record, not extra keys in EvidenceContext. The classifier must not assign independentRecall merely because a target is a word or a response is typed. New non-binary/phoneme/story records cannot enter the old answer adapter. Unapproved constructs have no mastery projection. SRS remains owner+word and requires an explicitly eligible lexical memory observation; no phoneme/story row is passed to rebuildWord. Non-assessed outcomes cannot generate XP/coins/quests by pretending to be binary answers. Actual active effort/history, if allowed, use their canonical policy rather than invented correctness.

## 6. Canonical transaction and replay protocol (future implementation)

1. Admit a session through the learning application/repository with exact content and owner. Capture a fresh OwnerGeneration capability at resume; do not serialize its in-memory token. Freeze the response operation identity before an asynchronous observation/evaluation begins.
2. Validate shape/version, session/item/target membership, owner access, current generation and consent. Bind canonical lease/owner checks at the durable write boundary, not only in the UI. OwnerOperationGate is a lease, not an idempotency key.
3. On retry, look up the immutable source under the original owner lineage. Same identity and identical canonical content returns the original result; changed target, response, rubric, support or actor rejects identity conflict. Do not regenerate occurrence time, bind the current owner or reinterpret under a newer policy. A replay must remain read-only even if its old session is now complete; a new first write still requires an admissible active session.
4. For a new source, transactionally store observation, immutable event/outbox and resolved-or-pending decision state. A crash must leave either none or a recoverable canonical record, not a UI-only success. A proposed unique `(owner, operationId)` plus global source identity must be checked for contradictory binding. One logical response has one source; a real new attempt has a new operation. A transport retry does not increment attempt ordinal.
5. Extend the existing learning event store resolver and projection decision machinery deliberately. Only authenticated sources may drive the session/progress rebuilders or existing side-effect reconciler. Unknown/pending/invalid cases are fail-closed for scoring. Record projection receipts with applied/notApplicable/blocked semantics; retries cannot regrant effects.
6. Preserve current lexical paths, identities and receipts unchanged. A future read-only legacy adapter can expose comparable information; do not dual-write the same observation as a new record and an old AnswerAttempt. That would double count and fabricate a binary fact.

Existing `learning-event:…`, `learning-attempt:…:v2`, `attempt:…:1` and current projection-applied version 2 are not reassigned. Proposed new derivations are `instructional-event:{sourceEvidenceId}`, `instructional-observation:{sourceEvidenceId}:v1` for envelope idempotency and `instructional-observation:{sourceEvidenceId}:1` for outbox operation, with outbox entity type `instructionalObservation`. They fit the 256-character ceiling with the existing 197-character source budget. Their future definitions belong in LearningEvidenceContract and require collision/length and consumer compatibility proof before writing. A separate immutable evaluation uses its own source ID and explicitly references its observation; neither source ID is recycled. This is a proposed naming decision, not registration in the production system or allocation of a database version.

## 7. Upgrade, migration, sync and rollback obligations

Current AppDatabase source reports schema **34**. This draft allocates no next schema number. Preferred later storage is additive canonical observation/evaluation tables or an equally strict versioned store alongside unchanged AnswerAttempts, not making its word FK nullable and teaching old code to guess.

Before rollout, prove: upgrade from supported real schemas; no rewrite of existing attempt/event/decision/outbox bytes; transaction crash/restart; session completion races; same-operation retry versus conflicting replay; owner switch and guest-to-account upgrade with content collisions; retained actor lineage; unavailable target/media; unknown-version offline queue; export/import/delete completeness; actual backup/restore with SQLite/WAL/SHM handled according to device state. Register every new owner-scoped table/artifact in OwnerLifecycleManifest and actual archive/deletion/upgrade consumers; adding only a descriptor is insufficient.

Hosted synchronization needs a versioned entity/payload codec, validation, transport allowlist, acknowledgement and deduplication support before any observation enters its outbox. Unsupported clients must not turn observations into attempts or drop them silently. Keep unsent sources durable and show a compatibility condition. No hosted acceptance follows from a local payload example.

Rollback: disable new admission first, preserve already-written observations/events/receipts/outbox and their reader, and retain a forward-compatible database. An older binary that cannot read the new schema must be refused or receive an explicitly supported compatible build. Restoring a pre-upgrade backup after new writes would lose learner work and is not a valid ordinary rollback. Reversal/repair of projections must be versioned and reconciled, never by clearing ledgers or editing accepted events. Actual reversible upgrade/restore evidence is a later gate, not supplied here.

## 8. Legacy unknown mapping

| Current fact | Proposed read-side view | Preservation rule |
| --- | --- | --- |
| AnswerAttempt with real wordId/isCorrect | word target; original binary result and provenance retained | It supports only what the historical policy declared; no new phonics/story objective inferred. |
| Frozen v13 legacy context | original `legacy-unspecified`, `legacy-unknown`, `legacyInferred`, sentinel and compatibility behavior retained | Its hintLevel 0 does not prove no support. No backfill of media/modality/reviewer or independent decoding. |
| Versioned declared EvidenceContext | preserve known skill/content/policy/feature and any assessment fields | Newly absent dimensions remain individually unknown. Do not erase known fields or relabel the whole record. |
| Reading checkpoint/completed event | exposure/navigation facts, document revision and known position | Never fabricate comprehension correct/wrong, response or trial outcome. |
| Prototype/manual self-report | draft or self-reported provenance only | Never import as committed learner assessment or claim a real participant result. |

Unknown is represented by explicit knowledge status plus no inferred value in the read model. Do not conflate unknown with known-none, zero, skipped or wrong. Legacy runtime projection compatibility remains frozen; stricter new reporting can exclude unknown conditions without rewriting old scores or receipt meaning. No historical rescore or retroactive mastery promotion is authorized.

## 9. Decisions and remaining prerequisites

Structural decisions resolved for this proposal: tagged targets; objective separate from interaction; five non-conflated outcomes; strict new payload namespace; preserved EvidenceContext/envelope contracts; one canonical repository/resolver/receipt route; immutable replay; explicit legacy unknown; additive migration preference and data-preserving rollback.

Content/reviewer decisions remain OPEN: phoneme inventory/accent and grapheme sequence; reviewed audio/rights/checksums; which supports are intended versus answer-revealing; objective-specific allowed claims and rubric dimensions; accepted variants/normalization; trial forms/transfer items and observer qualification. These cannot be manufactured from source code.

Engineering implementation obligations remain OPEN: confirm the proposed event/entity names and size budgets against actual codecs/transport; implement evaluation-link uniqueness and authenticated append-only correction; allocate migration version/DDL and complete lifecycle/export/sync integration; pin classifier configuration and per-projection dispositions from reviewed constructs; prove compatible client rollout. For an evaluation correction, the proposed rule is one accepted successor per evaluated revision, same owner/item/observation, authorized evaluator, explicit reason and a monotonic evaluation revision; concurrent/conflicting successors reject, and only the canonical latest accepted revision contributes. Older evaluations remain readable and cannot be independently replayed for rewards. These rules require implementation proof, not further speculative schema changes in this package. The document does not claim a deployed interface or fully reviewed instructional specification.

Review acceptance for S01-Z is source/design consistency only: references resolve, current APIs are distinguished from proposed ones, every required dimension has a contract and owner, legacy semantics remain intact, and future proofs are explicit. No tests that merely restate this Markdown, no mock learning payloads, and no unchanged Y gate rerun. Relevant domain/migration/replay/native tests are required when an implementation is separately admitted. Reviewers can assess this draft before that admission.
