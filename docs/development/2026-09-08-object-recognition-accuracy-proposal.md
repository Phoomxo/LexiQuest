# แนวทางเพิ่มความแม่นยำกล้องเรียนคำศัพท์

สถานะ: ข้อเสนอการพัฒนา ไม่ใช่ผลทดสอบความแม่นยำหรือการอนุมัติฝึก/เผยแพร่โมเดลใหม่

ผู้ใช้เลือกของใช้ในห้องเรียน/บ้านและเครื่องมือช่าง โดยเริ่มจากรายการจำกัด เมื่อ 8 กันยายน 2026 เป้าหมายคือคำตอบถูกต้องจริงมากกว่า 90% และคะแนนความมั่นใจที่เชื่อถือได้ ภาพและคำตอบของผู้ใช้ใน UAT ไม่ใช่ชุดข้อมูลฝึกโดยอัตโนมัติ

## ข้อค้นพบจากระบบปัจจุบัน

- โมเดลที่รันจริงเป็น MobileNet V1 ImageNet แบบ quantized จำแนกภาพที่ครอปกลางและย่อเหลือ 224×224 ไม่มีกรอบตำแหน่งวัตถุให้แยกสิ่งของหลายชิ้น
- บน vivo เห็นภาพสดและผล `joystick 34%` ขณะที่วัตถุที่ถือในภาพดูเป็นไขควง จึงยืนยันการรับภาพ/รันโมเดลได้ แต่ยังไม่รับรองการระบุวัตถุ
- พบข้อบกพร่องก่อนการฝึกใหม่: baseline ของ `ObjectVocabularyDatabase.lookupByMlLabel` ใช้ substring สองทิศทาง ทำให้ `screwdriver` ตรงกับ `River` ได้ โมเดลมี screwdriver อยู่แล้ว แต่คลังคำศัพท์ยังไม่มีรายการ screwdriver ข้อบกพร่องนี้แยกจากการที่โมเดลตอบ joystick ขณะจัดทำข้อเสนอนี้แก้ source เป็น exact/alias ที่ตรวจแล้วและผ่าน focused tests 34 กรณี ยังต้องใช้ APK ใหม่จึงจะได้พฤติกรรมที่แก้บน vivo
- คำว่า invalidImage ใช้ร่วมกันทั้งถอดรหัสภาพไม่ได้และโมเดลตอบด้วยความมั่นใจต่ำ จึงยังแยกเหตุจากข้อความนั้นเพียงอย่างเดียวไม่ได้
- Native model execution/shape/checksum tests ที่ผ่านแล้วไม่ใช่การวัดความแม่นยำบนภาพสิ่งของจริง

## ขอบเขตรอบแรกที่เสนอ

ประมาณ 30 ชนิด แบ่งกลุ่มละ 15 ชนิด รายการด้านล่างเป็นร่างสำหรับเลือกตามประโยชน์การเรียนและภาพที่หาได้ ไม่ถือว่าโมเดลปัจจุบันรองรับครบ

| กลุ่ม | รายการตั้งต้น |
| --- | --- |
| ห้องเรียนและบ้าน | ปากกา ดินสอ ยางลบ ไม้บรรทัด สมุด หนังสือ กรรไกร กระเป๋าเป้ ขวดน้ำ แก้ว ช้อน ส้อม จาน เก้าอี้ ที่เย็บกระดาษ |
| เครื่องมือและอุปกรณ์ | ไขควง ค้อน คีม ประแจ ตลับเมตร คัตเตอร์ สกรู ตะปู นอตตัวเมีย สลักเกลียว แปรงทาสี ลูกกลิ้งทาสี สว่าน ระดับน้ำ เลื่อย |

กำหนดความละเอียดของแต่ละชนิดให้ชัดก่อนติดป้าย เช่น รอบแรกใช้ screwdriver รวม ยังไม่บังคับแยกชนิดหัว ส่วน screw/bolt/nut ต้องมีคู่มือระบุชื่อและตรวจความสม่ำเสมอของผู้ติดป้าย หากข้อมูลไม่พอให้ปรับขอบเขตอย่างเปิดเผย ไม่รวมชนิดยากเข้าหากันหลังเห็นชุดสอบเพื่อให้คะแนนผ่าน

## ลำดับการพัฒนา

1. **แก้ผลคำศัพท์และสร้างค่าตั้งต้น** — ใช้ชื่อที่ตรงกันหรือ alias ที่ตรวจความหมายแล้วเท่านั้น ชื่อไม่รู้จักต้องไม่กลายเป็นคำอื่น สอบโมเดลเดิมกับรายการเป้าหมายและรายงานแยกความผิดของภาพ/โมเดล/คำแปล สำหรับ flow รุ่นใหม่ต้องแยกคำทำนายอันดับแรกกับคำแนะนำอันดับรอง ไม่เลื่อนคำอันดับรองเป็นคำตอบหลักเพียงเพราะมีคำแปลในคลัง ปัจจุบันมีพฤติกรรมเลือก mapped label จาก top-10 ซึ่งต้องประเมินผลกระทบก่อนเปลี่ยน
2. **ช่วยให้ถ่ายวัตถุที่ต้องการได้ชัด** — แสดงกรอบเล็งหรือให้เลือกพื้นที่ของวัตถุ ใช้พื้นที่เดียวกันทั้งภาพตัวอย่างและภาพที่ส่งเข้าโมเดล ตรวจภาพมืด/เบลอแล้วบอกวิธีถ่ายใหม่ ถ้าภาพมีหลายชิ้นให้ผู้ใช้เลือกเป้าหมาย ไม่สรุปว่าชิ้นใดสำคัญจากความมั่นใจสูงสุดอย่างเดียว
3. **จัดข้อมูลจริง** — ใช้หลายชิ้น หลายยี่ห้อ หลายห้อง หลายมุม แสง และพื้นหลัง รวมสิ่งที่หน้าตาคล้ายกันและของนอกขอบเขต ตั้งต้นภาพฝึกประมาณ 200–500 ภาพต่อชนิดเป็นงบทดลอง ไม่ใช่จำนวนที่รับประกัน 90%; ปรับตามผลและความหลากหลาย เพิ่มแสง/มุมแบบสมจริงเฉพาะชุดฝึก แยก train/validation/test ตามวัตถุจริงและรอบถ่ายก่อนเพิ่มภาพ ห้ามเฟรมใกล้กันหรือภาพครอปจากภาพเดียวกันข้ามชุด
4. **ฝึกต่อจากโมเดลสำเร็จรูป** — เปรียบเทียบโมเดลเดิมที่แก้ pipeline แล้วกับ MobileNetV3 Small/Large ที่ fine-tune สำหรับกลุ่มเป้าหมาย โดยใช้ชุดสอบเดียวกัน การ transfer learning ใช้ความรู้ภาพเดิมแล้วปรับกับโจทย์เฉพาะ ไม่ต้องฝึกจากศูนย์ [TensorFlow](https://www.tensorflow.org/tutorials/images/transfer_learning), [Keras MobileNet](https://keras.io/api/applications/mobilenet/)
5. **เพิ่มการหาตำแหน่งเมื่อจำเป็น** — ถ้ากรอบเล็งยังแยกฉากรก/หลายวัตถุไม่ได้ ให้ทดลอง detector ที่ฝึกกับรายการเป้าหมายและกล่องวัตถุจริง เทียบกับแนวทางครอปก่อนเลือก ไม่เพิ่มโมเดลสองตัวโดยไม่มีหลักฐานว่าคุ้มกับความช้า/หน่วยความจำ โมเดล COCO สำเร็จรูปไม่ได้ครอบคลุมเครื่องมือทุกชนิดโดยอัตโนมัติ [Google Object Detector](https://developers.google.com/edge/mediapipe/solutions/vision/object_detector)
6. **ทำให้คะแนนความมั่นใจสอดคล้องกับความถูกต้อง** — ปรับ calibration บน validation แยกจากชุดฝึกและชุดสอบ เช่น temperature scaling แล้วเลือกเกณฑ์ตอบ/ไม่ตอบต่อชนิด ทดสอบของนอกขอบเขตด้วย ไม่เพิ่มคะแนนที่แสดงหรือปรับ threshold เพื่อทำให้ภาพเดิมดูผ่าน Calibration ไม่ได้แก้คำทำนายผิดหรือรับประกันข้อมูลสภาพแวดล้อมใหม่ [งานวิจัย ICML](https://proceedings.mlr.press/v70/guo17a.html)
7. **สอบไฟล์ที่ส่งลงมือถือจริง** — สอบหลังแปลง/quantize อีกครั้ง รวมคุณภาพภาพ คำศัพท์ ภาษาไทย ความเร็ว หน่วยความจำ ความร้อน ออฟไลน์ และการพัก/กลับแอปบน vivo ใช้การดาวน์โหลด/ตรวจ hash/สลับรุ่น/ย้อนกลับตามระบบเดิม และเพิ่มสัญญา input/output ของรุ่นใหม่อย่างชัดเจน ไม่เพียงเปลี่ยนชื่อไฟล์แล้วผ่าน validator เดิม [LiteRT quantization](https://developers.google.com/edge/litert/conversion/tensorflow/quantization/post_training_integer_quant)

ข้อจำกัดทางเทคนิคที่ต้องแก้ตามรุ่น: adapter ปัจจุบันใช้ raw RGB224 และ Uint8List สำหรับ input/output, ตัด index 0 เป็น background แบบตายตัว ยังไม่รองรับ logits/float/detector เพียงเพราะ enum ระบุชนิดนั้น โมเดลใหม่ต้องประกาศความหมายของ score, reserved class และ preprocessing ให้ตรงกัน และ reject รูปแบบที่ runtime ยังไม่รองรับ ผูก model SHA, label/taxonomy version, preprocessing, calibration และ threshold เข้ากับรุ่นเดียวกันทั้งตอนสอบและย้อนกลับ

เลือก architecture, ขนาดภาพ, ROI, augmentation, calibration และ threshold จาก development/validation เท่านั้น แล้ว freeze ก่อนเปิด final test ใช้ชุดสอบเดียวกันเปรียบเทียบรุ่นที่ freeze แล้วได้ แต่ถ้านำข้อผิดพลาดจากชุดนั้นไปปรับโมเดล ชุดนั้นกลายเป็นข้อมูลพัฒนาและต้องมีชุดสอบอิสระใหม่

ประเมิน calibration ของไฟล์ quantized ที่ส่งลงมือถือจริง โดยแสดงอัตราตอบถูกในแต่ละช่วงคะแนน จำนวนผลในแต่ละช่วง และช่วงความเชื่อมั่น หากช่วง ≥90% มีตัวอย่างน้อยให้ระบุว่าหลักฐานยังไม่พอ ไม่ใช้ค่าเฉลี่ยจากโมเดล float หรือชุด calibration เองมารับรองแทน

## เกณฑ์รับงานที่เสนอ

| เกณฑ์ | การตัดสิน |
| --- | --- |
| คำตอบถูกจริง | อันดับแรกถูก >90% บนชุดสอบอิสระที่เป็นตัวแทนงานจริง รายงานทั้งรวม รายกลุ่ม และรายชนิด พร้อมจำนวนภาพและช่วงความเชื่อมั่น ไม่ใช้ accuracy ตอนฝึก |
| คำตอบที่ระบบสรุปให้ผู้ใช้ | ตั้งเป้า precision อย่างน้อย 95% และรายงาน coverage แยก หากตอบถูกเฉพาะภาพง่ายแต่ปฏิเสธส่วนใหญ่ ห้ามอ้างว่าระบบตอบถูก >90% ของการใช้งานทั้งหมด |
| ความสำเร็จในการใช้งาน | รายงานคำตอบถูกต่อการถ่ายทั้งหมดในขอบเขต รวมจำนวนถ่ายใหม่/ไม่ตอบเป็นผลที่ยังไม่สำเร็จ แยกจาก accuracy ของตัวจำแนก เพื่อเห็นความยุ่งยากที่ผู้ใช้เจอจริง |
| คะแนน ≥90% | ตรวจว่ากลุ่มผลที่แสดงคะแนนระดับนี้มีอัตราตอบถูกสอดคล้องกันบนชุดสอบ ไม่ใช่ยกเลขความมั่นใจทุกภาพให้เกิน 90% |
| ของที่ไม่รู้จัก | สอบแยกภาพนอกขอบเขต ฉากว่าง หลายวัตถุ ภาพมืด และของหน้าตาคล้ายกัน วัดอัตราตอบผิดแต่มั่นใจสูง |
| ผลด้านการเรียน | คำอังกฤษ–ไทยตรงวัตถุและผ่านการตรวจชื่อ ไม่มีการบันทึกคำผิดอัตโนมัติ การยืนยัน/แก้ไขของผู้ใช้เป็นคนละหลักฐานกับโมเดลตอบถูกเอง |

เกณฑ์ตัวเลขเป็นเป้าหมายการรับงาน ต้องทดลองก่อนรับรอง และไม่รับประกันว่าสามารถระบุวัตถุทุกอย่างทุกภาพบนโลกได้เกิน 90% หากต้องอ้างความแม่นยำของประชากรเกิน 90% ควรใช้ขอบล่างช่วงความเชื่อมั่นที่กำหนดล่วงหน้า พร้อมชุดสอบที่ใหญ่และเป็นอิสระพอ

นิยามตัวหารก่อนเก็บชุดสอบ: ให้ N เป็นการถ่ายทั้งหมดของงานในขอบเขตที่กำหนดล่วงหน้า รวมภาพที่ quality gate ขอให้ถ่ายใหม่, A เป็นครั้งที่ระบบสรุปคำตอบเอง และ C เป็นคำตอบเหล่านั้นที่ถูกต้อง จะได้ precision = C/A, coverage = A/N และความสำเร็จต่อการถ่าย = C/N ส่วนความสำเร็จหลังถ่ายใหม่หรือผู้ใช้เลือกคำให้ต้องรายงานแยก และห้ามนับเป็นโมเดลตอบถูกเอง เป้าหมาย >90% ของการถ่ายทั้งหมดหมายถึง C/N >0.90 ซึ่งเข้มกว่าการมี precision >90% เพียงอย่างเดียว

ก่อนเริ่มรอบฝึกจริง ต้องล็อกจำนวนสอบต่อชนิด จำนวนวัตถุคนละชิ้น/ฉาก/อุปกรณ์ ระดับช่วงความเชื่อมั่น (เสนอ 95%) และ coverage ขั้นต่ำจาก pilot พร้อมคำนึงถึงภาพหลายภาพจากวัตถุชิ้นเดียวที่ไม่เป็นอิสระ ข้อเสนอนี้ยังไม่ใช่ acceptance protocol ที่มี sample budget ผ่านการตกลงครบแล้ว

## ผลต่อ workflow เดิมและแรงจูงใจ

เส้นทางยังเป็น ถ่ายรูป → ตรวจ/ยืนยันสิ่งของ → ดูคำศัพท์ → ฟัง/ฝึกพูด → บันทึกด้วยระบบคำศัพท์เดิม เปลี่ยนการเตรียมภาพ การระบุวัตถุ และความชัดเจนของผล ใช้ authority การเรียน/รางวัลเดิม เมื่อระบบไม่แน่ใจให้บอก “ยังไม่แน่ใจ ลองถ่ายใกล้ขึ้น” หรือให้เลือกคำที่ใช่ ไม่หักคะแนนเด็กเพราะโมเดลผิด และไม่นับคำที่เด็กช่วยเลือกเป็นการตอบถูกของโมเดล

หน้าผลหลักควรแสดงวัตถุที่เลือก ชื่ออังกฤษ–ไทย และปุ่มฟัง/ฝึกพูด ส่วนชื่อโมเดลและ CPU/XNNPACK เป็นรายละเอียดขั้นสูง ไม่ใช้เปอร์เซ็นต์ความมั่นใจของ AI เป็นคะแนนความสามารถของเด็ก แนวทางเริ่มต้นประมวลผลบนเครื่องเพื่อลดค่าใช้จ่ายต่อภาพและรองรับออฟไลน์หลังดาวน์โหลดโมเดล โดยต้องวัดทรัพยากรบนอุปกรณ์จริงก่อนเลือกขนาดโมเดล

ไม่มีการอัปโหลดภาพเด็ก เก็บภาพฝึก หรือส่งภาพไปบริการภายนอกโดยอัตโนมัติ การเพิ่มชุดข้อมูล/ค่าใช้จ่ายฝึก/บริการ cloud เป็นการตัดสินใจแยกจากการแก้บักกล้องที่อนุมัติไว้แล้ว ความคิดเห็นแก้คำต้องมีคนตรวจ ก่อนนำเข้าชุดฝึกในอนาคต

ข้อควรเลือกเครื่องมือจากข้อมูลล่าสุด: หน้า MediaPipe Model Maker ระบุว่าไม่ actively maintained แล้ว จึงไม่กำหนดให้เป็น dependency ของ pipeline ใหม่โดยอัตโนมัติ ใช้เอกสารนั้นเป็นตัวอย่างหลักการและรูปแบบข้อมูลเท่านั้น [เอกสารสถานะ](https://developers.google.com/edge/mediapipe/solutions/customization/object_detector)
