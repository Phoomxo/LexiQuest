## Design and compatibility

Keep F2's conservative frontend source closure and explicit Flutter selection.
Extend the existing runner rather than introducing a second runner or importing
main's release implementation. Backend closures now include CLI code and root
uv/Python configuration. Fingerprints retain base SHA, HEAD and raw file bytes;
they also digest environment variables (values are never emitted), executable
resolution and launcher bytes, Flutter/Dart SDK metadata, ignored Dart package
configuration, backend local environment configuration and pyvenv configuration.
Managed dependencies remain governed by lockfiles (`uv --frozen --group dev`,
with llm/gpu/train excluded). This is conservative local caching, not a hermetic
build guarantee against arbitrary modification of external package caches.

Result v2 records exact command arguments, source area, closure path/SHA256 rows,
environment digest, source fingerprint, timestamps and log paths/hashes.
Resume requires matching command identity and fingerprint, Passed with exit 0,
required metadata, and both logs present with matching hashes. Old v1 records
without these pins are rejected. Failed/missing/stale evidence cannot supply PASS.
An unrelated environment change may invalidate a result; correctness takes
priority over maximizing reuse. Hashing adds overhead to the synthetic regression.

`-PlanOnly` validates selection and command paths, emits `status: Planned` and
`runtimeVerified: false`, and does not create execution results or start tools.
`-CliOnly` is additive and valid only for Subsystem/Runtime without Flutter
selection; it runs the existing F2 regression and new behavioral regression.
Normal Runtime scope keeps its existing selection for compatibility.
Release execution now requires `-FrozenSha <full current HEAD>` and a clean
checkout. A plan-only Release does not require that attestation or execute release.
The caller must choose an actually frozen PR/release commit, not merely any clean
commit. No release verifier was executed here.
