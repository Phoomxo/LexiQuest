## สิ่งที่ผู้เริ่มต้นพบในระบบปัจจุบัน

- แท็บเรียนอยู่ลำดับแรก ในหน้าเรียนมีทางเข้ารอง วันนี้/แผนเรียน/Adventure ตาม gate และ dependency ที่พร้อม แล้วจึงการ์ด “เริ่มฝึกสั้น ๆ” และกลุ่ม จำคำศัพท์ / อ่านและประโยค / ฟังและพูด [C1–C2]
- ปุ่มเริ่มสั้นเลือก quiz→SRS→associative reading ตามความพร้อมของระบบ ไม่ใช่หลักฐานว่าจัดอันดับจากเป้าหมายเฉพาะคน แตะแล้วมีสรุปเนื้อหา จำนวนข้อ เวลา และวิธีตอบก่อน “เริ่มเรียน”; ปรับรายละเอียดได้โดยไม่บังคับเปิด [C2–C3]
- วันนี้อ่านกิจกรรมค้าง แบบประเมินที่ได้รับมอบหมายเมื่อมีสิทธิ์ งานทบทวน คำแนะนำ และความต่อเนื่อง ส่วน `planning` case ใน view นี้ยังไม่มีเนื้อหา ไม่ควรถือว่ามีแผนสัปดาห์เชื่อมครบแล้ว [C4]
- เป้าหมายที่อ่านมีชนิด ชื่อ deadline เขตเวลา และสถานะ; ไม่มีช่องตารางรายสัปดาห์ใน model นี้ UI ยังให้พิมพ์ UTC ISO กับชื่อเขตเวลาเอง และรายการมีข้อความ “เลยกำหนด … วัน” จึงเป็นจุดสะดุดชัดเจนสำหรับผู้ไม่รู้ศัพท์ระบบ [C5]
- ภาพรวมการเรียนแยกความชำนาญ การทบทวน เวลาเรียนจริง และความแม่นยำพร้อมจำนวนคำตอบแล้ว ร้านค้ามีการซื้อ/เลือกใช้งาน แต่บอกตรง ๆ ว่าปัจจุบันอุปกรณ์แสดงเป็นชื่อ ไม่มีภาพอุปกรณ์หรือธีมทั้งแอป [C6–C7]
- ภารกิจเดิมแสดงตัวอย่างรายวัน/รายสัปดาห์ที่อิงจำนวนคำตอบถูก การมีหน้าสถานะไม่เท่ากับมีระบบให้ผู้เรียนเลือกภารกิจหลากหลายแล้ว [C8]

## ความเสี่ยงสำคัญสามข้อ

1. **ตัวเลือกใหม่กลบปุ่มเริ่มเรียน:** เพิ่มการ์ดแผน ภารกิจ อวาตาร์ และเพื่อนบนหน้าเรียนทั้งหมดจะดันปุ่มหลักลงอีก เพราะ `leadingCards` ถูกวางก่อน starter จริง [C2] ขัดเป้าหมาย quickstart ของ UI ที่เพิ่งปรับเสร็จ [H7] ข้อเสนอ P1/P3/P5/P6 จึงควรใช้ทางรองเดิมและรวมเพียง next action บนเรียน
2. **แผนกลายเป็นภาระกับข้อความที่ผู้ใช้ไม่เข้าใจ:** UTC/Asia-Bangkok รวมถึง “หลักฐานยังไม่แข็งแรง” และ “กิจกรรมถูกจำกัดตามโปรโตคอล” อาจทำให้ผู้เริ่มต้นไม่ทราบว่าจะทำอะไรต่อ [C4–C5] P1/P4 ไม่ควรแค่ครอบ deadline เดิมด้วยรายการค้างรายสัปดาห์ ต้องใช้ปฏิทินท้องถิ่น อธิบายการกระทำถัดไป และเปิดรายละเอียดเหตุผลจริงได้ โดยไม่ซ่อนข้อจำกัดสิทธิ์
3. **รางวัล/ภาพสนุกทำให้ตีความว่าความรู้เพิ่ม:** P2/P5 ต้องไม่แปลงอวาตาร์ XP หรือจำนวนวันกลับมาเป็นคะแนนความชำนาญ ร้านค้ายังไม่มีภาพจริง [C7] และการฝึกพูดเสริมล่าสุดเป็นชั่วคราว ไม่มีคะแนน/หลักฐานรางวัลเพิ่ม [H8] ส่วน P6 ขัด non-goal ระยะแรกที่ไม่มี multiplayer/social network [H4] จึงเป็น scope decision ใหม่ ไม่ใช่เพียงปรับสำเนาข้อความ

## เกณฑ์ตรวจรับเสนอสามสถานการณ์

1. **ใหม่และไม่รู้ UTC:** ผู้ใช้ข้ามเป้าหมายและไม่เปิดปรับตัวเลือกยังเข้ากิจกรรมแรกได้ เมื่อเลือกตั้งเป้าหมาย ใช้ปฏิทินท้องถิ่นและเห็นสรุปถูกเขตเวลา; ที่ตัวอักษร 200% ยังเข้าถึงเริ่ม/ย้อนกลับได้ เป้าหมายการประเมินคือผู้ใช้บอกได้ว่าจะกดอะไรต่อ โดยไม่ให้ผู้ทดสอบสอนศัพท์ระบบ
2. **มีงานค้างและกลับหลังเจ็ดวัน:** เห็น next action เด่นหนึ่งรายการ ต่อของเดิมหรือเริ่มใหม่ได้โดยเข้าใจผล ไม่มีหนี้กิจกรรม/การตัดรางวัล/การเปิดเตือนอัตโนมัติ การย้อนหรือเปิดใหม่ไม่เพิ่มความก้าวหน้าและรางวัลซ้ำ
3. **ตอบแล้วฟัง/พูดซ้ำหรือข้าม:** สรุปอิงคำตอบที่บันทึกจริง ไม่มีคะแนนการออกเสียงหรือรางวัลจาก optional speech เมื่อไม่มีหลักฐานแสดง “ยังไม่มีข้อมูล” แทน 0; ปิดความสามารถแผน/เพื่อน/อวาตาร์ใหม่แล้วยังเรียนผ่านทางเดิมได้

ทั้งหมดเป็น acceptance scenarios ที่เสนอ ไม่ใช่ผลการทดสอบที่รันแล้ว

1. อ่าน `03-cross-review-brief.md`, `02-design-evidence.md` และ peer `U5-play-social.md`, `SA-architecture.md`, `QA-acceptance.md`; รับข้อกำหนด polished/familiar UX โดยไม่อนุมานอายุหลักที่ยังไม่ได้ยืนยัน
2. เปิดดูเองเฉพาะภาพ renderer เดิม Learn `build/verification/ui-implementation-20260908/visual/390x844-01-learning.png` และ shop `build/verification/ui-implementation-20260908/visual/390x844-06b-shop.png`; ไม่ได้ดูอีกสองภาพหรือหน้าจอโทรศัพท์
3. ภาพ Learn มี CTA สีน้ำเงินเด่น ห้าแท็บไทย และรายการโหมดซ้ำรูปแบบ; ภาพร้านใช้กล่องเงาหลายชุด มี icon/ชื่อ แต่ไม่มี preview ตัวละคร จึงมีฐานให้ปรับ polish โดยไม่ต้องเปลี่ยนโครงสร้างทั้งหมด
4. ข้อเห็นต่างที่หนึ่ง: U1 เดิมเลื่อนคอสเมติกหลังแผนสัปดาห์ ต่างจาก U5 ที่ให้ P5 ทำคู่กับ quickstart (`U5-play-social.md:10`); ยอมปรับเพราะร้านสร้างความคาดหวังเรื่องสิ่งที่เลือกใช้จริงแล้ว
5. รับภาพนิ่งจาก equipped/ownership ในพื้นที่รองหนึ่งแห่งพร้อมชื่อสำรอง; ยังไม่รับการขยายร้าน/ชุดลองจำนวนมากหรือการซื้อเป็นขั้นตอนบนทางเริ่ม ต้องไม่รอโหลดภาพจึงกดเรียนได้
6. ข้อเห็นต่างที่สอง: U1 เดิมเสนอแผนสัปดาห์ก่อนสรุปผล ต่างจาก SA ที่แยก projection กับ planning domain (`SA-architecture.md:34`–`:41`); ยอมเปลี่ยนลำดับ เพราะ title/deadline ยังไม่ยืนยันเนื้อหาที่ช่วยเป้าหมาย
7. ระยะแรกจึงใช้ชื่อ “เป้าหมายของคุณ” และ “รายการฝึก” ตามข้อมูลจริง ไม่เรียก “แผนเฉพาะบุคคล” หรือบอกว่าฝึกครบแล้วพร้อมสอบ; แผนที่ผูกเนื้อหา/เกิดซ้ำมีสัญญาและ acceptance ต่างหาก
8. เห็นด้วยกับ SA เรื่องแยก “เลือกกิจกรรมฝึก” จาก “เลือกรับภารกิจให้รางวัล” (`:25`); UI เสนอ safe modes เดิมได้ แต่ไม่ให้ bonus/Quest credit จากการเลือกหรือจาก optional speech/replay
9. รับข้อท้าทาย QA ว่าภาพสวยไม่แทนการกดและความเข้าใจ (`QA-acceptance.md:51`–`:59`); prototype ต้องมีทั้งหน้าพร้อมใช้และ empty/pending/error/disabled ก่อนเป็นเป้า implement
10. ความคุ้นเคยที่รับจาก Duolingo/ALLTCAS คือความสม่ำเสมอของหัวข้อ ระยะห่าง ปุ่ม และ feedback; ไม่รับเส้นทางหลักสูตร/ด่านปลดล็อกที่ข้อมูลจริงไม่รองรับ และไม่ถือว่าความนิยมพิสูจน์ว่าเด็กเราใช้เป็น
11. ขอบเขตแรกที่รับคือ Learn/Today หนึ่ง canonical next action เด่นและทางเลือกฝึกเดิม, goal picker ท้องถิ่น, result จากผลที่ commit จริง, gentle return และ static avatar แบบเลือกได้
12. Today ยุบคิวเป็นสรุปได้แต่ต้องเปิดรายการจริงได้และคง priority เดิม; ช่องอุปกรณ์ที่ยังไม่พร้อมห้ามดันงานค้าง/assigned/ทบทวนออกจากเส้นทางที่ควรเห็น
13. ไม่ยอมแลกห้าแท็บ ทางเรียนเดิม การขยายตัวอักษร ข้อมูล owner เดียว และสถานะยังไม่ยืนยัน เพื่อให้ภาพเรียบ; สี/เสียง/animation ไม่เป็นสัญญาณสำเร็จเพียงอย่างเดียวและไม่หน่วงปุ่มต่อ
14. เกณฑ์ชี้ขาดแรก: ทดสอบ prototype กับผู้ใช้ตัวแทนที่ยินยอมโดยไม่บอกตำแหน่งปุ่ม ให้เริ่ม–เลือกคำตอบ–อ่านผล–กลับเรียนเอง แล้วบันทึกความลังเล ความช่วยเหลือ และคำอธิบายด้วยคำของผู้ใช้จริง
15. ผู้ใช้ต้องแยกได้ว่า “ผลรอบนี้” “คำที่ควรทบทวน” และ “ของที่สวม” หมายถึงคนละเรื่อง; รายงานคำพูดจริงเมื่อมีการเก็บอย่างเหมาะสมเท่านั้น รอบนี้ไม่มีคำพูดผู้ใช้หรือผลทดสอบดังกล่าว
16. เกณฑ์ที่สอง: prototype/ภาพเป้าครอบคลุม 390×844/text100 และ 360×800/text200, keyboard/back, TalkBack order, reduced motion, offline/asset missing; ตรวจเส้นทางและปุ่มจริงควบคู่ภาพในงาน implementation
17. เกณฑ์ที่สาม: เปลี่ยน owner/เปิดซ้ำ/กลับหลังเจ็ดวันแล้วไม่มีภาพ งาน หรือเตือนของคนก่อน ไม่มีหนี้เรียนปลอม และไม่เพิ่ม answer/Quest/reward จากการแสดงภาพหรือ retry
18. P6 ระยะแรกเก็บปัญหาและทดสอบแนวคิดสังเคราะห์เท่านั้น ไม่สร้าง friend graph/บัญชีเด็ก/การส่งคำชวนจริง; ความยั่งยืนไม่เปลี่ยนเป้าหมายแก้ปัญหาเด็กเป็นยอดซื้อหรือยอดกลับแอป
19. ปรับข้อสรุป ตารางเส้นทาง และลำดับด้านบนให้ตรงกันแล้ว: polished UX กับความสนุกเล็กน้อยทำคู่กับการลดภาระได้; personalized weekly plan/recurrence/Quest ใหม่/social ต้องแยกตัดสิน ไม่อ้างว่าเสร็จจากการปรับ UI
20. ตรวจเอกสารนี้เท่านั้น ไม่มี source/test/build/UAT ใหม่; หลักฐานเดิมใช้ได้ตามรุ่นและขอบเขตเดิม การตรวจระบบหลัง UI เสร็จและการตรวจเครื่องจริงยังเป็น acceptance ของงาน implementation ในอนาคต
