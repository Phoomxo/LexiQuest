# U3 — ผู้ใหญ่ไทยที่กลับมาเรียนหลังพัก 1–3 สัปดาห์

วันที่ 8 กันยายน 2026 — วิเคราะห์จาก working tree `C:/Users/Phet/.codex/worktrees/02fa/LexiQuest`, branch `codex/pair-matching-pm0-pm8`, รวมงาน UI/contextual ที่ยังไม่ commit ตาม brief งานนี้อ่านโค้ดและเอกสารเท่านั้น ไม่รันแอป เทสต์ build หรือเปลี่ยน rollout มุมมองผู้เรียนเป็น persona จำลอง ไม่ใช่คำสัมภาษณ์ UAT หรือหลักฐานประสิทธิผลด้านแรงจูงใจ

รับคำชี้แจงล่าสุดว่าโครงการมุ่งแก้ปัญหาการเรียนของเด็กไทยก่อน ไม่ใช่รายได้ Persona ผู้ใหญ่ในรายงานนี้จึงเป็นกลุ่มรอง ใช้ท้าทายเรื่องเวลาที่ไม่แน่นอน ส่วนเด็กอาจหยุดจากการใช้เครื่องร่วมกัน อินเทอร์เน็ต กิจวัตรบ้าน หรือการดูแลของผู้ใหญ่ ซึ่งยังเป็นสมมติฐานที่ต้องตรวจจริง ห้ามตีความการหายไปว่าไม่พยายามหรือขาดวินัย หลักการกลับมาได้ง่าย/ไม่มีหนี้งาน/ไม่กดดันเพื่อนยิ่งต้องคงไว้สำหรับเด็ก และแผนหรือการเตือนต้องปรับตามความพร้อมโดยไม่ให้เด็กต้องอธิบายเรื่องส่วนตัวก่อนเรียน

## ข้อเสนอหลัก

สำหรับคนที่งานไม่เป็นเวลา สิ่งสำคัญที่สุดคือ “กลับมาแล้วเริ่มสิ่งเล็กที่เหมาะสมได้ทันที และหยุดได้โดยไม่รู้สึกติดหนี้” ให้ทำ P4 การกลับมาอย่างอ่อนโยนร่วมกับ P2 คำอธิบายพัฒนาการก่อน แล้วเชื่อม P1 เท่าที่ช่วยเลือกงานครั้งถัดไป ไม่ควรเปิดแผนรายสัปดาห์ ภารกิจใหม่ อวาตาร์ และเพื่อนพร้อมกันบนหน้าแรก คนกลุ่มนี้อาจมองสิ่งเหล่านั้นเป็นภาระเพิ่ม แม้ทุกส่วนจะสมัครใจก็ตาม

## สิ่งที่มีจริงและช่องว่าง

1. **Today มีลำดับงานและเหตุผลแล้ว แต่หน้าแรกอาจยาวมากหลังพัก**: reader เรียง resume → assigned → review → recommendation → planning → continuity และเก็บ goals/reminders/quests/streak ใน snapshot (`lib/features/today_hub/data/drift_today_hub_reader.dart:62–111`) การโหลด review ไม่ระบุ limit (`:196–208`) และ renderer เพิ่มการ์ด review ทุกคำ (`lib/screens/today_hub_view.dart:193–194`) ปุ่ม “เปิดรายการทบทวน” อยู่ท้ายรายการผ่าน `_childActions` (`:218`, `:416–450`) การ์ดคำบน Today มีเหตุผลและรายละเอียด แต่ไม่มีปุ่มเริ่มของตัวเอง (`:275–305`) ผู้มีคิวมากจึงต้องเลื่อนผ่านคำจำนวนมากเพื่อไปต่อ นี่เป็นความเสี่ยงด้านการเข้าถึงงานจากโค้ด ไม่ใช่การวัดความรู้สึกจริง

2. **Gentle Streak policy มี recovery อยู่แล้ว แต่ Today ไม่แสดงความหมายครบ**: `StreakPolicy.snapshot` เปลี่ยน phase เป็น recovery เมื่อวันห่างตั้งแต่ 2 วัน โดยไม่แก้ durable counters (`lib/features/motivation/domain/streak_policy.dart:102–136`) เมื่อมี eligible learning commit หลังพักนานจึงเริ่ม current streak ที่ 1 และเก็บ longest เดิม (`:90–98`) แต่ Today ส่งเพียง `currentStreakDays` เข้า `_streakCard` (`lib/screens/today_hub_view.dart:207–209`) และแสดง “ต่อเนื่อง X วัน” ทุก phase (`:393–408`) จึงอาจเห็นจำนวนเดิมก่อนกลับไปเรียน แล้วลดเหลือ 1 หลังเรียนสำเร็จ โดยไม่มีคำอธิบาย recovery/สถิติเดิมในหน้าดังกล่าว `GentleStreakCard` มี Welcome back/longest/Continue gently อยู่ (`lib/widgets/gentle_streak_card.dart:140–148`, `:91–98`) แต่การค้นการใช้งานใน `lib` พบเพียงประกาศของ widget ไม่พบการนำไปใช้ในหน้าปัจจุบัน ห้ามนับว่า Today มี flow นี้ครบแล้ว

3. **เป้าหมายเป็นรายการกับเส้นตาย ยังไม่ใช่แผนปฏิบัติ**: domain มี kind/title/deadline/status และ timezone (`lib/features/goals/domain/learning_goal.dart:35–44`, `:89–96`) หน้าจอแสดง “เหลือ/ครบกำหนดวันนี้/เลยกำหนด” (`lib/screens/learning_goals_screen.dart:185–197`) เปลี่ยนสถานะได้ แต่ยังไม่มี UI เลื่อนเส้นตาย (`:481–489`) แม้ snapshot โหลด planning แล้ว renderer กลับ `break` โดยไม่แสดงอะไร (`lib/screens/today_hub_view.dart:204–205`) การเชื่อมเป้าหมายกับ Today จึงเป็นช่องว่างจริง ส่วนตารางรายสัปดาห์ที่จำวัน/ปริมาณ/การเลื่อนงานเป็น capability เพิ่ม ต้องนิยามและใช้เจ้าของข้อมูลที่เหมาะสมก่อน

4. **Reminder สมัครใจและปิดได้ แต่การกรอกยังหนักสำหรับคนทั่วไป**: มีข้อความเมื่อปฏิเสธ permission ว่ายังเรียนได้ (`lib/screens/study_reminder_settings_screen.dart:82–90`) และปุ่มปิด (`:156–162`) แต่ต้องกรอก UTC แบบลงท้าย Z, timezone และ quiet hours เป็นนาทีหลังเที่ยงคืน (`:62–75`, `:165–195`) ผู้เรียนไทยที่ตารางเปลี่ยนไม่ควรต้องแปลงเวลาเอง การเปลี่ยนเป็นตัวเลือกวันเวลาไทยที่ส่งค่า UTC เดิมเป็นการลดแรงเสียดทานที่ชัดกว่าการเพิ่มระบบเตือนอีกตัว

5. **มีทางเลือกจำนวนข้อและ companion แต่ยังไม่ได้รับรู้การหายไปหลายสัปดาห์โดยตรง**: session configuration มีปุ่มเริ่มและซ่อนตัวเลือก พร้อมจำนวนข้อภายใต้ขอบเขต activity/protocol (`lib/features/learning/presentation/session_configuration_sheet.dart:296–330`) contextual companion ทั่วไปเป็น local scripts แค่เริ่ม/ลองใหม่หลังผิด/จบ (`lib/features/companion/domain/companion_reaction_catalog.dart:17–24`); Adventure ใช้ resumed เมื่อสถานะ paused → active (`lib/features/adventure/presentation/widgets/adventure_companion_panel.dart:24–26`) จึงไม่เท่ากับการตรวจการกลับมา 1–3 สัปดาห์ อย่าอ้างว่าระบบรู้เหตุผลที่หยุดหรือสภาพอารมณ์ของผู้เรียน

6. **Quest/อวาตาร์มีฐานแล้ว**: หน้าภารกิจแสดง daily-correct-5/weekly-correct-20 และจำนวนคำตอบถูก (`lib/screens/quest_status_screen.dart:142–191`) ใช้คำสำหรับ expired ว่า “ทำได้ในครั้งถัดไป” (`:221–225`) แต่เป็นหน้าสถานะ ไม่ใช่ตัวเลือก quest อวาตาร์แจ้งตามจริงว่าปัจจุบันแสดงชื่ออุปกรณ์ ไม่มีภาพอุปกรณ์หรือเปลี่ยนธีมทั้งแอป (`lib/screens/avatar_equipment_screen.dart:225`) ตรงรายงาน UI ล่าสุด (`docs/development/2026-09-08-approved-learner-ui-results.md:70`)

## ท้าทายข้อเสนอทั้งหกและจุดประนีประนอม

- **P1 goal → weekly plan: เห็นด้วยเฉพาะขนาดเล็กก่อน** ต้องเชื่อมเป้าหมายเดิมกับงานที่ทำได้จริง ไม่คัดลอก deadline เป็นอีก authority และไม่สร้าง “ยอดติดค้างรายสัปดาห์” วันที่ขาดไม่ควรเพิ่มงานวันถัดไปอัตโนมัติ สำหรับงานกลับมาใช้คำเชิญ “วันนี้สะดวกแค่ไหน” และการตั้งค่าครั้งนี้ก่อน หากเก็บ weekly availability/plan revisions ถาวร ให้ SA/BA ระบุ schema/lifecycle ต่างหาก ต้องไม่ให้ UI เปลี่ยน deadline ที่ผู้เรียนใช้สอบจริงเอง
- **P2 personal progress: ลำดับต้น แต่ต้องจริงและสั้น** อย่าบอกว่า “เก่งขึ้น” จาก XP, กลับมาเปิดแอป หรือข้ามข้อ การพักไม่ทำให้ประวัติที่บันทึกหาย แต่ไม่ได้ยืนยันว่าความจำไม่ลดลง ใช้ข้อเท็จจริงที่อ่านได้และ freshness ชัดเจน ปรับคำ “หลักฐานยังไม่แข็งแรง” บน Today (`lib/screens/today_hub_view.dart:501`) ให้ผู้เรียนเข้าใจว่าจะได้ฝึกอะไร โดยยังรักษา reason เดิม
- **P3 choice quests: เลื่อนไปหลังทางกลับมาที่ง่าย** รายการหลายแบบอาจเป็น choice overload และ “ตอบถูก N ข้อ” อาจไม่เหมาะกับคนเพิ่งกลับมา ห้ามแก้เป็น “ทำครบ N ข้อรับ XP” ผ่าน presentation เพราะจะเปลี่ยน canonical eligibility หากเพิ่มจริงให้เสนอไม่เกินตัวเลือกที่มีความหมายในครั้งเดียว เช่นทบทวน/ฝึกต่อ พร้อมทางเดิม; การเพิ่ม quest objectives เป็นการเปลี่ยน policy ที่ต้องออกแบบและตรวจเฉพาะ
- **P4 gentle comeback/reminders: ทำก่อน** ใช้ Streak snapshot ที่มีอยู่ พร้อมซ่อม Today presentation และ local-time form; ไม่สร้าง streak ใหม่ ไม่ขายหรือ grant streak repair ไม่แก้ SRS backlog เพื่อให้ตัวเลขสวย ไม่ใช้ภาษาว่าเพื่อน/companion ผิดหวังหรือรอเราอยู่
- **P5 visible cosmetics: คุณค่ารองสำหรับ persona นี้** อาจช่วยรู้สึกว่าของที่เลือกมีผลจริง แต่ทำเป็นการแสดงอุปกรณ์ที่ถือครองจาก Reward authority เดิม ไม่มี popup บังคับแต่งตัวก่อนเรียน ไม่เอาจำนวนครั้งกลับมาเป็นรางวัลใหม่โดยไม่มี policy ไม่ดันร้านค้าขึ้นก่อนปุ่มเรียน
- **P6 opt-in cooperative friends: ยังไม่ควรอยู่ในรอบแรก** การสมัครใจไม่ลบแรงกดดันจากการทำให้ทีมพลาด ผู้มีงานกะไม่ควรรับภาระว่าเพื่อนเสียโบนัสเพราะตนหายไป อีกทั้ง Adventure spec กำหนด friend/room/chat เป็น non-goal รุ่นแรก (`docs/superpowers/specs/2026-09-01-adventure-motivation-mode-design.md:79–94`) ถ้าทำภายหลังต้องเลือกเข้าร่วมเอง พัก/ออกโดยไม่เสียผลการเรียน ไม่เปิดเผย last-active/ความอ่อน/ตารางส่วนตัวตามปริยาย และไม่มี shared streak หรือเงื่อนไขรางวัลทีมที่ลงโทษคนหายไป

## ความต่อเนื่องกับพัฒนาการโครงการ

- V2 วาง recovery/reduced session ไว้แล้วและห้าม motivation เขียน mastery/reward โดยตรง (`docs/superpowers/specs/2026-08-03-lexiquest-v2-evolution-framework-design.md:106`, `:338–341`) งานนี้ควรทำเป้าหมายนั้นให้เห็นจริงในหน้าหลัก ไม่ย้อนใช้ prototype status เก่าเป็นสถานะปัจจุบัน
- Runtime convergence กำหนด learning authority และ projection ที่ rebuild ได้ (`docs/superpowers/specs/2026-08-08-lexiquest-complete-field-trial-convergence-design.md:63`); 8/44 ระบุ Quest, Gentle Streak และ Today ที่ไม่เป็นเจ้าของ progress (`docs/superpowers/specs/2026-08-14-lexiquest-alltcas-idea-integration-feature-contract-design.md:323–324`, `:352`) จึงไม่ควรเพิ่ม habit counter/weekly score อีกชุด
- Adventure รักษา Standard, ห้าม shame streak/hearts/forced timer และใช้ due/review ก่อน new work (`docs/superpowers/specs/2026-09-01-adventure-motivation-mode-design.md:17–24`, `:286–292`) การยุบ preview เป็น presentation เท่านั้น ต้องรักษางานที่มีสิทธิ์และเหตุผลเลือก ไม่ให้ P1 หรือ P3 แซง review โดยเงียบ ๆ
- Research engineering แยก product/research และ frozen envelope (`docs/development/2026-09-05-research-engineering-status.md:40–44`); Pair ยังใช้ engine/session/evidence เดิมและ Replay ไม่เป็น authority ใหม่ (`docs/development/2026-09-07-pair-matching-pm8-local-verification.md:17`) การช่วยกลับมาไม่ควรเปลี่ยนความหมาย replay หรือ grant จากการแวะหน้าผล
- Thai UI ได้ปรับข้อความ/ตัวเลือกแล้ว แต่ยังไม่ใช่ learner UAT (`docs/development/2026-09-08-approved-learner-ui-results.md:62`) contextual speech ล่าสุดเป็น optional ephemeral unscored หลังคำตอบหลัก (`docs/development/2026-09-08-contextual-practice-results.md:11–14`) การเลือก quest พูดต้องไม่เปลี่ยนสิ่งนี้เป็นหลักฐาน mastery/reward โดยปริยาย

## Acceptance scenarios ที่เสนอให้ตรวจในงาน implementation/UAT ภายหลัง

1. **พัก 14 วัน คิวทบทวน 120 คำ มีเซสชันค้าง**: เปิด Today ต้องมีข้อความกลับมาจาก phase จริง ปุ่มทำต่อกดถึงได้โดยไม่ต้องเลื่อนผ่าน 120 คำ; preview จำกัดแต่เปิดรายการเต็มได้; เมื่อเลือกครั้งใหม่ต้องจัดการ active session ผ่าน recovery flow เดิม ไม่ทิ้งหรือสร้างคู่ขนานอัตโนมัติ การเปิด/ยุบ/เลือกไม่เพิ่ม answer, SRS, XP, streak หรือ research rows; longest คงเดิมและ current จะเปลี่ยนตาม commit ที่มีสิทธิ์เท่านั้น
2. **กลับมาแล้วมีเวลาไม่แน่นอน เป้าหมายส่วนตัวเลยกำหนด**: ไม่มี onboarding แผนสัปดาห์บังคับ สามารถเริ่มขนาดที่ policy รองรับผ่านตัวเลือกเดิม หยุด/ข้ามเสียงเสริมแล้วกลับหน้าเดิมได้; เส้นตายไม่ถูกเลื่อนเอง ไม่มีหนี้งาน/รางวัลหายเพราะข้ามเสียง; ตั้งเตือนด้วยเวลา Asia/Bangkok และ quiet hours ที่เข้าใจได้ หรือปฏิเสธ permission แล้วเรียนต่อได้ ตรวจข้ามเที่ยงคืนและ reopen settings ว่าสื่อความหมายตรง schedule ที่บันทึกจริง
3. **กลับมาแบบ offline บัญชี A แล้วสลับ B**: แสดงความก้าวหน้าเฉพาะเจ้าของและสถานะข้อมูลที่มี ไม่มี inference จากบัญชีก่อนหน้า; ภารกิจ/อุปกรณ์/คำอธิบายที่ข้อมูลไม่พร้อมต้องไม่สร้างค่าแทน การลองเปิดซ้ำหรือ retry ผลไม่ซ้ำ reward/session; ผู้ไม่ร่วมวิจัยยังเรียนได้โดยไม่มี research rows/events/uploads และใช้ Standard ได้แม้ Adventure ไม่พร้อม

ผลตรวจรอบนี้จำกัดที่หลักฐานโค้ดและเอกสาร Acceptance ทั้งสามยังไม่ได้รัน ผลอัตโนมัติ 4,964 ผ่านในรายงาน contextual เป็นหลักฐานก่อนหน้า ไม่พิสูจน์ว่ากลุ่มผู้เรียนนี้เริ่มง่ายขึ้น กลับมาบ่อยขึ้น หรือเรียนได้ดีขึ้น ควรทำ comprehension/task UAT แยกจากการวัด motivation, retention และ learning outcomes

## Cross-review และข้อสรุปหลังโต้แย้ง

- อ่าน `U2-exam.md`, `BA-user-problems.md`, `DEV-integration.md`, `02-design-evidence.md` และ brief รอบโต้แย้งแล้ว ข้อสรุปนี้ปรับลำดับแรกให้ชัดกว่าข้อเสนอเริ่มต้น โดยยังไม่อนุมัติ implementation
- **เห็นต่างกับ U2 เรื่องน้ำหนักเส้นตาย:** การแสดง countdown เด่นทุกครั้งอาจเพิ่มภาระแก่คนกลับมา แต่ยอมรับคำทักท้วง U2 ว่าผู้เตรียมสอบต้องเห็นกำหนดจริง จึงใช้ “เป้าหมายของฉัน” ที่กางได้ ไม่ลบหรือเลื่อน deadline เพื่อให้ดูสบายขึ้น (`U2-exam.md:85`)
- **ยอมปรับจาก P4/P2 ก่อนทุกอย่าง:** ระยะแรกให้แสดง goal/deadline เดิมควบคู่กับทางกลับมาได้ เมื่ออยู่รองจาก canonical next action และผู้ไม่มี goal ยังเรียนได้ทันที ไม่ต้องกรอกแผนก่อนกลับไปเรียน
- **เห็นต่างกับถ้อยคำ P1 ของ BA:** เกณฑ์ว่าเด็กอธิบายได้ว่างานช่วยสิ่งที่เลือกอย่างไร ยังใช้ไม่ได้กับ goal ที่มีเพียง title/deadline เพราะอาจทำให้ UI แต่งเหตุผลเชื่อมสอบกับชุดคำเอง (`BA-user-problems.md:41`)
- รับข้อจำกัด DEV ว่า goal display ไม่ใช่ persistent weekly plan; ระยะแรกแสดงเป้าหมายกับงานวันนี้ตามข้อมูลจริงแยกกัน ส่วน goal-content binding, workload และการปรับแผนถาวรต้องมี contract/lifecycle ก่อน (`DEV-integration.md:10`, `:18`)
- **ยอมปรับตาม BA เรื่องเด็กไทย:** ผู้ใหญ่ในรายงานเป็นกลุ่มรอง; เครื่องร่วม เวลาที่บ้าน และอินเทอร์เน็ตเป็นสมมติฐานปัญหาของเด็กที่ต้องฟังจริง ไม่ใช่คำวินิจฉัยเหตุที่เด็กหายไป และไม่มีอายุหลักที่ผู้ใช้ยืนยันแล้ว (`BA-user-problems.md:29–33`)
- จึงไม่ถามเหตุผลส่วนตัวหรือให้เด็กแก้ตัวก่อนเรียนต่อ ไม่แสดงข้อความขาดวินัย/ค้างหนี้ และไม่ตั้งจำนวนวันต่อเนื่องเป็นเงื่อนไขได้เนื้อหาหรือความช่วยเหลือ
- **ยอมรับ DEV และแก้ความกำกวมของคำว่าเตือน:** ระยะแรกปรับ local date/time picker และ quiet hours สำหรับ reminder ครั้งเดียวเดิม; recurrence, exception, เลื่อนทั้งสัปดาห์เป็น policy เพิ่ม ต้องไม่แอบทำใน UI (`DEV-integration.md:21`)
- การแสดงเวลาไม่เปลี่ยน UTC instant เดิม; เปิด/ปิดเตือนต้องสมัครใจและผ่าน use case เดิม เมื่อ owner เปลี่ยนต้องล้างภาพ/งาน/preview เก่า พร้อม cancel หรือ reconcile OS reminder ตาม authority ที่เกี่ยวข้อง ไม่เพียงซ่อนการ์ด
- **ยอมปรับเรื่อง P5 จากลำดับรองเป็นทำควบคู่ได้:** รับ DEV/U2 ให้ภาพนิ่งขนาดเล็กจากของที่สวมจริงในหน้าตัวละครเป็นส่วนหนึ่งของ UI ที่เสร็จเรียบร้อย โดยไม่มี popup ก่อนเรียน ไม่มีโหลดทั้งร้าน และไม่เพิ่ม economy (`DEV-integration.md:9`, `:22`; `U2-exam.md:86–87`)
- รับทางเลือก 2 ของ design evidence: คงห้าแท็บ หนึ่งปุ่มหลักต่อจังหวะ ภาษาไทย ลำดับตัวอักษร/ระยะห่าง/ภาพที่สัมพันธ์กัน และ fallback ที่ยังดูเรียบร้อย ความเบาในการใช้งานไม่ใช่เหตุให้ปล่อยหน้าจอดิบ
- ความคุ้นเคยจาก Duolingo/ALLTCAS ให้นำมาใช้กับการมองหางานถัดไป ปุ่ม feedback และการเลือกงาน ไม่วาดหลักสูตร/ด่านปลดล็อกที่ไม่มี content progression รองรับ และไม่คัดลอก assets
- P3 ระยะแรกอนุญาตทางเลือกกิจกรรมเดิมจำนวนน้อยที่มีสิทธิ์ โดยรักษา resume/assigned/review และทางดูทั้งหมด; ยังไม่ใช่ quest ให้รางวัลใหม่ ไม่เปลี่ยน eligibility เพราะอยากให้ผู้กลับมาสำเร็จเร็ว
- P2 บอกสิ่งที่ทำจริงในครั้งนี้พร้อมชนิดหลักฐาน/จำนวนและสถานะบันทึกเมื่อข้อมูลมี; “เก่งขึ้น” หรือความจำคงทนต้องมีฐานเปรียบเทียบจริง รักษา optional speech เป็น ephemeral/unscored และ replay ตามกติกาเดิม
- **ระยะแรกที่ยอมรับ:** prototype Learn/Today, local-time form, lesson/result และ avatar states → Today recovery/ย่อ preview/goal display → local-time reminder เดิม → ผลจริงและภาพนิ่งที่เหมาะกับวัย โดยไม่มี weekly-plan store, recurring scheduler หรือ social ใหม่
- **Acceptance ด้านกลับมา:** fixture พัก 14 วันมี resume+assigned+120 due items ต้องเข้าถึง canonical action ในไม่เกินสองการกดหลังเข้า Today; preview ที่ยุบไม่เปลี่ยน IDs/ลำดับ/due dates และไม่มีการเริ่ม session/ให้ reward เพียงเปิดหน้า
- **Acceptance ด้านเครื่องร่วมและเวลา:** ทดสอบ A→B ทั้ง online/offline และ callback ที่กลับช้า ต้องไม่เห็น goal/ภาพ/notification ของ A; เลือกเวลาไทย เปิดใหม่และข้ามเที่ยงคืนยังตรง instant/quiet hours ที่บันทึก ปิด permission แล้วเรียนต่อได้
- **Acceptance ด้าน polish:** ก่อน implement ตรวจ prototype ด้วยข้อมูลจริงครบ empty/pending/error/retry และภาพ390×844/text100 กับ360×800/text200+keyboard; CTA/ชื่อแท็บไม่ถูกตัดหรือทับ มี reduced motion และภาพหาย fallback โดยไม่ลด text scaling
- ทำ task/comprehension UAT กับกลุ่มเป้าหมายที่ยินยอมภายหลัง ให้เริ่มต่อ ดูงานทั้งหมด และปิดเตือนได้โดยไม่บอกตำแหน่งปุ่ม บันทึกความลังเล/การช่วยเหลือ/ความรู้สึกต่อดีไซน์แยกจากคะแนนเรียน; automation และภาพเก่าไม่ตอบคำถามนี้
- **ไม่ยอมแลก:** ไม่มีหนี้รายสัปดาห์ การลงโทษเพื่อนที่หายไป shared streak บังคับ หรือ reward จาก UI; P6 เก็บความต้องการ/ต้นแบบแยกก่อน ไม่มีข้อมูลเด็กจริงหรือขยาย Research default-off/consent/permit ในงานนี้
- หลัง implementation ทั้งชุดจึงตรวจภาพ เส้นทางและ data invariants พร้อม final system gates บน source เดียวกัน และ device/UAT ตามแผน; รอบโต้แย้งนี้แก้เฉพาะรายงาน U3 ไม่มีการค้นเว็บใหม่ แก้แอป หรือรัน tests/build
