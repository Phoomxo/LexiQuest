## Important

- **[P2] Apply the page bound before hydrating History entries** — `lib/features/history/data/drift_learning_history_reader.dart:125–145`. The terminal-session query no longer has a limit, and this loop calls `_purpose` and `_entry` for every terminal session before `result.take(filter.limit)`. The default History request (`limit: 20`) therefore reads/decodes every historical session's checkpoints, answers and canonical events; `_entry` also repeats the purpose read. Work and memory grow with the owner's lifetime history rather than the requested page. More directly, any old session whose canonical evidence is corrupt now throws from `_entry` and prevents the newest page from loading even when that old session could never appear in the returned page. Previously the SQL limit kept such rows outside the requested page. Preserve purpose filtering before the limit, but choose the actual globally ordered eligible page (including assessment terminal ordering) before full entry hydration. Read candidate pages incrementally when necessary; do not weaken validation of an entry that is actually returned. Add a regression with valid recent entries, an older malformed canonical answer/event outside `limit: 1`, and newer replay entries excluded by the normal-only filter; the current normal page must load, while requesting the malformed row must still fail. A bounded hydration/query assertion should prove older off-page entries are not fully decoded.
