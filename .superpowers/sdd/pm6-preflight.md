## Real-shell risks requiring integration tests

1. `UnifiedLessonShell` wraps the mode surface in a pointer listener invoking `noteActiveLearningInteraction`; the controller calls configuration interaction and active-time/focus-time recording without a Pair purpose check in that method. Practice Replay can therefore create forbidden study-time/configuration/focus effects even when answer projection no-ops. PM5/coordinator must supply purpose-aware shell admission before UI replay becomes operable. Verify real pointer taps and keyboard/semantic activation against persisted projection deltas. Do not just test a mock answer gateway. Keyboard currently bypasses that pointer listener, another modality parity risk.
2. Generic `ProductionFeatureGate` can replace/dispose the mounted host on runtime off. Preserve accepted pending answer/close and test parent gate off → disposal → reopen/recover/close with starts disabled. Getter-only gate tests cannot prove this. Coordinate shell changes with root/PM8; no PM6 shared-shell writes without ownership transfer.
3. The existing screen initializes canonical lifecycle, resumes pending close, serializes abandonment and PopScope, and removes matched controls immediately. Compatibility extraction must preserve those paths and its existing tests; new board needs placeholders plus matched semantic removal and deterministic next focus, without double submissions.
4. AccessibilityScope only exposes text scale/high contrast/reduced motion, not an explicit Switch profile. Board/host needs explicit simpler-traversal presentation policy plus MediaQuery accessibleNavigation where appropriate; do not infer age from performance. Use LayoutBuilder effective available width and actual text-fit policy, 56px regular/64px compact tiles, 48px actions. Narrow/200% long Thai fixtures need scrolling without clipped essential labels.
5. Shell-owned feedback can appear before the mode unless the returned surface implements `AccessibilityModeFeedbackSurface`. Preserve canonical context → prompt → response → feedback → navigation semantics; test actual shell, not only standalone board. Use one semantics action per tile and language/state labels, with matching placeholders excluded after status announcement. Focus changes and live regions must never count as learning commands or consume timer budget.
6. Timeout dialog must not auto-close or auto-abandon. Heading/primary focus and restored board focus need explicit handling. Continue untimed primary; +30 only once and only unlock after acknowledgement; restart preserves attempts/extension and changes round only. UI tick is display only; no per-frame checkpoint. Parent background/route retirement while dialog or audio is open must be tested.
