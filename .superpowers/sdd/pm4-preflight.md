## Proposed single-authority implementation

Add a pure `domain/pair_active_clock.dart` defining an injected monotonic microsecond read port, timer value/state and owned pause tokens. The coordinator owns process-local active anchor and its single durable folded timer snapshot. Clock callbacks, renderer ticks and UI presentation cannot append checkpoints or create evidence. Keep the existing frozen plan's OFF/60/90/120 choice; each fresh setup defaults OFF. A restart inside that timed session uses its pinned duration, not a preference from an earlier session.

Persist bounded fields: timer mode (`off`, running/extended, timeoutDecision, continuedUntimed), remainingActiveMs, accumulated accounted active time if required by result presentation, extensionUsed, latest timer decision/operation identity, roundOrdinal/currentRoundSeed, and safe recoverable pause state. Fixed-key enums and bounded IDs only; no tick samples, callback log or per-restart snapshot list. Keep immutable plan, purpose, session ID and start serialization unchanged.

Each active interval opens from a fresh monotonic sample only after the board is usable and the admitting persistence acknowledgement is complete. Pause folds `max(0, now-anchor)` exactly once; normalize micros to milliseconds without charging rounding twice. No wall deadline drives v6. Negative/nonmonotonic/faulty reads stop the segment and expose a recoverable paused state with Continue untimed. Restoration uses the last durable remaining value and starts paused until current lifecycle readiness is established; never reset to the original duration or deduct background wall time.

Abrupt process death can lose the unflushed portion of an active segment when per-tick persistence is prohibited. Tests must state that limitation honestly: recover the exact last acknowledged timer snapshot and decision, not claim exact knowledge of elapsed time after that snapshot. Persist accepted operation/lifecycle boundaries; a crash must not reset the entire clock, add an extension or erase evidence.

### Referenceable pause ownership

Represent runtime ownership as reason -> set of opaque leases/tokens, with owner/session/coordinator generation binding. Reasons cover board unavailable, background/system interruption, modal, persistence, required narration, recovery/clock fault. A completion releases only the exact lease it acquired. Two modals or narration requests of the same reason remain paused until both release; a stale completion from an earlier modal, round, session or coordinator cannot remove a newer lease. Duplicate acquire/release for the same token is idempotent. Persist canonical effective reasons, not an unbounded token history; reconstructed runtime tokens are fresh and cannot be released by pre-crash callbacks.

Only the transition from active to paused needs a timer fold. Additional reasons and duplicate callbacks coalesce before a write has been attempted. Once an append has uncertain outcome, its state/time/revision are frozen; changes wait in at most one folded successor. Persistence's own pause token must not recursively schedule a write. A successor must itself pass reserve admission before the board starts another active segment. If capacity is tight, keep the timer safely paused and retain the reserved Continue path; do not resume an interval whose eventual mandatory flush cannot fit.

### Serialized decisions and exact recovery

Every answer, expire, Continue, +30, restart and close enters the existing admitted/recovery authority. At admission, sample/fold active time and apply a documented deterministic ordering: an already accepted answer completes/reconciles first; expiry accepted before a new answer fences that answer. If the accepted last answer completes the board, later expiry is neutral. While an uncertain pending answer/checkpoint/close exists, new conflicting intents are unavailable; exact retry/reconciliation remains usable. Owner/lease checks apply within admission and around awaits.

- Expiry appends timeoutDecision once, with zero new AnswerAttempts, no incorrect, no terminal envelope and no automatic completion. Only show the acknowledged decision as actionable; persistence failure keeps exact retry.
- Continue appends continuedUntimed using the same board/session/ledger and then enables interaction. It remains available after extension is used, clock fault or capacity exhaustion of optional actions.
- +30 freezes its operation ID and target `extensionUsed=true, remainingActiveMs=30000` before append. Start counting only after acknowledgement. Repeated same intent/recovery reuses this identity; a changed duplicate is rejected and a second entitlement use is unavailable. Restart never clears extensionUsed.
- Restart admits a candidate for **all remaining bounded learning work**, then appends exactly one new round ordinal/seed. Derive seed deterministically from pinned original seed + next ordinal + policy version, and verify it on decode/repository transition. Technical retry reuses ordinal/seed and operation identity. Preserve exact lexical set/revisions/checksums/direction, purpose, all committed attempts/evidence IDs, original support acquisition revisions, first-opportunity history and one-repair-per-session history.
- Restart clears only current-round selection/matched presentation. Derive current-round progress from attempts whose round equals current round; historical matched words cannot pre-complete the new board. Retained rounds must be ordered and <= current; global operation/attempt chronology stays strict. Repair ticket usage and semantic support remain session scoped. A prior guided word cannot become independent after restart, and a spent repair cannot be reissued. New rounds may require honest guided acknowledgement for already-supported words. Validate this against PM3's accepted projection rather than discarding prior tickets to make the board playable.

## Full bounded capacity model

Use one shared policy over the accepted PM3 state. Let `A(s)` be the maximum number of further allowed canonical answers to finish the current round (including first wrong, one scheduled repair wrong, and explicit guided confirmation where still reachable), and `G(s)` the maximum remaining standalone mandatory support/guided writes not already folded into those two-revision answer transitions. Let `T(s)=2` while timed and a future timeout remains reachable (decision + Continue), `T(s)=1` in an acknowledged timeout/clock-fault decision, and `T(s)=0` once untimed/off. Terminal reserve remains 3.

For any candidate operation of cost `c`, require before acknowledgement:

`currentRevision + c + 2*A(candidate) + G(candidate) + T(candidate) + 3 <= 64`

and `retainedAttempts + candidateNewAttempts + A(candidate) <= 128`, plus the unified projected UTF-8 bound. Count an accepted pending answer's remaining clear cost exactly once. A timeout consumes a reserved decision revision and reduces T; Continue consumes its reserved revision and reduces T to zero. +30 and restart must replenish T=2 and pass the full new candidate reserve. Restart may increase A because it resets the board. Lifecycle writes consume optional slack; reserve an outstanding mandatory pause flush before active resume. If PM3's accepted policy has tighter costs, use its proven values, not the PM2 `remainingPairs*2` shortcut.

A conservative complete-round upper bound is at most three answers per word (first opportunity, at most one repair, explicit guided correct) and at most one standalone reveal/support write per word, i.e. `2*(3*N)+N = 7*N` revisions. PM3 may fold support into wrong/clear and produce a lower proven bound; this preflight does not assert its final write count. Already spent session repair/support can only reduce future options if enforced correctly; restart must not renew them.

For six pairs, the conservative round reserve is 42. A concrete upper-bound exercise is: initial checkpoint 1; seven timeout -> restart cycles with no answers cost 14; timeout -> +30 cost 2; second timeout -> Continue cost 2; the full allowed wrong/repair/guided round costs <=42; real close/ack/presentation costs 3. Total <=64. This includes repeated restarts and extension use, not just an all-correct tail. It is an upper-bound test schedule, not a claim that all six words can realize every upper-bound repair branch simultaneously. With any pre-restart answers, reveals or distinct pause flushes, subtract their cost from restart slack and recompute A/G for the candidate; deny the optional restart before changing state if it no longer fits. A denied restart must leave Continue and complete current round possible. No claim or requirement of unlimited restarts.

Exercise four and six pairs, both directions, every-pair wrong, simultaneous repair tickets, late tail, partial completion before restart, extension before/after restart, owned overlapping pauses, and exact fault retries. Test the maximum allowed boundary found by the real policy, then one more optional intent rejection with unchanged state/evidence. Continue and the entire remaining allowed PM3 sequence plus all three terminal receipts must still succeed. Do not substitute silently rejecting an admitted wrong answer for full-round admission.

For bytes, expand accepted PM2's projection to retain all prior-round attempts and evidence IDs, candidate pending answer/frozen metadata, maximum remaining allowed PM3 answers/support/repair representation, maximum timer/restart/close/summary fields and numeric widths. Measure canonical UTF-8 with permitted maximum Thai/Unicode identifiers and valid 197-character evidence IDs. Initial acceptance and restart admission must reserve the full candidate round; every pending/clear/decision/terminal state remains <=65,536. The old 1024 allowance cannot be assumed to cover an unspecified timer or future star structure. Keep explicit bounded allowances validated against actual serialized maxima; no ceiling increase, discarded history or down-conversion.
