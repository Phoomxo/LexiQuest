## Executable owner authentication contract

Use one shared pure comparison over supplied canonical rows, with repository reads inside the existing transaction; no new table, alias, provenance field or externally supplied authorization token.

- Inputs: authenticated current runtime owner R, canonical session, all checkpoint envelopes (limit 65 to reject >64), original plan P from strict revision 1, latest strict snapshot and canonical attempts/source events.
- Writes/restore admission require exactly one active `local_owners` row and its ID equals R. Read-only History/export for an explicitly scoped inactive account need not acquire write permission; keep that distinction rather than imposing global active-owner checks on all historical readers.
- Session/checkpoint/attempt/event row ownership must be R; session ID/start/app/build/purpose/source and immutable initial operation must match. Checkpoint revision 1 must retain original actor P.ownerId and actor-derived key; later checkpoint keys derive from each actual stored actor, never from a blanket replacement owner.
- P.ownerId == R is normal. Otherwise require the existing P.ownerId row, `is_active = 0`, exact `account_state = mergedInto:R`, valid created/upgraded UTC-ms values, created <= plan.createdAt <= upgraded; R exists and is the live destination for mutation. No marker supplied by UI/JSON counts.
- Historical checkpoint/frozen actors require their own inactive canonical row pointing directly to R and an occurrence at/before that row's upgraded timestamp. Validate timestamp units: owner/session fields use milliseconds, Drift event occurred_at_utc uses seconds. Account for the stored event timestamp precision, not equality with ms payload time.
- Reject missing, active, wrong-target, malformed/future-impossible timestamps, unrelated historical actor, wrong actor-derived key, foreign-owned canonical rows and partial/mixed revision chains. Do not accept arbitrary transitive strings or follow unbounded links.
- Actual repeated merge rewrites old `mergedInto:source` rows to the final R and advances upgraded timestamp. Validate that direct rewritten marker, while preserving original checkpoint actor/key and start owner. The field proves canonical local lineage, not cryptographic protection against an attacker with unrestricted SQL write access; marker+timestamp alone cannot detect a perfectly forged entire database.
- Historical actors are authorized only for their exact durable operations. Do not let a retired guest mint a new first-write answer. A pre-merge frozen pending reservation can first-write after upgrade only when strict accepted checkpoint bytes bind its original actor, ID, time, word, contexts and canonical session to R.
- Post-merge NEW occurrences capture R as frozen owner/actor through existing evidence capture; original plan owner remains P. Thus strict codec needs to allow internally consistent frozen owner==actor distinct from plan owner, while repository/purpose reader authenticates that actor against current row ownership/lineage. Pure codec parsing itself never grants owner authority. Do not fake a pre-upgrade actor or re-resolve an already-frozen context.
- Query dependencies must include plan owner and all frozen/checkpoint actors as well as R, not only checkpoint actors. `historicalOwnerQuery` currently extracts checkpoint actors only. Preserve tracked `_Reads` integration in research authorization so changes/absence/insertion invalidate external-await authorization.

## Collision semantics that must be explicit

Recommended minimal semantics: accepted session completes using original lexical identity, including collision tombstones; existing projection aliases deliver any already-authorized learning projection to canonical target. Exact display/pins remain historical. Fresh replay/start from a deleted pin remains unavailable under existing freshness rules. This gives resume without mutating pins or automatically abandoning Pair.
Alternative if product requires a fresh replay of a collided historical source: define a separate explicit source-selection policy for a new session. Remapping the old plan in-place or silently replacing its words violates accepted exact-source replay and is not an implementation shortcut. Do not implement that expanded behavior under owner compatibility alone.
Existing aliases must be tested for an answer FIRST written after collision; committed-before-merge alias coverage alone is insufficient. If that real path cannot project correctly, fix its existing resolver narrowly; do not add reward/study authority.
