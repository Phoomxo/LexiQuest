## Strict shared persisted-purpose contract

Decoder result should distinguish validated ordinary legacy/non-Pair, validated v6 learning, validated v6 practiceReplay and invalid/unsupported metadata. Never default malformed/unknown v6 to normal learning. Use the existing canonical checkpoint event validation/codec, exact schema/key/version bounds, owner/session/activity identities, canonical event/revision identity and accepted plan fingerprint. Validate immutable initial revision 1 against latest accepted checkpoint: same session/owner, purpose, sourceSessionId and immutable plan identity/pins. Reject mixed legacy/v6 history, duplicate/ambiguous initial or latest revisions, missing initial for observed v6, unknown version and altered lineage. A non-Pair/legacy session receives only the existing legacy semantics; do not infer Pair stars or replay eligibility retrospectively.

The snapshot value may carry validated owner/session/plan identity/purpose for the host, but cannot accept a caller bool or transient route intent as authority. Host admission must await/read persisted acceptance before any study/focus/configuration side effect; stale owner/session callbacks fail admission. Replay first-write validation must tie pending command to that accepted lineage; ordinary duplicate attempt/event identity checks remain mandatory.

Today excludes replay from its mission/resume selector. Research skips validated replay in scanning, rejects replay on direct attachment/completion/upload and fails closed for corrupt/ambiguous v6. Ordinary learning remains usable when research is unavailable. History may expose an unavailable/corrupt entry state rather than invent a normal Pair score. Any policy on corrupt latest candidates must preserve the current consumer's explicit corrupt state instead of silently granting normal authority.

An upload decoder must not perform hidden DB reads. Give it the tracked session row plus tracked ordered checkpoint event rows. Do not snapshot only a chosen event ID: insertion of a newer checkpoint or a formerly missing initial must change the comparison too. The existing `_Reads` tracks query results in `values`; preserve deterministic ordering and complete relevant payload/identity fields in its before/after comparison.
