## 2. Typed host queries ที่ยังขาด — root ยืนยันให้รวมใน narrow PM6 ownership

ห้ามให้ UI parse `StateError.message`, copy checkpoint budgets หรือจำลอง evidence state machine. `state.pending == null` ยังไม่ได้แปลว่า ready: `_capturedState`, `_pending`, `_pendingAppend`, `_pendingSnapshot`, `_busy` และ `_close` เป็น private; lost acknowledgement ของ non-answer flush/timer/reveal และ captured-before-freeze failure ไม่ปรากฏครบใน engine state. `summaryPresented == false` ไม่บอกว่า close ยังไม่ ack หรือแค่ยังไม่มี presentation receipt

ชุด query ต่ำสุดที่ต้องเพิ่มใน **coordinator เดิม** (ชื่อด้านล่างเป็นชื่อเสนอสำหรับ handoff, **ยังไม่มี callable API**):

1. `PairMatchingHostStatus get hostStatus`: typed current phase / in-flight operation / exact recovery action (`none`, retry retained pending, finish canonical close, acknowledge result presentation) พร้อม `canResumeInteraction`, `canFlush`, `canDispatch`, owner/lifecycle unavailable และ terminal acknowledgement/presentation state. ต้อง derive จาก private retained state จริง รวม captured-only และ pending checkpoint ไม่เปิด frozen evidence payload ให้ widget
2. `PairTimerAvailability get timerAvailability`: availability และ typed unavailable reason ของ Continue / extend / restart / expire โดยใช้ timer + pending/terminal/lifecycle + shared capacity/byte admission ใน authority เดิม. Query ต้องไม่เขียน checkpoint/consume ID/lease/revision หรือเปลี่ยน round และ dispatch ต้อง revalidate อีกครั้งเมื่อมี race

Read-only availability เป็นข้อผูกมัดของ host integration ไม่ใช่ permission ให้ลดการตรวจใน dispatch. ตอนนี้ยังไม่มี notification API; awaited commands + display refresh ใช้ได้ จึงไม่จำเป็นต้องเพิ่ม notifier เป็นข้อกำหนดใหม่
